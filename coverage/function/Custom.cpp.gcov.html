      35             : /*
      36             : Calculate a combination of variables using a custom expression.
      37             : 
      38             : CUSTOM is one of the most useful actions in PLUMED.  This action takes in a list of arguments and then uses
      39             : the [lepton mathematical expression parser](https://simtk.org/projects/lepton) to evaluate a user defined function
      40             : of these input arguments. We can thus use this action in the input below to perform a metadynamics
      41             : simulation using the difference between two distances as a CV.
      42             : 
      43             : ```plumed
      44             : dAB: DISTANCE ATOMS=10,12
      45             : dAC: DISTANCE ATOMS=10,15
      46             : diff: CUSTOM ARG=dAB,dAC FUNC=y-x PERIODIC=NO
      47             : # notice: the previous line could be replaced with the following
      48             : # diff: COMBINE ARG=dAB,dAC COEFFICIENTS=-1,1
      49             : METAD ARG=diff SIGMA=0.1 HEIGHT=0.5 BIASFACTOR=10 PACE=100
      50             : ```
      51             : 
      52             : The particular function that should be evaluated from the input arguments is specified using the `FUNC` keyword.
      53             : The function provided to the `FUNC` keyword is written in terms of `x` and `y` in the input above.  `x` here deonetes the
      54             : first argument provided to the ARG keyword, `dAB`, while `y` is the second argument provided to the `ARG` keyword, `dAC`.
      55             : 
      56             : ## The VAR keyword
      57             : 
      58             : If you wish, you can rewrite the example input above more transparantly as:
      59             : 
      60             : ```plumed
      61             : dAB: DISTANCE ATOMS=10,12
      62             : dAC: DISTANCE ATOMS=10,15
      63             : diff: CUSTOM ARG=dAB,dAC VAR=dAB,dAC FUNC=dAC-dAB PERIODIC=NO
      64             : METAD ARG=diff SIGMA=0.1 HEIGHT=0.5 BIASFACTOR=10 PACE=100
      65             : ```
      66             : 
      67             : By using the `VAR` keyword here we ensure that we can use the labels of the arguments in the mathematical expression that
      68             : we provide to the `FUNC` argument.  Notice that, if you have four or more arguments you must use the `VAR` keyword.  With
      69             : three or less arguments the `VAR` keyword can be ommitted and the symbols `x`, `y` and `z` can be used to denote the first,
      70             : second and third arguments respectively.

      72             : The following input illustrates a case where using the `VAR` keyword is essential.  This input tells PLUMED to
      73             : print the angle between the vector connecting atoms 1,2 and the vector connecting atoms 2,3.
      74             : 
      75             : ```plumed
      76             : d1: DISTANCE ATOMS=1,2 COMPONENTS

     165             : ## The PERIODIC keyword
     166             : 
     167             : If the function you have evaluated has a periodic codomain then you have to use the PERIODIC keyword to specify the codomain of the function.
     168             : To see how to use this keyword consider the following input:
     169             : 
     170             : ```plumed
     171             : d: DISTANCE ATOMS=1,2 COMPONENTS
     172             : theta: CUSTOM ARG=d.x,d.y FUNC=atan2(y,x) PERIODIC=-pi,+pi
     173             : PRINT ARG=theta FILE=colvar
     174             : ```
     175             : 
     176             : The above input calculates the torsional angle between the vector connecting atoms 1 and 2 and positive $x$ direction around the $z$ axis.
     177             : This quantity must lie between $-\pi$ and $\pi$ so we use the PERIODIC keyword to tell PLUMED this fact about the output quantity.
     178             : 
     179             : Notice that PLUMED cannot automatically detect if the codomain of the function is periodic.  You thus always have to specifiy the
     180             : periodicity of the codomain whenever you use the CUSTOM command.  However, the codomain of most functions that people use are not periodic
     181             : so you can normally just write `PERIODIC=NO`
     182             : 
     183             : ## The step function
     184             : 
     185             : The `step` operation (that is the Heaviside function) from the table above allow you to use if clauses in CUSTOM actions.
     186             : As discussed in the table `step(x)` is 1 when `x` is positive and `0` when `x` is negative.  So the function `step(1-x)` is
     187             : 1 if x is less than one and zero otherwise.
     188             : 
     189             : Using the `step` operation multiple times in a function allows you to perform logical operations.  For example, the equivalent of the AND operator
     190             : is the product so, for example, `step(1.0-x)*step(x-0.5)` is only equal to 1 when x is greater than 0.5 AND less than 1.0.
     191             : By a similar logic we can use the function `1-step(1.0-x)*step(x-0.5)` to create a value that is 1 if x is less than 0.5 OR
     192             : greater than 1.0.
     193             : 
     194             : The example below illustrtes how we can put these ideas of using the `step` operation into practise.
     195             : 
     196             : ```plumed
     197             : d: DISTANCE ATOMS=10,15
     198             : m: CUSTOM ARG=d FUNC=0.5*step(0.5-x)+x*step(x-0.5) PERIODIC=NO
     199             : # check the function you are applying:
     200             : PRINT ARG=d,m FILE=checkme
     201             : RESTRAINT ARG=d AT=0.5 KAPPA=10.0
     202             : ```
     203             : 
     204             : The meaning of the function `0.5*step(0.5-x)+x*step(x-0.5)` in this example is:
     205             : - If x<0.5 (step(0.5-x)!=0) use 0.5
     206             : - If x>0.5 (step(x-0.5)!=0) use x
     207             : Notice that the same result can be achieved by using [UPPER_WALLS](UPPER_WALLS.md)
     208             : However, with CUSTOM you can create much more complex definitions.
     209             : 
     210             : Notice that we can apply a force on the value `m` by using the [RESTRAINT](RESTRAINT.md) command as the function we defined in the expression that was passed to the `FUNC` keyword is continuous.
     211             : In general, however, you must be careful when using the `step`, `delta`, `nandelta` and `select` functions as you can easily write expression for
     212             : discontinuous functions by using these operations. If you want to check if a function you have created using `step`
     213             : is continuous you can easily plot the function in gnuplot by using a commands like those shown below
     214             : 
     215             : ````
     216             : # this allow to step function to be used in gnuplot:
     217             : gnuplot> step(x)=0.5*(erf(x*10000000)+1)
     218             : # here you can test your function
     219             : gnuplot> p 0.5*step(0.5-x)+x*step(x-0.5)
     220             : ````

     235             : ## Using CUSTOM in shortcuts
     236             : 
     237             : The CUSTOM action is used in many of the [shortcut actions](shortcuts.md) that are implemented in PLUMED. We think that using this action in these places is beneficial as it ensures that the mathematical
     238             : expressions that are used in the method are visible in the log. We have found that there are many actions that
     239             : are used in relatively few papers. When implementing these actions we think that sharing implementations of these methods that are comprehensible is more important than sharing methods that are
     240             : fast.
     241             : 
     242             : As an example of why this is useful consider some of the variants of the DISTANCE keyword that were present in PLUMED 1.3. These variants allowed you to compute the distance between a point and a line defined by
     243             : two other points or the progression along that line.  In PLUMED 2.10 we can implement these variables using the following input file:
     244             : 
     245             : ```plumed
     246             : # take center of atoms 1 to 10 as reference point 1
     247             : p1: CENTER ATOMS=1-10
     248             : # take center of atoms 11 to 20 as reference point 2
     249             : p2: CENTER ATOMS=11-20
     250             : # take center of atoms 21 to 30 as reference point 3
     251             : p3: CENTER ATOMS=21-30
     252             : 
     253             : # compute distances
     254             : d12: DISTANCE ATOMS=p1,p2
     255             : d13: DISTANCE ATOMS=p1,p3
     256             : d23: DISTANCE ATOMS=p2,p3
     257             : 
     258             : # compute progress variable of the projection of point p3
     259             : # along the vector joining p1 and p2
     260             : # notice that progress is measured from the middle point
     261             : onaxis: CUSTOM ARG=d13,d23,d12 FUNC=(0.5*(y^2-x^2)/z) PERIODIC=NO
     262             : 
     263             : # compute between point p3 and the vector joining p1 and p2
     264             : fromaxis: CUSTOM ARG=d13,d23,d12,onaxis VAR=x,y,z,o FUNC=(0.5*(y^2+x^2)-o^2-0.25*z^2) PERIODIC=NO
     265             : 
     266             : PRINT ARG=onaxis,fromaxis
     267             : ```
     268             : 
     269             : The equations in this input were also used to combine [RMSD](RMSD.md) values from different snapshots of a protein so as to define
     270             : progression (S) and distance (Z) variables in the paper that is cited in the bibliography.  We can understand how these expressions
     271             : are derived by noting that $x$, $y$ and $z$ are the distances between atoms 1 and 3, 2 and 3 and 1 and 2 respectively.  The projection
     272             : of the vector connecting atom 1 to atom 3 onto the vector connecting atom 1 to atom 2 is thus $x\cos(\theta)$, where theta is the angle
     273             : between the vector connecting atoms 1 and 3 and the vector connecting atoms 1 and 2.  We can arrive at the following expression for $x\cos(\theta)$
     274             : by rearranging the cosine rule:
     275             : 
     276             : $$
     277             : x\cos(\theta) = \frac{y^2 - x^2}{z} - \frac{z}{2}
     278             : $$
     279             : 
     280             : Notice that the value called `onaxis` in the above input is thus $o=x\cos(\theta) + \frac{z}{2}$.  Adding the factor of $\frac{z}{2}$ ensures that the origin
     281             : is at the center of the bond connecting atom 1 to atom 2.
     282             : 
     283             : The value `fromaxis` measures the square of the distance from the the line.  It is calculated using pythagoras theorem as follows:
     284             : 
     285             : $$
     286             : f^2 = y^2 - x^2\cos^2(\theta)
     287             : $$
     288             : 
     289             : Inserting $x\cos(\theta) = o - \frac{z}{2}$ into this expression gives:
     290             : 
     291             : $$
     292             : f^2 = y^2 - (o -\frac{z}{2})^2 = y^2 - o^2 + oz - \frac{z^2}{4}
     293             : $$
     294             : 
     295             : Inserting the fact that $oz = \frac{y^2 - x^2}{2}$, which comes from the expression for $o$ that was used to calculate `onaxis`, gets us to the expression that is used to calculate `fromaxis`.
     296             : 
     297             : ## CUSTOM with vector arguments
     298             : 
     299             : The examples above have shown how CUSTOM operates when the input arguments are scalars. You can also pass vectors in the argument to a CUSTOM action. The function you define will then
     300             : be applied to each element of the vector in turn.  So, for example in the input below a vector that contains three angles is passed to the CUSTOM action. The CUSTOM action calculates the
     301             : cosine of these three angles and outputs them in a three dimensional vector called `c` that is printed to the colvar file.
     302             : 
     303             : ```plumed
     304             : a: ANGLE ATOMS1=1,2,3 ATOMS2=4,5,6 ATOMS3=7,8,9
     305             : c: CUSTOM ARG=a FUNC=cos(x) PERIODIC=NO
     306             : PRINT ARG=c FILE=colvar
     307             : ```
     308             : 
     309             : You are not confined to passing a single vector to CUSTOM. The input below shows what you can do by pass two vectors with the same numbers of elements. The first element of the vector
     310             : output by the CUSTOM action here contains the projection of the vector connecting atom 1 and 2 on the vector connecting atom 2 and 3, the second element contains the projection of the
     311             : vector connecting atoms 4 and 5 on the vector connecting atoms 5 and 6 and the final element contains the projection of the vector connecting atoms 7 and 8 on the vector connecting atoms
     312             : 8 and 9.
     313             : 
     314             : ```plumed
     315             : d: DISTANCE ATOMS1=1,2 ATOMS2=4,5 ATOMS3=7,8
     316             : a: ANGLE ATOMS1=1,2,3 ATOMS2=4,5,6 ATOMS3=7,8,9
     317             : c: CUSTOM ARG=d,a FUNC=x*cos(y) PERIODIC=NO
     318             : PRINT ARG=c FILE=colvar
     319             : ```
     320             : 
     321             : Notice, when we multiply two vectors in CUSTOM the output is a vector.  This product that emerges from using a CUSTOM action is __not__ the scalar or cross product of the input vectors.
     322             : 
     323             : Lastly, notice that you can pass a mixture of vectors and scalars in the input to a CUSTOM action. However, the labels of the scalar values that appear in the input for the ARG keyword
     324             : must appear after the labels of vector vectors as shown below:
     325             : 
     326             : ```plumed
     327             : d: DISTANCE ATOMS=1,2
     328             : a: ANGLE ATOMS1=1,2,3 ATOMS2=1,2,4 ATOMS3=1,2,5 ATOMS4=1,2,6
     329             : c: CUSTOM ARG=a,d FUNC=y*cos(x) PERIODIC=NO
     330             : PRINT ARG=c FILE=colvar
     331             : ```
     332             : 
     333             : The multiplication of a scalar by a vector in the above input is done in [the usual way](https://en.wikipedia.org/wiki/Scalar_multiplication).
     334             : Similarly, dividing a vector by a scalar is equivalent to multiplying the vector by the reciprocal of the scalar.  If you write an expression that adds or subtract a
     335             : scalar from a vector addition is performed.  To understand why consider the following example that adds the constant `c` to the input vector of distances `d`. The
     336             : result of this operation is a vector `f` that contains the three input distances from `d` with 23 added to each of them.
     337             : 
     338             : ```plumed
     339             : c: CONSTANT VALUE=23
     340             : d: DISTANCE ATOMS1=1,2 ATOMS2=4,5 ATOMS3=7,8
     341             : f: CUSTOM ARG=d,c FUNC=x+y PERIODIC=NO
     342             : PRINT ARG=f FILE=colvar
     343             : ```

     345             : ## CUSTOM, MASK and vector arguments
     346             : 
     347             : The example input below illustrates a way you can use the MASK keyword to improve PLUMED performance for inputs that use CUSTOM actions that take arguments that
     348             : are vectors:
     349             : 
     350             : ```plumed
     351             : # Fixed virtual atom which serves as the probe volume's center (pos. in nm)
     352             : center: FIXEDATOM AT=2.5,2.5,2.5
     353             : ow: GROUP ATOMS=1-400
     354             : hw: GROUP ATOMS=401-1200
     355             : # Vector in which element i is one if atom i is in sphere of interest and zero otherwise
     356             : sphere: INSPHERE ATOMS=ow CENTER=center RADIUS={GAUSSIAN D_0=0.5 R_0=0.01 D_MAX=0.52}
     357             : # Calculate coordination with oxygen atoms
     358             : ow_ones: ONES SIZE=400
     359             : ow_mat: CONTACT_MATRIX GROUP=ow MASK=sphere SWITCH={RATIONAL R_0=0.3 D_MAX=0.8}
     360             : ow_coord: MATRIX_VECTOR_PRODUCT ARG=ow_mat,ow_ones
     361             : # And transform the coordination numbers by a switching function
     362             : ow_mt: MORE_THAN ARG=ow_coord MASK=sphere SWITCH={RATIONAL R_0=4}
     363             : # Calculate the coordination with hydrogen atoms
     364             : hw_ones: ONES SIZE=800
     365             : hw_mat: CONTACT_MATRIX GROUPA=ow GROUPB=hw MASK=sphere SWITCH={RATIONAL R_0=0.1 D_MAX=0.5}
     366             : hw_coord: MATRIX_VECTOR_PRODUCT ARG=hw_mat,hw_ones
     367             : # And transform the coordination numbers by a switching function
     368             : hw_mt: MORE_THAN ARG=hw_coord MASK=sphere SWITCH={RATIONAL R_0=2}
     369             : # And multiply the two vectors of transformed coordination numbers together
     370             : prod: CUSTOM ARG=hw_mt,ow_mt FUNC=x*y MASK=sphere PERIODIC=NO
     371             : # Sum of coordination numbers for atoms that are in the sphere of interest
     372             : cv: SUM ARG=prod PERIODIC=NO
     373             : # And print out final CV to a file
     374             : PRINT ARG=cv FILE=colvar STRIDE=1
     375             : ```
     376             : 
     377             : The variable being computed here measures the number of oxygen atoms in a spherical region centered on the point $(2.5,2.5,2.5)$ that have a coordination
     378             : that is greater than 4 with other oxygen atoms and a coordination that is greater than 2 with other hydrogen atoms.  Notice how by using the MASK keyword
     379             : in the [CONTACT_MATRIX](CONTACT_MATRIX.md), [MORE_THAN](MORE_THAN.md and CUSTOM actions we avoid calculating the order parameters that are not in the spherical
     380             : region of interest in the way that is described in more detail in the documentation for [CONTACT_MATRIX](CONTACT_MATRIX.md).
     381             : 
     382             : 
     383             : ## CUSTOM with matrix arguments
     384             : 
     385             : You can also pass matrices in the argument to a CUSTOM action. These input matrices are treated similarly to input vectors. In other words, any function you define
     386             : is applied to each element of the matrix in turn so if the input matrix is $N \times M$ the output matrix is also $N \times M$.  The following example illustrates how you
     387             : can use this functionality to calculate all the angles between a set of bond vectors.
     388             : 
     389             : ```plumed
     390             : # Calculate the vectors connecting four atoms
     391             : d: DISTANCE COMPONENTS ATOMS1=1,2 ATOMS2=3,4 ATOMS3=5,6 ATOMS4=7,8
     392             : # Calculate the norm of these four vectors
     393             : norm: CUSTOM ARG=d.x,d.y,d.z FUNC=sqrt(x*x+y*y+z*z) PERIODIC=NO
     394             : # Now calculate the directors of the vectors
     395             : norm_x: CUSTOM ARG=d.x,norm FUNC=x/y PERIODIC=NO
     396             : norm_y: CUSTOM ARG=d.y,norm FUNC=x/y PERIODIC=NO
     397             : norm_z: CUSTOM ARG=d.z,norm FUNC=x/y PERIODIC=NO
     398             : # And combine all these directors in a matrix
     399             : stack: VSTACK ARG=norm_x,norm_y,norm_z
     400             : # Now calculate the matrix of dot products between directors (these are the cosines of the angles)
     401             : stackT: TRANSPOSE ARG=stack
     402             : cosa: MATRIX_PRODUCT ARG=stack,stackT
     403             : # And finally get the 4x4 matrix of angles and print it to a file
     404             : angles: CUSTOM ARG=cosa FUNC=acos(x) PERIODIC=NO
     405             : PRINT ARG=angles FILE=colvar
     406             : ```
     407             : 
     408             : Notice that you can pass multiple $N\times M$ matrices in the input to a CUSTOM action as illustrated in the example below:
     409             : 
     410             : ```plumed
     411             : c1: CONSTANT VALUES=2,3,4,5 NROWS=2 NCOLS=2
     412             : c2: CONSTANT VALUES=1,0,0,1 NROWS=2 NCOLS=2
     413             : f: CUSTOM ARG=c1,c2 FUNC=x*y PERIODIC=NO
     414             : PRINT ARG=f FILE=colvar
     415             : ```
     416             : 
     417             : The four by four matrix that is calculated by the custom action in this input is given by:
     418             : 
     419             : $$
     420             : f = \left(
     421             : \begin{matrix}
     422             : 2 & 0 \\
     423             : 0 & 5
     424             : \end{matrix}
     425             : \right)
     426             : $$
     427             : 
     428             : which is the element-wise [Hadamard product](https://en.wikipedia.org/wiki/Hadamard_product_(matrices)) and __not__ the matrix product.
     429             : By a similar token if you have a custom command that takes two matrices in input and use `FUNC=x/y` the Hadamard product between the matrix
     430             : x and a matrix that contains the reciprocals of each of the elements in y is computed.  If you wish to calcalculate the
     431             : [product of two matrices](https://en.wikipedia.org/wiki/Matrix_multiplication) you should use the [MATRIX_PRODUCT](MATRIX_PRODUCT.md) comamnd.
     432             : Similarly, if you want to calculate the product of a matrix and a vector you should use the [MATRIX_VECTOR_PRODUCT](MATRIX_VECTOR_PRODUCT.md)
     433             : command.
     434             : 
     435             : Lastly, note that you can pass a mixture of scalars and $N\times M$ matrices in the input to a CUSTOM command. As with vectors, you can think of
     436             : any scalars you pass as being converted into $N\times M$ matrix in which every element is equal to the input scalar.  Furthermore, the labels of
     437             : the input scalars must appear __after__ the labels fo the input matrices in the input for the ARG keyword.
     438             : 
     439             : ## CUSTOM, MASK and matrix arguments

     503             : ## CUSTOM with grid arguments
     504             : 
     505             : CUSTOM will also accept a function on a grid in input.  You might use this feature if you want to calculate a free energy from a histogram

     516             : would do this in practise. The final output here is a function on a grid that tells you the average value of the FCC order parameter at each point in the cell.

     533             : ## Making lepton library faster
     534             : 
     535             : If you use a lot of [CUSTOM](CUSTOM.md) actions or CUSTOM [switching functions](LESS_THAN.md) it can slow down PLUMED.
     536             : These commands use the lepton library that is included in PLUMED.
     537             : This library replaces libmatheval since PLUMED 2.5, and by itself it is significantly faster than libmatheval.
     538             : However, you can make it even faster using a [just-in-time compiler](https://github.com/asmjit/asmjit.git).
     539             : As of PLUMED 2.6, the correct version of ASMJIT is embedded in PLUMED.
     540             : As of PLUMED 2.8, ASMJIT is enabled by default on supported architectures (X86/X64).
     541             : You can disable it at runtime setting the environment variable `PLUMED_USE_ASMJIT`:
     542             : 
     543             : ```bash
     544             : export PLUMED_USE_ASMJIT=no
     545             : ```
     546             : 
     547             : In some case using a custom expression is almost as fast as using a hard-coded
     548             : function. For instance, with an input that contained the following lines:
     549             : 
     550             : ```plumed
     551             : c: COORDINATION GROUPA=1-108 GROUPB=1-108 R_0=1
     552             : d_fast: COORDINATION GROUPA=1-108 GROUPB=1-108 SWITCH={CUSTOM FUNC=1/(1+x2^3) R_0=1}
     553             : ```
     554             : 
     555             : I (GB) obtained the following timings (on a Macbook laptop):
     556             : 
     557             : ````
     558             : ...
     559             : PLUMED: 4A  1 c                                          108     0.126592     0.001172     0.000701     0.002532
     560             : PLUMED: 4A  2 d_fast                                      108     0.135210     0.001252     0.000755     0.002623
     561             : ...
     562             : ````
     563             : 
     564             : Notice the usage of `x2` as a variable for the switching function, which
     565             : avoids an unnecessary square root calculation (this is done automatically by the hard-coded switching functions
     566             : when you use only even powers). The asmjit calculation (`d_fast`) takes less than 10% more than the hard-coded
     567             : one (`c`).
     568             :
