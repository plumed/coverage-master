      32             : 
      33             : This action can be used to construct instantaneous distributions for quantities by using [kernel density esstimation](https://en.wikipedia.org/wiki/Kernel_density_estimation).
      34             : The input arguments must all have the same rank and size but you can use a scalar, vector or matrix in input.  The distribution
      35             : of this quantity on a grid is then computed using kernel density estimation.
      36             : 
      37             : The following example demonstrates how this action can be used with a scalar as input:
      38             : 
      39             : ```plumed
      40             : d1: DISTANCE ATOMS=1,2
      41             : kde: KDE ARG=d1 GRID_MIN=0.0 GRID_MAX=1.0 GRID_BIN=100 BANDWIDTH=0.2
      42             : DUMPGRID ARG=kde STRIDE=1 FILE=kde.grid
      43             : ```
      44             : 
      45             : This input outputs a different file on every time step. These files contain a function stored on a grid.  The function output in this case
      46             : consists of a single Gaussian with $\sigma=0.2$ that is centered on the instantaneous value of the distance between atoms 1 and 2.  Obviously,
      47             : you are unlikely to use an input like the one above. The more usual thing to do would be to accumulate the histogram over the course of a
      48             : few trajectory frames using the [ACCUMULATE](ACCUMULATE.md) command as has been done in the input below, which estimates a histogram as a function
      49             : of two collective variables:
      50             : 
      51             : ```plumed
      52             : d1: DISTANCE ATOMS=1,2
      53             : d2: DISTANCE ATOMS=1,2

      55             : histo: ACCUMULATE ARG=kde STRIDE=1

     172             : ## Setting the kernel
     173             : 
     174             : When you run molecular dynamics and calculate $d$ collective variables using PLUMED you generate a time series of $d$ dimensional vectors $\mathbf{x}_t$. The Kernel Density Estimation
     175             : method that is implemented in this action allows you to calculate an estimate of the probabilty density for the $d$ collective variables, which is a function with $d$ arguments.
     176             : This estimate is calculated using:
     177             : 
     178             : $$
     179             : f(\mathbf{x}) = \sum_{t=1}^n h_t K\left[ \sqrt{(\mathbf{x}-\mathbf{x}_t)^T \mathbf{H}^{-1} (\mathbf{x}-\mathbf{x}_t)} \right]
     180             : $$
     181             : 
     182             : This expression assumes that you are calculating the density from $n$ trajectory frames. $\mathbf{H}$ is bandwidths matrix and $h_t$ is the height that you want to use for the $t$th of your observations.
     183             : $K$ is then a non-negative function called the kernel.  This function acts upon the [Mahalanobis distance](https://en.wikipedia.org/wiki/Mahalanobis_distance) between $\mathbf{x}$ and $\mathbf{x}_t$.
     184             : 
     185             : To provide users with flexibility, the functional form for the kernel is specified using a syntax similar to the one described in the documentation for the [LESS_THAN](LESS_THAN.md)
     186             : action. The only difference from the instructions for swtiching functions in [LESS_THAN](LESS_THAN.md) is that PLUMED automatically
     187             : sets the $r_0$ parameter of your switching function to one for you. __You should thus not include R_0 when you set the parameters of your kernel function.__
     188             : 
     189             : By default PLUMED uses a Gaussian kernel function as illustrated in the input below:
     190             : 
     191             : ```plumed
     192             : d1: DISTANCE ATOMS=1,2
     193             : kde: KDE ARG=d1 GRID_MIN=0.0 GRID_MAX=1.0 GRID_BIN=100 BANDWIDTH=0.2 KERNEL={GAUSSIAN D_MAX=3.5355}
     194             : DUMPGRID ARG=kde STRIDE=1 FILE=kde.grid
     195             : ```
     196             : 
     197             : Notice that a stretching and scaling is performed on the gaussian kernel that is employed here so the function is guaranteed to be equal to zero if
     198             : $\sqrt{(\mathbf{x}-\mathbf{x}_t)^T \mathbf{H}^{-1} (\mathbf{x}-\mathbf{x}_t)}>3.5355$.  One consequence of this is that the integral of the $d$ dimensional
     199             : Gaussian will be slightly less than $(2\pi)^{d/2}\det(H)^{1/2}$. This can be a problem if you are assuming that the integral of your Gaussians is equal to this value when
     200             : normalising them.  You can partially avoid this problem by using the NOSTRETCH option as shown below:
     201             : 
     202             : ```plumed
     203             : d1: DISTANCE ATOMS=1,2
     204             : kde: KDE ARG=d1 GRID_MIN=0.0 GRID_MAX=1.0 GRID_BIN=100 BANDWIDTH=0.2 KERNEL={GAUSSIAN NOSTRETCH D_MAX=3.5355}
     205             : DUMPGRID ARG=kde STRIDE=1 FILE=kde.grid
     206             : ```
     207             : 
     208             : This, however, introduces a discontinuity in the kernel at $d_{max}$.
     209             : 
     210             : __We strongly recommend setting a D_MAX parameter for your kernels__.
     211             : If you do not set a D_MAX value for your KERNEL then a cutoff of $d_{max}=\sqrt{2*6.25}\approx 3.5355$ is used. If you are calculating a 1D histogram and D_MAX is unset PLUMED
     212             : then you evaluate a kernel at centered at $a$ on the gridpoint at $b$ if $\frac{|a-b|}{s}<=\left\lceil \frac{d_{max}\sigma}{s}\right\rceil$, where $s$ is the spacing between
     213             : grid points and $\sigma$ is the bandwidth. The ceiling on the right hand side of this inequality obviously makes this s necessary but not sufficient condition for ensuring that
     214             : $\sqrt{(\mathbf{x}-\mathbf{x}_t)^T \mathbf{H}^{-1} (\mathbf{x}-\mathbf{x}_t)}<d_{max}$.  In higher dimensions this becomes even more severe.  In 2D to
     215             : determine if we need to evaluate a kernel centered at $(a,b)$ for the grid point $(c,d)$ we first determine if $\frac{|a-c|}{s}<=\left\lceil \frac{d_{max}\sigma}{s}\right\rceil$ and
     216             : if $\frac{|b-d|}{s}<=\left\lceil \frac{d_{max}\sigma}{s}\right\rceil$. With these tests there are many more points that satisfy these two criteria but that do not satisfy
     217             : $\sqrt{(\mathbf{x}-\mathbf{x}_t)^T \mathbf{H}^{-1} (\mathbf{x}-\mathbf{x}_t)}<d_{max}$. The key thing to recognise is that when D_MAX is set PLUMED sets the value of the kernel equal to zero if
     218             : $\sqrt{(\mathbf{x}-\mathbf{x}_t)^T \mathbf{H}^{-1} (\mathbf{x}-\mathbf{x}_t)}>d_{max}$ even when the NOSTRETCH option is employed. If D_MAX is not set this check is not performed and
     219             : kernels can thus contribute density to grid points that are more than $\sqrt(2*6.25)$ from the center of the kernel.
     220             : 
     221             : Kernel density estimation is a method for estimating a histogram but it is probably not the first method that you learned for estimating histograms. Instead you probably learned to assume that the
     222             : the density is constant between grid points. In 1D we thus express the density between grid point $x_k$ and $x_{k+1}$ using:
     223             : 
     224             : $$
     225             : F(x_{k+1}) - F(x_k) = \int_{x_k}^{x_{k+1}} f(x) \textrm{d}x = \int_{x_k}^{x_{k+1}} \sum_{t=1}^n h_t K\left[ \frac{|x - x_t|}{\sigma} \right] \textrm{d}x
     226             : $$
     227             : 
     228             : In the typical method for calculating histograms $\sigma=x_{k+1}-x_k$ and $K$ is then:
     229             : 
     230             : $$
     231             : K(x) = \begin{cases}
     232             : 1 & \textrm{if} x<1 \\
     233             : 0 & \textrm{otherwise}
     234             : \end{cases}
     235             : $$
     236             : 
     237             : This is the method used for estimating the histogram when you use KERNEL=DISCRETE. Other (continuous) choices for $K$ are possible and are described in the documentation for [BETWEEN](BETWEEN.md).
     238             : For example, in the following input $K$ is is a Gaussian:
     239             : 
     240             : ```
     241             : d1: DISTANCE ATOMS=1,2
     242             : kde: KDE ARG=d1 GRID_MIN=0.0 GRID_MAX=1.0 GRID_BIN=100 BANDWIDTH=0.2 KERNEL=gaussian-bin
     243             : DUMPGRID ARG=kde STRIDE=1 FILE=kde.grid
     244             : ```
     245             : 
     246             : Multidimensional analogues of this approach can also be used. For example, in a 2D analogue the density in the square with corners at $(x_k,y_j)$, $(x_{k+1},y_j)$, $(x_k,y_{j+1})$ and $(x_{k+1},y_{j+1})$ is computed using:
     247             : 
     248             : $$
     249             : [ F(x_{k+1}) - F(x_k) ][ F(y_{j+1} - F(y_j) ] = \int_{x_k}^{x_{k+1}} f(x) \textrm{d}x = \sum_{t=1}^n h_t \int_{x_k}^{x_{k+1}} K\left[ \frac{|x - x_t|}{\sigma} \right] \textrm{d}x \int_{y_j}^{y_{j+1}} K\left[ \frac{|y - y_t|}{\sigma} \right] \textrm{d}y
     250             : $$
     251             : 
     252             : */
