      30             : /*
      31             : Create a histogram from the input scalar/vector/matrix using KDE
      32             : 
      33             : This action can be used to construct instantaneous distributions for quantities by using [kernel density esstimation](https://en.wikipedia.org/wiki/Kernel_density_estimation).
      34             : The input arguments must all have the same rank and size but you can use a scalar, vector or matrix in input.  The distribution
      35             : of this quantity on a grid is then computed using kernel density estimation.
      36             : 
      37             : The following example demonstrates how this action can be used with a scalar as input:
      38             : 
      39             : ```plumed
      40             : d1: DISTANCE ATOMS=1,2
      41             : kde: KDE ARG=d1 GRID_MIN=0.0 GRID_MAX=1.0 GRID_BIN=100 BANDWIDTH=0.2
      42             : DUMPGRID ARG=kde STRIDE=1 FILE=kde.grid
      43             : ```
      44             : 
      45             : This input outputs a different file on every time step. These files contain a function stored on a grid.  The function output in this case
      46             : consists of a single Gaussian with $\sigma=0.2$ that is centered on the instantaneous value of the distance between atoms 1 and 2.  Obviously,
      47             : you are unlikely to use an input like the one above. The more usual thing to do would be to accumulate the histogram over the course of a
      48             : few trajectory frames using the [ACCUMULATE](ACCUMULATE.md) command as has been done in the input below, which estimates a histogram as a function
      49             : of two collective variables:
      50             : 
      51             : ```plumed
      52             : d1: DISTANCE ATOMS=1,2
      53             : d2: DISTANCE ATOMS=1,2
      54             : kde: KDE ARG=d1,d2 GRID_MIN=0.0,0.0 GRID_MAX=1.0,1.0 GRID_BIN=100,100 BANDWIDTH=0.2,0.2
      55             : histo: ACCUMULATE ARG=kde STRIDE=1
      56             : DUMPGRID ARG=histo FILE=histo.grid STRIDE=10000
      57             : ```
      58             : 
      59             : Notice, that you can also achieve something similar by using the [HISTOGRAM](HISTOGRAM.md) shortcut.
      60             : 
      61             : ## Controlloing the grid
      62             : 
      63             : If you prefer to specify the grid spacing rather than the number of bins you can do so using the GRID_SPACING keyword as shown below:
      64             : 
      65             : ```plumed
      66             : d1: DISTANCE ATOMS=1,2
      67             : kde: KDE ARG=d1 GRID_MIN=0.0 GRID_MAX=1.0 GRID_SPACING=0.01 BANDWIDTH=0.2
      68             : DUMPGRID ARG=kde STRIDE=1 FILE=kde.grid
      69             : ```
      70             : 
      71             : If $x$ is one of the input arguments to the KDE action and $x<g_{min}$ or $x>g_{max}$, where $g_{min}$ and $g_{max}$ are the minimum
      72             : and maximum values on the grid for that argument that were specified using GRID_MIN and GRID_MAX, then by PLUMED will crash.
      73             : 
      74             : Notice also that when you use Gaussian kernels to accumulate a denisty as in the input above you need to define a cutoff beyond, which the
      75             : Gaussian (which is a function with infinite support) is assumed not to contribute to the accumulated density.  When setting this cutoff you
      76             : set the value of $x$ in the following expression $\sigma \sqrt{2*x}$, where $\sigma$ is the bandwidth.  By default $x$ is set equal to 6.25 but
      77             : you can change this value by using the CUTOFF keyword as shown below:
      78             : 
      79             : ```plumed
      80             : d1: DISTANCE ATOMS=1,2
      81             : kde: KDE ARG=d1 GRID_MIN=0.0 GRID_MAX=1.0 GRID_SPACING=0.01 BANDWIDTH=0.2 CUTOFF=6.25
      82             : DUMPGRID ARG=kde STRIDE=1 FILE=kde.grid
      83             : ```
      84             : 
      85             : ## Constructing the density
      86             : 
      87             : If you are performing a simulation in the NVT ensemble and wish to look at the density as a function of position in the cell you can use an input like the one shown below:
      88             : 
      89             : ```plumed
      90             : a: FIXEDATOM AT=0,0,0
      91             : dens: DISTANCES ATOMS=1-100 ORIGIN=a COMPONENTS
      92             : kde: KDE ARG=dens.x,dens.y,dens.z GRID_BIN=100,100,100 BANDWIDTH=0.05,0.05,0.05
      93             : DUMPGRID ARG=kde STRIDE=1 FILE=density
      94             : ```
      95             : 
      96             : Notice that you do not need to specify GRID_MIN and GRID_MAX values with this input. In this case PLUMED gets the extent of the grid from the cell vectors during the first
      97             : step of the simulation.
      98             : 
      99             : ## Specifying a non diagonal bandwidth
     100             : 
     101             : If for any reason you want to use a bandwidth that is not diagonal when doing kensity density estimation you can do by using an input similar to the one shown below:
     102             : 
     103             : ```plumed
     104             : d1: DISTANCE ATOMS=1,2
     105             : d2: DISTANCE ATOMS=1,2
     106             : kde: KDE ...
     107             :   ARG=d1,d2 GRID_MIN=0.0,0.0
     108             :   GRID_MAX=1.0,1.0 GRID_BIN=100,100
     109             :   BANDWIDTH=0.2,0.1,0.1,0.2 HEIGHTS=1
     110             : ...
     111             : histo: ACCUMULATE ARG=kde STRIDE=1
     112             : DUMPGRID ARG=histo FILE=histo.grid STRIDE=10000
     113             : ```
     114             : 
     115             : As there are two arguments for this KDE action the four numbers passed in the bandwdith parameter are interepretted as a $2\times 2$ matrix.
     116             : Notice that you can also pass the information for the bandwidth in from another argument as has been done here:
     117             : 
     118             : ```plumed
     119             : m: CONSTANT VALUES=0.2,0.1,0.1,0.2 NROWS=2 NCOLS=2
     120             : 
     121             : d1: DISTANCE ATOMS=1,2

     125             :   GRID_MAX=1.0,1.0 GRID_BIN=100,100

     127             : ...

     129             : DUMPGRID ARG=histo FILE=histo.grid STRIDE=10000
     130             : ```
     131             : 
     132             : In this case the input is equivalent to the first input above and the bandwidth is a constant.  You could, however, also use a non-constant value as input to the BANDWIDTH keyword.
     133             : 
     134             : ## Working with vectors and scalars
     135             : 
     136             : If the input to your KDE action is a set of scalars it appears odd to separate the process of computing the KDE from the process of accumulating the histogram. However, if
     137             : you are using vectors as in the example below, this division can be helpful.
     138             : 
     139             : ```plumed
     140             : d1: DISTANCE ATOMS1=1,2 ATOMS2=3,4 ATOMS3=5,6 ATOMS4=7,8 ATOMS5=9,10
     141             : kde: KDE ARG=d1 GRID_MIN=0.0 GRID_MAX=1.0 GRID_BIN=100 BANDWIDTH=0.2
     142             : ```
     143             : 
     144             : In the papea cited in the bibliography below, the [KL_ENTROPY](KL_ENTROPY.md) between the instantaneous distribution of CVs and a reference distribution was introduced
     145             : as a collective variable. As is detailed in the documentation for that action, the ability to calculate the instantaneous histogram from an input vector is essential to
     146             : reproducing these calculations.
     147             : 
     148             : Notice that you can also use a one or multiple matrices in the input for a KDE object.  The example below uses the angles between the z axis and set of bonds aroud two
     149             : atoms:
     150             : 
     151             : ```plumed
     152             : d1: DISTANCE_MATRIX GROUPA=1,2 GROUPB=3-10 COMPONENTS
     153             : phi: CUSTOM ARG=d1.z,d1.w FUNC=acos(x/y) PERIODIC=NO
     154             : kde: KDE ARG=phi GRID_MIN=0 GRID_MAX=pi GRID_BIN=200 BANDWIDTH=0.1
     155             : ```
     156             : 
     157             : ## Using different weights
     158             : 
     159             : In all the inputs above the kernels that are added to the grid on each step are Gaussians with that are normalised so that their integral over all space is one. If you want your
     160             : Gaussians to have a particular height you can use the HEIGHT keyword as illustrated below:
     161             : 
     162             : ```plumed
     163             : d1: CONTACT_MATRIX GROUPA=1,2 GROUPB=3-10 SWITCH={RATIONAL R_0=0.1} COMPONENTS
     164             : mag: CUSTOM ARG=d1.x,d1.y,d1.z FUNC=x*x+y*y+z*z PERIODIC=NO
     165             : phi: CUSTOM ARG=d1.z,mag FUNC=acos(x/sqrt(y)) PERIODIC=NO
     166             : kde: KDE ARG=phi GRID_MIN=0 GRID_MAX=pi HEIGHTS=d1.w GRID_BIN=200 BANDWIDTH=0.1
     167             : ```
     168             : 
     169             : As indicated above, the HEIGHTS keyword should be passed a Value that has the same rank and size as the arguments that are passed using the ARG keyword. Each of the Gaussian kernels
     170             : that are added to the grid in this case have a value equal to the weight at the maximum of the function.
     171             : 
     172             : Notice that you can also use the VOLUMES keyword in a similar way as shown below:
     173             : 
     174             : ```plumed
     175             : d1: CONTACT_MATRIX GROUPA=1,2 GROUPB=3-10 SWITCH={RATIONAL R_0=0.1} COMPONENTS
     176             : mag: CUSTOM ARG=d1.x,d1.y,d1.z FUNC=x*x+y*y+z*z PERIODIC=NO
     177             : phi: CUSTOM ARG=d1.z,mag FUNC=acos(x/sqrt(y)) PERIODIC=NO
     178             : kde: KDE ARG=phi GRID_MIN=0 GRID_MAX=pi VOLUMES=d1.w GRID_BIN=200 BANDWIDTH=0.1
     179             : ```
     180             : 
     181             : Now, however, the integral of the Gaussians over all space are equal to the elements of d1.w.
     182             :
