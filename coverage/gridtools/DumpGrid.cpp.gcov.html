      33             : /*
      34             : Output a three dimensional grid using the Gaussian cube file format.
      35             : 
      36             : Suppose you have calculated the value of a function on a three dimensional grid.
      37             : This function might be a [HISTOGRAM](HISTOGRAM.md), [KDE](KDE.md) or it might be a free energy energy surface
      38             : that was calculated from this histogram by using [CONVERT_TO_FES](CONVERT_TO_FES.md).  Alternatively,
      39             : your function might be a phase-field that was calculated using [MULTICOLVARDENS](MULTICOLVARDENS.md) or a series of [CUSTOM](CUSTOM.md) functions
      40             : that had been applied on the input grid.
      41             : Whatever the function is, however, you obviously cannot show it using a typical contour
      42             : plotting program such as gnuplot as you have three input variables.
      43             : 
      44             : Tools like VMD have nice features for plotting these types of three dimensional functions
      45             : but typically you are required to use a Gaussian cube file format to input the data.  This
      46             : action thus allows you to output a function evaluated on a grid to a Gaussian cube file format.
      47             : 
      48             : ## Examples
      49             : 
      50             : The input below can be used to post process a trajectory.  A histogram as a function of the distance
      51             : between atoms 1 and 2, the distance between atom 1 and 3 and the angle between the vector connecting atoms 1 and
      52             : 2 and 1 and 3 is computed using kernel density estimation.  Once all the data contained in the trajectory has been read in and
      53             : all the kernels have been added the resulting histogram is output to a file called histoA1.cube.  This file has the
      54             : Gaussian cube file format.  The histogram can thus be visualized using tools such as VMD.
      55             : 
      56             : ```plumed
      57             : x1: DISTANCE ATOMS=1,2
      58             : x2: DISTANCE ATOMS=1,3
      59             : x3: ANGLE ATOMS=1,2,3
      60             : 
      61             : hA1: HISTOGRAM ARG=x1,x2,x3 GRID_MIN=0.0,0.0,0.0 GRID_MAX=3.0,3.0,3.0 GRID_BIN=10,10,10 BANDWIDTH=1.0,1.0,1.0
      62             : DUMPCUBE ARG=hA1 FILE=histoA1.cube
      63             : ```
      64             : 
      65             : In the input above the cube file is output at the end of the simulation or when the full trajectory has been read.
      66             : If you want to output the cube file every 1000 steps you would use an input like the one shown below:
      67             : 
      68             : ```plumed
      69             : x1: DISTANCE ATOMS=1,2
      70             : x2: DISTANCE ATOMS=1,3
      71             : x3: ANGLE ATOMS=1,2,3
      72             : 
      73             : hA1: HISTOGRAM ARG=x1,x2,x3 GRID_MIN=0.0,0.0,0.0 GRID_MAX=3.0,3.0,3.0 GRID_BIN=10,10,10 BANDWIDTH=1.0,1.0,1.0
      74             : DUMPCUBE ARG=hA1 FILE=histoA1.cube STRIDE=1000
      75             : ```
      76             : 
      77             : The default option is used here and thus multiple cube files are output.  The cube file that is obtained from the
      78             : first 1000 steps of the trajectory will be named `analysis.0.histoA1.cube`, the one from the second 1000 steps of
      79             : trajectory is named `analysis.1.histoA1.cube` and so on until the final histogram output, which will called
      80             : `histoA1.cube`.  If you would like to output the data from all these cube files in a single file you use the
      81             : `PRINT_ONE_FILE` flag as shown below:
      82             : 
      83             : ```plumed
      84             : x1: DISTANCE ATOMS=1,2
      85             : x2: DISTANCE ATOMS=1,3
