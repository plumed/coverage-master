      45             : //+PLUMEDOC BIAS METAD
      46             : /*
      47             : Used to perform metadynamics on one or more collective variables.
      48             : 
      49             : In a metadynamics simulations a history dependent bias composed of
      50             : intermittently added Gaussian functions is added to the potential as discussed in the first paper cited below.
      51             : 
      52             : $$
      53             : V(\vec{s},t) = \sum_{ k \tau < t} W(k \tau)
      54             : \exp\left(
      55             : -\sum_{i=1}^{d} \frac{(s_i-s_i^{(0)}(k \tau))^2}{2\sigma_i^2}
      56             : \right).
      57             : $$
      58             : 
      59             : This potential forces the system away from the kinetic traps in the potential energy surface
      60             : and out into the unexplored parts of the energy landscape. Information on the Gaussian
      61             : functions from which this potential is composed is output to a file called HILLS, which
      62             : is used both to restart the calculation and to reconstruct the free energy as a function of the CVs.
      63             : The free energy can be reconstructed from a metadynamics calculation because the final bias is given
      64             : by:
      65             : 
      66             : $$
      67             : V(\vec{s}) = -F(\vec{s})
      68             : $$
      69             : 
      70             : During post processing the free energy can be calculated in this way using the [sum_hills](sum_hills.md)
      71             : utility.
      72             : 
      73             : The following example provides an example input for a simple metadynamics calculation:
      74             : 
      75             : ```plumed
      76             : d1: DISTANCE ATOMS=3,5
      77             : d2: DISTANCE ATOMS=2,4
      78             : restraint: METAD ARG=d1,d2 SIGMA=0.2,0.2 HEIGHT=0.3 PACE=500
      79             : PRINT ARG=d1,d2,restraint.bias STRIDE=100  FILE=COLVAR
      80             : ```
      81             : 
      82             : In this calculation the distance between atoms 3 and 5
      83             : and the distance between atoms 2 and 4 are used as collective variables. Gaussian hills with a height of 0.3 kJ/mol
      84             : and widths of 0.2 nm in the two CVs are added every 500 steps. The values
      85             : of the CVs and the metadynamics bias potential are written to the COLVAR file every 100 steps.
      86             : 
      87             : ## Using grids
      88             : 
      89             : In the simplest possible implementation of a metadynamics calculation __the expense associated with calculating the
      90             : bias potential increases with the length of the simulation as one has to, at every step, evaluate
      91             : the values of a larger and larger number of Gaussian kernels. To avoid this issue you can
      92             : store the bias on a grid.__  This approach is similar to that proposed in the second paper cited below but has the
      93             : advantage that the grid spacing is independent of the Gaussian width.  An example input for a calculation
      94             : that uses a grid to store the bias is shown below:
      95             : 
      96             : 
      97             : ```plumed
      98             : t1: TORSION ATOMS=1,2,3,4
      99             : t2: TORSION ATOMS=5,6,7,8
     100             : m: METAD ARG=t1,t2 SIGMA=0.1,0.1 HEIGHT=1.2 PACE=500 GRID_MIN=-pi,-pi GRID_MAX=pi,pi GRID_BIN=100,100
     101             : PRINT ARG=t1,t2,m.bias STRIDE=100 FILE=COLVAR
     102             : ```
     103             : 
     104             : GRID_MIN and GRID_MAX give the initial range of the grid.  You can also specify the number
     105             : of grid points for every collective variable (GRID_BIN) or the desired grid spacing (GRID_SPACING).
     106             : If you specify the GRID_SPACING and the number of bins  PLUMED uses the most conservative choice.  In other words, it uses
     107             : the choice that gives you the  largest number of bins for each dimension.
     108             : 
     109             : If you specify neither GRID_BIN nor GRID_SPACING PLUMED uses 1/5 of the Gaussian width (SIGMA) as grid spacing if the width is
     110             : fixed or 1/5 of the minimum Gaussian width (SIGMA_MIN - see next section) if the width is variable.
     111             : This default choice should be reasonable for most applications.
     112             : 
     113             : The grid is extended automatically, along the variables that are not periodic, whenever a Gaussian does not fit in it:
     114             : the grid always contains all the points where a Gaussian is not zero (Gaussians are truncated at a distance of
     115             : $\sqrt{2\cdot 6.25}$ widths, and stretched so that they go to zero there), so that the
     116             : bias is exactly zero outside it (with INTERVAL, the grid contains the interval, and beyond the limits the bias is
     117             : the constant value at the limits).  The grid spacing does not change and the new points are on the same lattice as the
     118             : initial ones, so the bias is the same as with a grid that is large enough from the beginning.  Every extension is
     119             : written on the log.  If you give GRID_SPACING without GRID_MIN and GRID_MAX the grid is placed around the first Gaussian and
     120             : then extended as needed, so that you do not need to know in advance the range explored by the variables.  The variables
     121             : that are periodic are always covered by the grid over the whole period.  GRID_SIZE_LIMIT sets the maximum number of points
     122             : of the grid: the calculation stops with an error if a Gaussian would require a larger grid (e.g. with a distance that grows
     123             : without limit); notice that every MPI process has its own copy of the grid.  Quantities that are obtained from the whole
     124             : grid (such as the c(t) reweighting factor, see CALC_RCT) are computed over the current range of the grid, so they change
     125             : when the grid is extended.  A TARGET grid is not extended: the variables must remain in its range.
     126             : 
     127             : ```plumed
     128             : d: DISTANCE ATOMS=1,10
     129             : m: METAD ARG=d SIGMA=0.05 HEIGHT=1.2 PACE=500 GRID_SPACING=0.01
     130             : PRINT ARG=d,m.bias STRIDE=100 FILE=COLVAR
     131             : ```
     132             : 
     133             : ## Using neighbour lists
     134             : 
     135             : Another way to decrease the cost associated with evaluating the metadynamics bias is to use a neighbor list.  If you
     136             : wish to use this alternative to grids you use the NLIST keyword as illustrated below.
     137             : 
     138             : ```plumed
     139             : d1: DISTANCE ATOMS=1,2
     140             : d2: DISTANCE ATOMS=3,4
     141             : d3: DISTANCE ATOMS=5,6
     142             : d4: DISTANCE ATOMS=7,8
     143             : m: METAD ARG=d1,d2,d3,d4 SIGMA=0.1,0.1,0.1,0.1 HEIGHT=1.2 PACE=500 NLIST
     144             : PRINT ARG=d1,d2,d3,d4,m.bias,m.nlker FILE=colvar
     145             : ```
     146             : 
     147             : Using NLIST is beneficial if you are using more than 2 collective variables as if you are using large numbers of CVs GRID becomes
     148             : expensive and memory consuming. Furthermore, as indicated above, if you are using this option you can have access to a value called
     149             : `nlker`, which tells you how many Gaussians were evaluated in each step.
     150             : 
     151             : The neighbor list is updated everytime the CVs move farther than a cut-off value
     152             : from the position they were at last neighbor list update. Gaussians are added to the neigbhor list if their center
     153             : is within 6.*DP2CUTOFF*sigma*sigma. While the list is updated if the CVs are farther from the center than 0.5 of the
     154             : standard deviation of the Gaussian center distribution of the list. These parameters (6 and 0.5) can be modified using
     155             : NLIST_PARAMETERS. Note that the use of neighbor list does not provide the exact bias.
     156             : 
     157             : ## Restarting a metadynamics simulation
     158             : 
     159             : Metadynamics can be restarted from a HILLS file as illustrated in the following input:
     160             : 
     161             : ```plumed
     162             : #SETTINGS INPUTFILES=regtest/basic/rt-mpi6/HILLS_multi
     163             : 
     164             : RESTART
     165             : d: DISTANCE ATOMS=1,10
     166             : c: COORDINATION GROUPA=1-108 GROUPB=1-108 R_0=0.5
     167             : m: METAD ARG=c,d SIGMA=0.1,0.2 HEIGHT=0.1 PACE=500 FILE=regtest/basic/rt-mpi6/HILLS_multi
     168             : PRINT ARG=d,c FILE=colvar STRIDE=10
     169             : ```
     170             : 
     171             : If you don't specify the location of the HILLS file then PLUMED looks for a file called HILLS to read in.
     172             : Metadynamics can also be restarted from a GRID, as in this second example.
     173             : 
     174             : ```plumed
     175             : #SETTINGS INPUTFILES=extras/1d_bias.grid
     176             : 
     177             : d1: DISTANCE ATOMS=1,2
     178             : m: METAD ...
     179             :   ARG=d1 SIGMA=0.1
     180             :   HEIGHT=0.1 PACE=500
     181             :   GRID_MIN=1.14 GRID_MAX=1.32 GRID_BIN=5
     182             :   GRID_RFILE=extras/1d_bias.grid
     183             :   RESTART=YES
     184             : ...
     185             : PRINT ARG=d1,m.bias FILE=colvar STRIDE=10
     186             : ```
     187             : 
     188             : Notice that if you want to use this option you first need to save the GRID using GRID_WFILE (and GRID_WSTRIDE) in the
     189             : previous simulation.
     190             : 
     191             : No Gaussian is added at the first step of a simulation.  When a simulation is continued with RESTART, a Gaussian is added
     192             : at the first step unless the hills file already contains it, i.e. unless the previous run had already performed this step
     193             : (some MD codes compute again the last step of the previous run when restarting, others do not).  When the bias is read
     194             : from a grid, the hills file (FILE) is still read, without adding its hills to the bias, to know the time of its last hill.
     195             : 
     196             : With [CHECKPOINT](CHECKPOINT.md) the restart is exact: the bias (the grid or the list of hills), the steps when the hills
     197             : are added, the statistics of the adaptive hills, the accumulated work, acceleration factor and c(t), and the number of
     198             : hills already read from the files of the other walkers (WALKERS_N) are restored from the checkpoint, and the hills file is
     199             : truncated at the checkpointing step instead of being read.  GRID_RFILE and ACCELERATION_RFILE are then not read.
     200             : 
     201             : Notice, also that in the first input above the
     202             : [RESTART](RESTART.md) action was used, while the second input used METAD's RESTART keyword.  If you use the first input
     203             : every action in the input is restarted so the [PRINT](PRINT.md) command will append to the output file from the earlier calculation.
     204             : In this second input, however, only the METAD action is restarted so the [PRINT](PRINT.md) file will output data to a new file and
     205             : back up any old files it finds with the same name.

     222             : ## Well-tempered metadynamics
     223             : 
     224             : Another option that is available in plumed is well-tempered metadynamics that is introduced in the third paper cited below. In this
     225             : variant of metadynamics the heights of the Gaussian hills are scaled at each step so the bias is now
     226             : given by:
     227             : 
     228             : $$
     229             : V({s},t)= \sum_{t'=0,\tau_G,2\tau_G,\dots}^{t'<t} W e^{-V({s}({q}(t'),t'))/\Delta T} \exp\left(
     230             : -\sum_{i=1}^{d} \frac{(s_i({q})-s_i({q}(t')))^2}{2\sigma_i^2}
     231             : \right),
     232             : $$
     233             : 
     234             : This method ensures that the bias converges more smoothly. The following example shows an example input for a well-tempered metadynamics
     235             : calculation.
     236             : 
     237             : ```plumed
     238             : d1: DISTANCE ATOMS=3,5
     239             : d2: DISTANCE ATOMS=2,4
     240             : restraint: METAD ARG=d1,d2 SIGMA=0.2,0.2 HEIGHT=0.3 BIASFACTOR=10 PACE=500
     241             : PRINT ARG=d1,d2,restraint.bias STRIDE=100  FILE=COLVAR
     242             : ```
     243             : 
     244             : It should be noted that, if you do well-tempered metadynamics,
     245             : the hills file output contains the value of Gaussian height re-scaled by the bias factor.
     246             : This rescaling is done to ensure that the HILLS file contains
     247             : negative of the free-energy estimate and __not__ the bias potential. An added bonus of this choice is that
     248             : one can restart a simulation using a different value for the $\Delta T$. The applied bias will be scaled accordingly.
     249             : 
     250             : ## Metadynamics with flexible Gaussians
     251             : 
     252             : You can also use the flexible Gaussian approach that is discussed in the fourth paper cited below.
     253             : This method adapts the Gaussian to the extent of Cartesian space covered by a variable or
     254             : to the space in collective variable covered in a given time. When you use these methods the width of the deposited
     255             : Gaussian potential is denoted by one value only that is a Cartesian space (ADAPTIVE=GEOM) or a time
     256             : (ADAPTIVE=DIFF). Note that a specific integration technique, which is discussed in the documentation for
     257             : [sum_hills](sum_hills.md), must be used when calculating the free energy from the deposited Gaussian kernels in this case.
     258             : 
     259             : The following example shows how to use adaptive Gaussian kernels, with the diffusion scheme.  In this example
     260             : Gaussians that cover the space of 20 time steps in collective variables are used.
     261             : 
     262             : ```plumed
     263             : d1: DISTANCE ATOMS=3,5
     264             : d2: DISTANCE ATOMS=2,4
     265             : restraint: METAD ARG=d1,d2 SIGMA=20 HEIGHT=0.3 PACE=500 ADAPTIVE=DIFF
     266             : PRINT ARG=d1,d2,restraint.bias STRIDE=100  FILE=COLVAR
     267             : ```
     268             : 
     269             : This second example shows you how to use adaptive Gaussian kernels, with the geometrical scheme.  In this example
     270             : Gaussians that cover the space of 0.05 nm in Cartesian space are used
     271             : 
     272             : ```plumed
     273             : d1: DISTANCE ATOMS=3,5
     274             : d2: DISTANCE ATOMS=2,4
     275             : restraint: METAD ARG=d1,d2 SIGMA=0.05 HEIGHT=0.3 PACE=500 ADAPTIVE=GEOM
     276             : PRINT ARG=d1,d2,restraint.bias STRIDE=100  FILE=COLVAR
     277             : ```
     278             : 
     279             : With both these methods you can limit how much the hills width can change by using the SIGMA_MIN and SIGMA_MAX keywords
     280             : as shown below.
     281             : 
     282             : ```plumed
     283             : d1: DISTANCE ATOMS=3,5
     284             : d2: DISTANCE ATOMS=2,4
     285             : restraint: METAD ...
     286             :   ARG=d1,d2 SIGMA=0.05 HEIGHT=0.3 PACE=500 ADAPTIVE=GEOM
     287             :   SIGMA_MIN=0.2,0.1 SIGMA_MAX=0.5,1.0
     288             : ...
     289             : PRINT ARG=d1,d2,restraint.bias STRIDE=100  FILE=COLVAR
     290             : ```
     291             : 
     292             : The sigma values that are provided to these two keywords are specified in the units of the CV.
     293             : Note that if you use a negative number, this means that the limit is not set.
     294             : 
     295             : With ADAPTIVE=DIFF the width of the hills is obtained from running averages of the CV values and of
     296             : their fluctuations over a time given by SIGMA (in time steps). These statistics are accumulated when the bias
     297             : is updated, so that with UPDATE_FROM they start only at the beginning of the update window and the first
     298             : hills can be much narrower than the following ones. With the PRECAL_DIFF flag the statistics are
     299             : accumulated from the beginning of the simulation: by using UPDATE_FROM with a time
     300             : larger than the one given by SIGMA, all the hills have a width estimated over a sufficiently long time.
     301             : 
     302             : ```plumed
     303             : d1: DISTANCE ATOMS=3,5
     304             : restraint: METAD ARG=d1 SIGMA=500 HEIGHT=0.3 PACE=50 ADAPTIVE=DIFF PRECAL_DIFF UPDATE_FROM=2.0
     305             : ```
     306             : 
     307             : When restarting, the statistics are initialized from the last hills of the hills file of the walker:
     308             : the covariance of the fluctuations is the one of the last hill, and the running average of the CVs is
     309             : estimated from the centers of the last hills, with the weights used by the running average.
     310             : This is also done when the bias is read from a grid (GRID_RFILE), if the hills file is available,
     311             : using only the hills deposited before the current time.
     312             : In this way the hills deposited after a restart have the same width they would have had without the restart,
     313             : apart from the effect of the limits set with SIGMA_MIN and SIGMA_MAX, which are applied to the hills.
     314             : Only the last hills of the walker that belong to the same run and precede the current time are used.
     315             : The hills file does not record how the hills were obtained: if it was written with a different
     316             : SIGMA, or with ADAPTIVE=GEOM, use the DIFF_FROM_SCRATCH flag. With this flag the statistics are
     317             : accumulated again from the restart, as in previous versions; no hill is then added before at least two
     318             : CV values are available.
     319             : 
     320             : ADAPTIVE=DIFF can be used with replica exchange. Since the MD code does not tell PLUMED
     321             : whether an exchange has been accepted, after an exchange attempt the CV values are compared with those
     322             : of the exchange partner: when the exchange is detected as accepted, the running average of the CVs is
     323             : restarted from their new values, while the estimate of their fluctuations is kept.
     324             : Note also that in this case the histogram correction is needed when summing up hills.
     325             : 
     326             : ## Metadynamics with the interval keyword
     327             : 
     328             : When you use the keyword INTERVAL the metadynamics bias force is set equal to zero
     329             : outside of a boundary as discussed in the fifth paper cited below. This feature is useful if, for example, metadynamics is performed on one or more CVs and if one is only interested
     330             : in the free energy for s > boundary.  When you use this option the history dependent potential is still updated in accordance with the formulas above.
     331             : The difference is simply that the metadynamics force is set to zero for s < boundary. This means that Gaussian kernels are added also
     332             : if s < boundary, as the tails of these Gaussian kernels influence VG in the relevant region s > boundary. In this way, the
     333             : force on the system in the region s > boundary comes from both metadynamics and the force field, while in the region
     334             : s < boundary the only force the system experiences is from the forcefield. This approach allows one to obtain a history-dependent bias potential VG that
     335             : fluctuates around a stable estimator, equal to the negative of the free energy far enough from the
     336             : boundaries. Notice that:
     337             : 
     338             : - This method only works for one-dimensional biases;
     339             : - It works both with and without GRID;
     340             : - The interval limit boundary should be set in a region where the derivative of the free energy is not large;
     341             : - If in the region outside the limit boundary the system has a free energy minimum, the INTERVAL keyword should
     342             :   be used together with a [UPPER_WALLS](UPPER_WALLS.md) or [LOWER_WALLS](LOWER_WALLS.md) that act when the system is beyond the boundary as illustrated in the following example.
     343             : 
     344             : ```plumed
     345             : r2g: DISTANCE ATOMS=1,2
     346             : m2g: METAD ARG=r2g HEIGHT=0.1 PACE=500 SIGMA=1.0 INTERVAL=4,8 FILE=H2G GRID_MIN=0 GRID_MAX=20 GRID_BIN=100
     347             : lw: LOWER_WALLS ARG=r2g AT=4 KAPPA=100
     348             : uw: UPPER_WALLS ARG=r2g AT=8 KAPPA=100
     349             : PRINT ARG=r2g,*.bias FILE=colvar STRIDE=10
     350             : ```
     351             : 
     352             : As a final note, since version 2.0.2 the force is set to zero and the bias value to the value at the corresponding boundary
     353             : when the system is outside of the selected interval. This choice allows acceptances for replica exchange methods to be computed correctly.
     354             : 
     355             : ## Multiple walkers metadynamics
     356             : 
     357             : The multiple walkers metadynamics method that is described in the sixth paper cited below can be used by using an input
     358             : like the one shown below:
     359             : 
     360             : ```plumed
     361             : d1: DISTANCE ATOMS=3,5
     362             : restraint: METAD ...
     363             :    ARG=d1 SIGMA=0.05 HEIGHT=0.3 PACE=500
     364             :    WALKERS_N=10
     365             :    WALKERS_ID=3
     366             :    WALKERS_DIR=../
     367             :    WALKERS_RSTRIDE=100
     368             : ...
     369             : ```
     370             : 
     371             : To use this method you need to set the number of walkers (WALKERS_N), the ID of the
     372             : current walker (WALKERS-ID), the directory where the files containing the hills files reside
     373             : (WALKERS_DIR) and the frequency to read the other walkers (WALKERS_RSTRIDE).
     374             : The bias potential experienced by all the walkers is synched between walkers every
     375             : WALKERS_RSTRIDE steps.  In addition, since version 2.2.5, hills files are automatically
     376             : flushed every WALKERS_RSTRIDE steps.
     377             : The grid written by a walker (GRID_WFILE) contains also the hills it has read from the files of the other walkers: their
     378             : number is written in a comment line after the grid.  When restarting from this grid (GRID_RFILE), only the hills of the
     379             : other walkers that are not in it are added.  For a grid written by an older version of PLUMED, the grid is assumed to
     380             : contain the hills of the other walkers up to the time of the last hill in the hills file of this walker.
     381             : With multiple walkers, the hills files and the grid files are read and written without the suffix of the replica
     382             : (e.g. with `--multi`): give a different GRID_WFILE to each walker (e.g. with `@replicas:`).

     384             : ## Reweighting a metadynamics simulation

     403             :    ARG=phi,psi

     413             : 
     414             : 
     415             : The expression used to calculate $c(t)$ follows directly from Eq. 3 in the seventh paper cited below,
     416             : where $F(\vec{s})=-\gamma/(\gamma-1) V(\vec{s})$.
     417             : This gives smoother results than Eqs. 13 and Eqs. 14 in that paper.
     418             : 
     419             : Notice that you can only use this option if you are accumulating the metadynamics bias on a grid.
     420             : $c(t)$ is given by the rct component of the METAD action above while the bias
     421             : normalized by $c(t)$ is given by the rbias component (rbias=bias-rct).  As illustrated above this
     422             : value  can be used to obtain a reweighted histogram.
     423             : 
     424             : By default $c(t)$ is updated every time the bias changes.  If this slows down the simulation, you can use the keyword
     425             : RCT_USTRIDE to update it only every RCT_USTRIDE*PACE steps (every RCT_USTRIDE Gaussian depositions, unless the pace
     426             : changes with FREQUENCY_ADAPTIVE): in the example input above $c(t)$ is calculated every 10 Gaussian depositions.
     427             :

     429             : ## Concurrent metadynamics
     430             : 
     431             : To implement the method of concurrent metadynamics that is discussed in the eighth paper cited below you insert multiple
     432             : METAD actions in your plumed input file.
     433             : 
     434             : ## Infrequent metadynamics
     435             : 
     436             : The kinetics of the transitions between basins can also be analyzed on the fly as
     437             : in discussed in the 9th paper cited below. The flag ACCELERATION turn on accumulation of the acceleration
     438             : factor that can then be used to determine the rate as illustrated by the following input.
     439             : 
     440             : ```plumed
     441             : psi: ANGLE ATOMS=7,9,15
     442             : 
     443             : md1: METAD ...
     444             :  ARG=psi SIGMA=0.20
     445             :  HEIGHT=1.20 TEMP=300.0 BIASFACTOR=10
     446             :  PACE=500 GRID_MIN=0 GRID_MAX=pi GRID_BIN=10
     447             :  ACCELERATION
     448             : ...
     449             : 
     450             : PRINT ARG=psi,md1.bias,md1.acc FILE=colvar STRIDE=10
     451             : ```
     452             : 
     453             : This method can be used together with [COMMITTOR](COMMITTOR.md) analysis to stop the simulation when the system get to the target basin.
     454             : It is meant to be used together with Well-Tempered Metadynamics. If restarting from a previous
     455             : metadynamics you need to use the ACCELERATION_RFILE keyword to give the name of the
     456             : data file from which the previous value of the acceleration factor should be read, otherwise the
     457             : calculation of the acceleration factor will be wrong.
     458             : 
     459             : ## Changing the deposition frequency adaptively
     460             : 
     461             : By using the flag FREQUENCY_ADAPTIVE the frequency adaptive scheme introduced in the 10th paper cited below
     462             : is turned on. The frequency for hill addition then changes dynamically based on the acceleration factor
     463             : according to the following equation
     464             : 
     465             : $$
     466             : \tau_{\mathrm{dep}}(t) =
     467             : \min\left[
     468             : \tau_0 \cdot
     469             : \max\left[\frac{\alpha(t)}{\theta},1\right]
     470             : ,\tau_{c}
     471             : \right]
     472             : $$
     473             : 
     474             : where $\tau_0$ is the initial hill addition frequency given by the PACE keyword,
     475             : $\tau_{c}$ is the maximum allowed frequency given by the FA_MAX_PACE keyword,
     476             : $\alpha(t)$ is the instantaneous acceleration factor at time $t$,
     477             : and $\theta$ is a threshold value that acceleration factor has to reach before
     478             : triggering a change in the hill addition frequency given by the FA_MIN_ACCELERATION keyword.
     479             : The frequency for updating the hill addition frequency according to this equation is
     480             : given by the FA_UPDATE_FREQUENCY keyword, by default it is the same as the value given
     481             : in PACE. The hill addition frequency increases monotonically such that if the
     482             : instantaneous acceleration factor is lower than in the previous updating step the
     483             : previous $\tau_{\mathrm{dep}}$ is kept rather than updating it to a lower value.
     484             : The instantaneous hill addition frequency $\tau_{\mathrm{dep}}(t)$ is outputted
     485             : to pace component. Note that if restarting from a previous metadynamics run you need to
     486             : use the ACCELERATION_RFILE keyword to read in the acceleration factors from the
     487             : previous run (the acceleration factor and the pace, if they are in the file), otherwise the hill addition frequency
     488             : will start from the initial frequency.
     489             : 
     490             : ## Targeted metadynamics
     491             : 
     492             : You can also provide a target distribution for your metadynamics simulations by using the keyword TARGET.
     493             : This idea is discussed in the last four papers cited in the references section.
     494             : 
     495             : The TARGET should be a grid containing a free-energy (i.e. the -$k_B$T*log for the desired target distribution).
     496             : Gaussian kernels will then be scaled by a factor
     497             : 
     498             : $$
     499             : e^{\beta(\tilde{F}(s)-\tilde{F}_{max})}
     500             : $$
     501             : 
     502             : Here $\tilde{F}(s)$ is the free energy defined on the grid and $\tilde{F}_{max}$ its maximum value.
     503             : Notice that we here used the maximum value as was done in the penultimate paper in the reference section.
     504             : This choice allows one to avoid the addition of exceedingly large Gaussian kernels. However,
     505             : it can also make the Gaussian too small. You should always choose the HEIGHT parameter carefully
     506             : in this case.
     507             : The grid file should be similar to other PLUMED grid files in that it should contain
     508             : both the target free-energy and its derivatives.
     509             : 
     510             : Notice that if you wish your simulation to converge to the target free energy you should use
     511             : the DAMPFACTOR command to provide a global tempering as is discussed in the last paper from the reference section.
     512             : Alternatively, if you use a BIASFACTOR your simulation will converge to a free
     513             : energy that is a linear combination of the target free energy and of the intrinsic free energy
     514             : determined by the original force field.
     515             : 
     516             : ```plumed
     517             : #SETTINGS INPUTFILES=extras/target.fes
     518             : 
     519             : d1: DISTANCE ATOMS=3,5
     520             : t1: METAD ...
     521             :  ARG=d1 SIGMA=0.05 TAU=200 DAMPFACTOR=100 PACE=250
     522             :  GRID_MIN=1.14 GRID_MAX=1.32 GRID_BIN=6
     523             :  TARGET=extras/target.fes
     524             : ...
     525             : 
     526             : PRINT ARG=d1,t1.bias STRIDE=100 FILE=COLVAR
     527             : ```
     528             : 
     529             : Notice that the BIASFACTOR can also be set equal to 1. In this case one will perform
     530             : unbiased sampling: no bias is applied, and the hills files and the grid contain the estimate of the negative of the
     531             : free energy (the heights of the hills are those of the limit of well-tempered metadynamics for a bias factor going to 1,
     532             : as in [PBMETAD](PBMETAD.md)). Instead of using HEIGHT, one should provide the TAU parameter as illustrated below.
     533             : 
     534             : ```plumed
     535             : d: DISTANCE ATOMS=3,5
     536             : METAD ARG=d SIGMA=0.1 TAU=4.0 TEMP=300 PACE=100 BIASFACTOR=1.0
     537             : ```
     538             : 
     539             : The HILLS file obtained will still work with `plumed sum_hills` so as to plot a free-energy.
     540             : The case where this makes sense is probably that of RECT simulations.
     541             : 
     542             : Regarding RECT simulations, you can also use the RECT keyword so as to avoid using multiple input files.
     543             : For instance, a single input file will be
     544             : 
     545             : ```plumed
     546             : d: DISTANCE ATOMS=3,5
     547             : METAD ARG=d SIGMA=0.1 TAU=4.0 TEMP=300 PACE=100 RECT=1.0,1.5,2.0,3.0
     548             : ```
     549             : 
     550             : The number of elements in the RECT array should be equal to the number of replicas.
     551             : 
     552             : */
