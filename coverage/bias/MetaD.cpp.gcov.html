      43             : //+PLUMEDOC BIAS METAD
      44             : /*
      45             : Used to perform metadynamics on one or more collective variables.
      46             : 
      47             : In a metadynamics simulations a history dependent bias composed of
      48             : intermittently added Gaussian functions is added to the potential as discussed in the first paper cited below.
      49             : 
      50             : $$
      51             : V(\vec{s},t) = \sum_{ k \tau < t} W(k \tau)
      52             : \exp\left(
      53             : -\sum_{i=1}^{d} \frac{(s_i-s_i^{(0)}(k \tau))^2}{2\sigma_i^2}
      54             : \right).
      55             : $$
      56             : 
      57             : This potential forces the system away from the kinetic traps in the potential energy surface
      58             : and out into the unexplored parts of the energy landscape. Information on the Gaussian
      59             : functions from which this potential is composed is output to a file called HILLS, which
      60             : is used both to restart the calculation and to reconstruct the free energy as a function of the CVs.
      61             : The free energy can be reconstructed from a metadynamics calculation because the final bias is given
      62             : by:
      63             : 
      64             : $$
      65             : V(\vec{s}) = -F(\vec{s})
      66             : $$
      67             : 
      68             : During post processing the free energy can be calculated in this way using the [sum_hills](sum_hills.md)
      69             : utility.
      70             : 
      71             : The following example provides an example input for a simple metadynamics calculation:
      72             : 
      73             : ```plumed
      74             : d1: DISTANCE ATOMS=3,5
      75             : d2: DISTANCE ATOMS=2,4
      76             : restraint: METAD ARG=d1,d2 SIGMA=0.2,0.2 HEIGHT=0.3 PACE=500
      77             : PRINT ARG=d1,d2,restraint.bias STRIDE=100  FILE=COLVAR
      78             : ```
      79             : 
      80             : In this calculation the distance between atoms 3 and 5
      81             : and the distance between atoms 2 and 4 are used as collective variables. Gaussian hills with a height of 0.3 kJ/mol
      82             : and widths of 0.2 nm in the two CVs are added every 500 steps. The values
      83             : of the CVs and the metadynamics bias potential are written to the COLVAR file every 100 steps.
      84             : 
      85             : ## Using grids
      86             : 
      87             : In the simplest possible implementation of a metadynamics calculation __the expense associated with calculating the
      88             : bias potential increases with the length of the simulation as one has to, at every step, evaluate
      89             : the values of a larger and larger number of Gaussian kernels. To avoid this issue you can
      90             : store the bias on a grid.__  This approach is similar to that proposed in the second paper cited below but has the
      91             : advantage that the grid spacing is independent of the Gaussian width.  An example input for a calculation
      92             : that uses a grid to store the bias is shown below:
      93             : 
      94             : 
      95             : ```plumed
      96             : t1: TORSION ATOMS=1,2,3,4
      97             : t2: TORSION ATOMS=5,6,7,8
      98             : m: METAD ARG=t1,t2 SIGMA=0.1,0.1 HEIGHT=1.2 PACE=500 GRID_MIN=-pi,-pi GRID_MAX=pi,pi GRID_BIN=100,100
      99             : PRINT ARG=t1,t2,m.bias STRIDE=100 FILE=COLVAR
     100             : ```
     101             : 
     102             : GRID_MIN and GRID_MAX give the initial range of the grid.  You can also specify the number
     103             : of grid points for every collective variable (GRID_BIN) or the desired grid spacing (GRID_SPACING).
     104             : If you specify the GRID_SPACING and the number of bins  PLUMED uses the most conservative choice.  In other words, it uses
     105             : the choice that gives you the  largest number of bins for each dimension.
     106             : 
     107             : If you specify neither GRID_BIN nor GRID_SPACING PLUMED uses 1/5 of the Gaussian width (SIGMA) as grid spacing if the width is
     108             : fixed or 1/5 of the minimum Gaussian width (SIGMA_MIN - see next section) if the width is variable.
     109             : This default choice should be reasonable for most applications.
     110             : 
     111             : The grid is extended automatically, along the variables that are not periodic, whenever a Gaussian does not fit in it:
     112             : the grid always contains all the points where a Gaussian is not zero (Gaussians are truncated at a distance of
     113             : $\sqrt{2\cdot 6.25}$ widths, and stretched so that they go to zero there), so that the
     114             : bias is exactly zero outside it (with INTERVAL, the grid contains the interval, and beyond the limits the bias is
     115             : the constant value at the limits).  The grid spacing does not change and the new points are on the same lattice as the
     116             : initial ones, so the bias is the same as with a grid that is large enough from the beginning.  Every extension is
     117             : written on the log.  If you give GRID_SPACING without GRID_MIN and GRID_MAX the grid is placed around the first Gaussian and
     118             : then extended as needed, so that you do not need to know in advance the range explored by the variables.  The variables
     119             : that are periodic are always covered by the grid over the whole period.  GRID_SIZE_LIMIT sets the maximum number of points
     120             : of the grid: the calculation stops with an error if a Gaussian would require a larger grid (e.g. with a distance that grows
     121             : without limit); notice that every MPI process has its own copy of the grid.  Quantities that are obtained from the whole
     122             : grid (such as the c(t) reweighting factor, see CALC_RCT) are computed over the current range of the grid, so they change
     123             : when the grid is extended.  A TARGET grid is not extended: the variables must remain in its range.
     124             : 
     125             : ```plumed
     126             : d: DISTANCE ATOMS=1,10
     127             : m: METAD ARG=d SIGMA=0.05 HEIGHT=1.2 PACE=500 GRID_SPACING=0.01
     128             : PRINT ARG=d,m.bias STRIDE=100 FILE=COLVAR
     129             : ```
     130             : 
     131             : ## Using neighbour lists
     132             : 
     133             : Another way to decrease the cost associated with evaluating the metadynamics bias is to use a neighbor list.  If you
     134             : wish to use this alternative to grids you use the NLIST keyword as illustrated below.
     135             : 
     136             : ```plumed
     137             : d1: DISTANCE ATOMS=1,2
     138             : d2: DISTANCE ATOMS=3,4
     139             : d3: DISTANCE ATOMS=5,6
     140             : d4: DISTANCE ATOMS=7,8
     141             : m: METAD ARG=d1,d2,d3,d4 SIGMA=0.1,0.1,0.1,0.1 HEIGHT=1.2 PACE=500 NLIST
     142             : PRINT ARG=d1,d2,d3,d4,m.bias,m.nlker FILE=colvar
     143             : ```
     144             : 
     145             : Using NLIST is beneficial if you are using more than 2 collective variables as if you are using large numbers of CVs GRID becomes
     146             : expensive and memory consuming. Furthermore, as indicated above, if you are using this option you can have access to a value called
     147             : `nlker`, which tells you how many Gaussians were evaluated in each step.
     148             : 
     149             : The neighbor list is updated everytime the CVs move farther than a cut-off value
     150             : from the position they were at last neighbor list update. Gaussians are added to the neigbhor list if their center
     151             : is within 6.*DP2CUTOFF*sigma*sigma. While the list is updated if the CVs are farther from the center than 0.5 of the
     152             : standard deviation of the Gaussian center distribution of the list. These parameters (6 and 0.5) can be modified using
     153             : NLIST_PARAMETERS. Note that the use of neighbor list does not provide the exact bias.
     154             : 
     155             : ## Restarting a metadynamics simulation
     156             : 
     157             : Metadynamics can be restarted from a HILLS file as illustrated in the following input:
     158             : 
     159             : ```plumed
     160             : #SETTINGS INPUTFILES=regtest/basic/rt-mpi6/HILLS_multi
     161             : 
     162             : RESTART
     163             : d: DISTANCE ATOMS=1,10
     164             : c: COORDINATION GROUPA=1-108 GROUPB=1-108 R_0=0.5
     165             : m: METAD ARG=c,d SIGMA=0.1,0.2 HEIGHT=0.1 PACE=500 FILE=regtest/basic/rt-mpi6/HILLS_multi
     166             : PRINT ARG=d,c FILE=colvar STRIDE=10
     167             : ```
     168             : 
     169             : If you don't specify the location of the HILLS file then PLUMED looks for a file called HILLS to read in.
     170             : Metadynamics can also be restarted from a GRID, as in this second example.
     171             : 
     172             : ```plumed
     173             : #SETTINGS INPUTFILES=extras/1d_bias.grid
     174             : 
     175             : d1: DISTANCE ATOMS=1,2
     176             : m: METAD ...
     177             :   ARG=d1 SIGMA=0.1
     178             :   HEIGHT=0.1 PACE=500
     179             :   GRID_MIN=1.14 GRID_MAX=1.32 GRID_BIN=5
     180             :   GRID_RFILE=extras/1d_bias.grid
     181             :   RESTART=YES
     182             : ...
     183             : PRINT ARG=d1,m.bias FILE=colvar STRIDE=10
     184             : ```
     185             : 
     186             : Notice that if you want to use this option you first need to save the GRID using GRID_WFILE (and GRID_WSTRIDE) in the
     187             : previous simulation.
     188             : 
     189             : No Gaussian is added at the first step of a simulation.  When a simulation is continued with RESTART, a Gaussian is added
     190             : at the first step unless the hills file already contains it, i.e. unless the previous run had already performed this step
     191             : (some MD codes compute again the last step of the previous run when restarting, others do not).  When the bias is read
     192             : from a grid, the hills file (FILE) is still read, without adding its hills to the bias, to know the time of its last hill.
     193             : 
     194             : Notice, also that in the first input above the
     195             : [RESTART](RESTART.md) action was used, while the second input used METAD's RESTART keyword.  If you use the first input
     196             : every action in the input is restarted so the [PRINT](PRINT.md) command will append to the output file from the earlier calculation.
     197             : In this second input, however, only the METAD action is restarted so the [PRINT](PRINT.md) file will output data to a new file and
     198             : back up any old files it finds with the same name.

     215             : ## Well-tempered metadynamics
     216             : 
     217             : Another option that is available in plumed is well-tempered metadynamics that is introduced in the third paper cited below. In this
     218             : variant of metadynamics the heights of the Gaussian hills are scaled at each step so the bias is now
     219             : given by:
     220             : 
     221             : $$
     222             : V({s},t)= \sum_{t'=0,\tau_G,2\tau_G,\dots}^{t'<t} W e^{-V({s}({q}(t'),t'))/\Delta T} \exp\left(
     223             : -\sum_{i=1}^{d} \frac{(s_i({q})-s_i({q}(t')))^2}{2\sigma_i^2}
     224             : \right),
     225             : $$
     226             : 
     227             : This method ensures that the bias converges more smoothly. The following example shows an example input for a well-tempered metadynamics
     228             : calculation.
     229             : 
     230             : ```plumed
     231             : d1: DISTANCE ATOMS=3,5
     232             : d2: DISTANCE ATOMS=2,4
     233             : restraint: METAD ARG=d1,d2 SIGMA=0.2,0.2 HEIGHT=0.3 BIASFACTOR=10 PACE=500
     234             : PRINT ARG=d1,d2,restraint.bias STRIDE=100  FILE=COLVAR
     235             : ```
     236             : 
     237             : It should be noted that, if you do well-tempered metadynamics,
     238             : the hills file output contains the value of Gaussian height re-scaled by the bias factor.
     239             : This rescaling is done to ensure that the HILLS file contains
     240             : negative of the free-energy estimate and __not__ the bias potential. An added bonus of this choice is that
     241             : one can restart a simulation using a different value for the $\Delta T$. The applied bias will be scaled accordingly.
     242             : 
     243             : ## Metadynamics with flexible Gaussians
     244             : 
     245             : You can also use the flexible Gaussian approach that is discussed in the fourth paper cited below.
     246             : This method adapts the Gaussian to the extent of Cartesian space covered by a variable or
     247             : to the space in collective variable covered in a given time. When you use these methods the width of the deposited
     248             : Gaussian potential is denoted by one value only that is a Cartesian space (ADAPTIVE=GEOM) or a time
     249             : (ADAPTIVE=DIFF). Note that a specific integration technique, which is discussed in the documentation for
     250             : [sum_hills](sum_hills.md), must be used when calculating the free energy from the deposited Gaussian kernels in this case.
     251             : 
     252             : The following example shows how to use adaptive Gaussian kernels, with the diffusion scheme.  In this example
     253             : Gaussians that cover the space of 20 time steps in collective variables are used.
     254             : 
     255             : ```plumed
     256             : d1: DISTANCE ATOMS=3,5
     257             : d2: DISTANCE ATOMS=2,4
     258             : restraint: METAD ARG=d1,d2 SIGMA=20 HEIGHT=0.3 PACE=500 ADAPTIVE=DIFF
     259             : PRINT ARG=d1,d2,restraint.bias STRIDE=100  FILE=COLVAR
     260             : ```
     261             : 
     262             : This second example shows you how to use adaptive Gaussian kernels, with the geometrical scheme.  In this example
     263             : Gaussians that cover the space of 0.05 nm in Cartesian space are used
     264             : 
     265             : ```plumed
     266             : d1: DISTANCE ATOMS=3,5
     267             : d2: DISTANCE ATOMS=2,4
     268             : restraint: METAD ARG=d1,d2 SIGMA=0.05 HEIGHT=0.3 PACE=500 ADAPTIVE=GEOM
     269             : PRINT ARG=d1,d2,restraint.bias STRIDE=100  FILE=COLVAR
     270             : ```
     271             : 
     272             : With both these methods you can limit how much the hills width can change by using the SIGMA_MIN and SIGMA_MAX keywords
     273             : as shown below.
     274             : 
     275             : ```plumed
     276             : d1: DISTANCE ATOMS=3,5
     277             : d2: DISTANCE ATOMS=2,4
     278             : restraint: METAD ...
     279             :   ARG=d1,d2 SIGMA=0.05 HEIGHT=0.3 PACE=500 ADAPTIVE=GEOM
     280             :   SIGMA_MIN=0.2,0.1 SIGMA_MAX=0.5,1.0
     281             : ...
     282             : PRINT ARG=d1,d2,restraint.bias STRIDE=100  FILE=COLVAR
     283             : ```
     284             : 
     285             : The sigma values that are provided to these two keywords are specified in the units of the CV.
     286             : Note that if you use a negative number, this means that the limit is not set.
     287             : 
     288             : With ADAPTIVE=DIFF the width of the hills is obtained from running averages of the CV values and of
     289             : their fluctuations over a time given by SIGMA (in time steps). These statistics are accumulated when the bias
     290             : is updated, so that with UPDATE_FROM they start only at the beginning of the update window and the first
     291             : hills can be much narrower than the following ones. With the PRECAL_DIFF flag the statistics are
     292             : accumulated from the beginning of the simulation: by using UPDATE_FROM with a time
     293             : larger than the one given by SIGMA, all the hills have a width estimated over a sufficiently long time.
     294             : 
     295             : ```plumed
     296             : d1: DISTANCE ATOMS=3,5
     297             : restraint: METAD ARG=d1 SIGMA=500 HEIGHT=0.3 PACE=50 ADAPTIVE=DIFF PRECAL_DIFF UPDATE_FROM=2.0
     298             : ```
     299             : 
     300             : When restarting, the statistics are initialized from the last hills of the hills file of the walker:
     301             : the covariance of the fluctuations is the one of the last hill, and the running average of the CVs is
     302             : estimated from the centers of the last hills, with the weights used by the running average.
     303             : This is also done when the bias is read from a grid (GRID_RFILE), if the hills file is available,
     304             : using only the hills deposited before the current time.
     305             : In this way the hills deposited after a restart have the same width they would have had without the restart,
     306             : apart from the effect of the limits set with SIGMA_MIN and SIGMA_MAX, which are applied to the hills.
     307             : Only the last hills of the walker that belong to the same run and precede the current time are used.
     308             : The hills file does not record how the hills were obtained: if it was written with a different
     309             : SIGMA, or with ADAPTIVE=GEOM, use the DIFF_FROM_SCRATCH flag. With this flag the statistics are
     310             : accumulated again from the restart, as in previous versions; no hill is then added before at least two
     311             : CV values are available.
     312             : 
     313             : ADAPTIVE=DIFF can be used with replica exchange. Since the MD code does not tell PLUMED
     314             : whether an exchange has been accepted, after an exchange attempt the CV values are compared with those
     315             : of the exchange partner: when the exchange is detected as accepted, the running average of the CVs is
     316             : restarted from their new values, while the estimate of their fluctuations is kept.
     317             : Note also that in this case the histogram correction is needed when summing up hills.
     318             : 
     319             : ## Metadynamics with the interval keyword
     320             : 
     321             : When you use the keyword INTERVAL the metadynamics bias force is set equal to zero
     322             : outside of a boundary as discussed in the fifth paper cited below. This feature is useful if, for example, metadynamics is performed on one or more CVs and if one is only interested
     323             : in the free energy for s > boundary.  When you use this option the history dependent potential is still updated in accordance with the formulas above.
     324             : The difference is simply that the metadynamics force is set to zero for s < boundary. This means that Gaussian kernels are added also
     325             : if s < boundary, as the tails of these Gaussian kernels influence VG in the relevant region s > boundary. In this way, the
     326             : force on the system in the region s > boundary comes from both metadynamics and the force field, while in the region
     327             : s < boundary the only force the system experiences is from the forcefield. This approach allows one to obtain a history-dependent bias potential VG that
     328             : fluctuates around a stable estimator, equal to the negative of the free energy far enough from the
     329             : boundaries. Notice that:
     330             : 
     331             : - This method only works for one-dimensional biases;
     332             : - It works both with and without GRID;
     333             : - The interval limit boundary should be set in a region where the derivative of the free energy is not large;
     334             : - If in the region outside the limit boundary the system has a free energy minimum, the INTERVAL keyword should
     335             :   be used together with a [UPPER_WALLS](UPPER_WALLS.md) or [LOWER_WALLS](LOWER_WALLS.md) that act when the system is beyond the boundary as illustrated in the following example.
     336             : 
     337             : ```plumed
     338             : r2g: DISTANCE ATOMS=1,2
     339             : m2g: METAD ARG=r2g HEIGHT=0.1 PACE=500 SIGMA=1.0 INTERVAL=4,8 FILE=H2G GRID_MIN=0 GRID_MAX=20 GRID_BIN=100
     340             : lw: LOWER_WALLS ARG=r2g AT=4 KAPPA=100
     341             : uw: UPPER_WALLS ARG=r2g AT=8 KAPPA=100
     342             : PRINT ARG=r2g,*.bias FILE=colvar STRIDE=10
     343             : ```
     344             : 
     345             : As a final note, since version 2.0.2 the force is set to zero and the bias value to the value at the corresponding boundary
     346             : when the system is outside of the selected interval. This choice allows acceptances for replica exchange methods to be computed correctly.
     347             : 
     348             : ## Multiple walkers metadynamics
     349             : 
     350             : The multiple walkers metadynamics method that is described in the sixth paper cited below can be used by using an input
     351             : like the one shown below:
     352             : 
     353             : ```plumed
     354             : d1: DISTANCE ATOMS=3,5
     355             : restraint: METAD ...
     356             :    ARG=d1 SIGMA=0.05 HEIGHT=0.3 PACE=500
     357             :    WALKERS_N=10
     358             :    WALKERS_ID=3
     359             :    WALKERS_DIR=../
     360             :    WALKERS_RSTRIDE=100
     361             : ...
     362             : ```
     363             : 
     364             : To use this method you need to set the number of walkers (WALKERS_N), the ID of the
     365             : current walker (WALKERS-ID), the directory where the files containing the hills files reside
     366             : (WALKERS_DIR) and the frequency to read the other walkers (WALKERS_RSTRIDE).
     367             : The bias potential experienced by all the walkers is synched between walkers every
     368             : WALKERS_RSTRIDE steps.  In addition, since version 2.2.5, hills files are automatically
     369             : flushed every WALKERS_RSTRIDE steps.
     370             : The grid written by a walker (GRID_WFILE) contains also the hills it has read from the files of the other walkers: their
     371             : number is written in a comment line after the grid.  When restarting from this grid (GRID_RFILE), only the hills of the
     372             : other walkers that are not in it are added.  For a grid written by an older version of PLUMED, the grid is assumed to
     373             : contain the hills of the other walkers up to the time of the last hill in the hills file of this walker.
     374             : With multiple walkers, the hills files and the grid files are read and written without the suffix of the replica
     375             : (e.g. with `--multi`): give a different GRID_WFILE to each walker (e.g. with `@replicas:`).
     376             : 
     377             : ## Reweighting a metadynamics simulation
     378             : 
     379             : The $c(t)$ reweighting factor can also be calculated on the fly using the equations
     380             : presented in the seventh paper in the references section by using the keyword CALC_RCT as illustrated in the example input below:
     381             : 
     382             : ```plumed
     383             : phi: TORSION ATOMS=1,2,3,4
     384             : psi: TORSION ATOMS=5,6,7,8
     385             : 
     386             : m: METAD ...
     387             :  ARG=phi,psi SIGMA=0.20,0.20 HEIGHT=1.20 BIASFACTOR=5 TEMP=300.0 PACE=500
     388             :  GRID_MIN=-pi,-pi GRID_MAX=pi,pi GRID_BIN=150,150
     389             :  CALC_RCT
     390             :  RCT_USTRIDE=10
     391             : ...
     392             : 
     393             : rw: REWEIGHT_METAD TEMP=300
     394             : 
     395             : h: HISTOGRAM ...
     396             :    ARG=phi,psi
     397             :    GRID_MIN=-pi,-pi GRID_MAX=pi,pi GRID_BIN=150,150
     398             :    BANDWIDTH=0.1,0.1
     399             :    LOGWEIGHTS=rw
     400             :    NORMALIZATION=true
     401             : ...
     402             : 
     403             : ff: CONVERT_TO_FES ARG=h TEMP=300
     404             : DUMPGRID ARG=ff FILE=fes.dat
     405             : ```
     406             : 
     407             : 
     408             : The expression used to calculate $c(t)$ follows directly from Eq. 3 in the seventh paper cited below,
     409             : where $F(\vec{s})=-\gamma/(\gamma-1) V(\vec{s})$.
     410             : This gives smoother results than Eqs. 13 and Eqs. 14 in that paper.
     411             : 
     412             : Notice that you can only use this option if you are accumulating the metadynamics bias on a grid.
     413             : $c(t)$ is given by the rct component of the METAD action above while the bias
     414             : normalized by $c(t)$ is given by the rbias component (rbias=bias-rct).  As illustrated above this
     415             : value  can be used to obtain a reweighted histogram.
     416             :

     427             : ## Infrequent metadynamics
     428             : 
     429             : The kinetics of the transitions between basins can also be analyzed on the fly as
     430             : in discussed in the 9th paper cited below. The flag ACCELERATION turn on accumulation of the acceleration
     431             : factor that can then be used to determine the rate as illustrated by the following input.
     432             : 
     433             : ```plumed
     434             : psi: ANGLE ATOMS=7,9,15
     435             : 
     436             : md1: METAD ...
     437             :  ARG=psi SIGMA=0.20
     438             :  HEIGHT=1.20 TEMP=300.0 BIASFACTOR=10
     439             :  PACE=500 GRID_MIN=0 GRID_MAX=pi GRID_BIN=10
     440             :  ACCELERATION
     441             : ...
     442             : 
     443             : PRINT ARG=psi,md1.bias,md1.acc FILE=colvar STRIDE=10
     444             : ```
     445             : 
     446             : This method can be used together with [COMMITTOR](COMMITTOR.md) analysis to stop the simulation when the system get to the target basin.
     447             : It is meant to be used together with Well-Tempered Metadynamics. If restarting from a previous
     448             : metadynamics you need to use the ACCELERATION_RFILE keyword to give the name of the
     449             : data file from which the previous value of the acceleration factor should be read, otherwise the
     450             : calculation of the acceleration factor will be wrong.
     451             : 
     452             : ## Changing the deposition frequency adaptively
     453             : 
     454             : By using the flag FREQUENCY_ADAPTIVE the frequency adaptive scheme introduced in the 10th paper cited below
     455             : is turned on. The frequency for hill addition then changes dynamically based on the acceleration factor
     456             : according to the following equation
     457             : 
     458             : $$
     459             : \tau_{\mathrm{dep}}(t) =
     460             : \min\left[
     461             : \tau_0 \cdot
     462             : \max\left[\frac{\alpha(t)}{\theta},1\right]
     463             : ,\tau_{c}
     464             : \right]
     465             : $$
     466             : 
     467             : where $\tau_0$ is the initial hill addition frequency given by the PACE keyword,
     468             : $\tau_{c}$ is the maximum allowed frequency given by the FA_MAX_PACE keyword,
     469             : $\alpha(t)$ is the instantaneous acceleration factor at time $t$,
     470             : and $\theta$ is a threshold value that acceleration factor has to reach before
     471             : triggering a change in the hill addition frequency given by the FA_MIN_ACCELERATION keyword.
     472             : The frequency for updating the hill addition frequency according to this equation is
     473             : given by the FA_UPDATE_FREQUENCY keyword, by default it is the same as the value given
     474             : in PACE. The hill addition frequency increases monotonically such that if the
     475             : instantaneous acceleration factor is lower than in the previous updating step the
     476             : previous $\tau_{\mathrm{dep}}$ is kept rather than updating it to a lower value.
     477             : The instantaneous hill addition frequency $\tau_{\mathrm{dep}}(t)$ is outputted
     478             : to pace component. Note that if restarting from a previous metadynamics run you need to
     479             : use the ACCELERATION_RFILE keyword to read in the acceleration factors from the
     480             : previous run (the acceleration factor and the pace, if they are in the file), otherwise the hill addition frequency
     481             : will start from the initial frequency.
     482             : 
     483             : ## Targeted metadynamics
     484             : 
     485             : You can also provide a target distribution for your metadynamics simulations by using the keyword TARGET.
     486             : This idea is discussed in the last four papers cited in the references section.
     487             : 
     488             : The TARGET should be a grid containing a free-energy (i.e. the -$k_B$T*log for the desired target distribution).
     489             : Gaussian kernels will then be scaled by a factor
     490             : 
     491             : $$
     492             : e^{\beta(\tilde{F}(s)-\tilde{F}_{max})}
     493             : $$
     494             : 
     495             : Here $\tilde{F}(s)$ is the free energy defined on the grid and $\tilde{F}_{max}$ its maximum value.
     496             : Notice that we here used the maximum value as was done in the penultimate paper in the reference section.
     497             : This choice allows one to avoid the addition of exceedingly large Gaussian kernels. However,
     498             : it can also make the Gaussian too small. You should always choose the HEIGHT parameter carefully
     499             : in this case.
     500             : The grid file should be similar to other PLUMED grid files in that it should contain
     501             : both the target free-energy and its derivatives.
     502             : 
     503             : Notice that if you wish your simulation to converge to the target free energy you should use
     504             : the DAMPFACTOR command to provide a global tempering as is discussed in the last paper from the reference section.
     505             : Alternatively, if you use a BIASFACTOR your simulation will converge to a free
     506             : energy that is a linear combination of the target free energy and of the intrinsic free energy
     507             : determined by the original force field.
     508             : 
     509             : ```plumed
     510             : #SETTINGS INPUTFILES=extras/target.fes
     511             : 
     512             : d1: DISTANCE ATOMS=3,5
     513             : t1: METAD ...
     514             :  ARG=d1 SIGMA=0.05 TAU=200 DAMPFACTOR=100 PACE=250
     515             :  GRID_MIN=1.14 GRID_MAX=1.32 GRID_BIN=6
     516             :  TARGET=extras/target.fes
     517             : ...
     518             : 
     519             : PRINT ARG=d1,t1.bias STRIDE=100 FILE=COLVAR
     520             : ```
     521             : 
     522             : Notice that the BIASFACTOR can also be set equal to 1. In this case one will perform
     523             : unbiased sampling: no bias is applied, and the hills files and the grid contain the estimate of the negative of the
     524             : free energy (the heights of the hills are those of the limit of well-tempered metadynamics for a bias factor going to 1,
     525             : as in [PBMETAD](PBMETAD.md)). Instead of using HEIGHT, one should provide the TAU parameter as illustrated below.
     526             : 
     527             : ```plumed
     528             : d: DISTANCE ATOMS=3,5
     529             : METAD ARG=d SIGMA=0.1 TAU=4.0 TEMP=300 PACE=100 BIASFACTOR=1.0
     530             : ```
     531             : 
     532             : The HILLS file obtained will still work with `plumed sum_hills` so as to plot a free-energy.
     533             : The case where this makes sense is probably that of RECT simulations.
     534             : 
     535             : Regarding RECT simulations, you can also use the RECT keyword so as to avoid using multiple input files.
     536             : For instance, a single input file will be
     537             : 
     538             : ```plumed
     539             : d: DISTANCE ATOMS=3,5
     540             : METAD ARG=d SIGMA=0.1 TAU=4.0 TEMP=300 PACE=100 RECT=1.0,1.5,2.0,3.0
     541             : ```
     542             : 
     543             : The number of elements in the RECT array should be equal to the number of replicas.
     544             : 
     545             : */
