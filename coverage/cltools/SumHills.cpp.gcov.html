      41             : //+PLUMEDOC TOOLS sum_hills
      42             : /*
      43             : sum_hills is a tool that sums the Gaussians in a hills file and writes the resulting free energy on a grid.
      44             : 
      45             : This tool is most frequently used after a [METAD](METAD.md) simulation to sum all the Gaussians in the hills file
      46             : and output the free energy surface:
      47             : 
      48             : ```plumed
      49             : plumed sum_hills --hills PATHTOMYHILLSFILE
      50             : ```
      51             : 
      52             : The default name for the output file is `fes.dat`. It contains, for each point of the grid, the free energy
      53             : and its derivatives with respect to the variables. The free energy is minus the sum of the Gaussians: with
      54             : well-tempered metadynamics the heights written in the hills file are already scaled by $\gamma/(\gamma-1)$
      55             : (where $\gamma$ is the bias factor), so that their sum is directly the estimate of minus the free energy.
      56             : As always, the free energy is defined up to an additive constant; use `--mintozero` to shift its minimum to zero.
      57             : 
      58             : sum_hills automatically detects the variables in the hills file and their periodicity. A column `X` of the file
      59             : is a variable if the file also contains its width (`sigma_X`, or `sigma_X_X` for multivariate Gaussians),
      60             : whatever the name of the variable. If you used flexible hills (multivariate Gaussian kernels), sum_hills
      61             : understands it from the hills file.
      62             : 
      63             : ## Choosing the grid
      64             : 
      65             : By default the grid is chosen so as to contain all the Gaussians, with a spacing of about a third of the smallest width.
      66             : You can instead choose the number of bins:
      67             : 
      68             : ```plumed
      69             : plumed sum_hills --bin 99,99 --hills PATHTOMYHILLSFILE
      70             : ```
      71             : 
      72             : In the command above the minimum and maximum of the grid are still detected for you. If you want to set them yourself
      73             : you can do so as shown below:
      74             : 
      75             : ```plumed
      76             : plumed sum_hills --bin 99,99 --min -pi,-pi --max pi,pi --hills PATHTOMYHILLSFILE
      77             : ```
      78             : 
      79             : You can of course use numbers instead of -pi/pi. `--min` and `--max` must be given together. Instead of the number of bins
      80             : you can give the grid spacing with `--spacing`, with or without `--min` and `--max`. If you give both `--bin` and `--spacing`,
      81             : the larger number of bins is used for each variable.
      82             : 
      83             : ## Multiple files and multiple walkers
      84             : 
      85             : sum_hills can also accept multiple files:
      86             : 
      87             : ```plumed
      88             : plumed sum_hills --hills PATHTOMYHILLSFILE1,PATHTOMYHILLSFILE2,PATHTOMYHILLSFILE3
      89             : ```
      90             : 
      91             : The files are integrated one after the other. This does not change the final free energy, but when
      92             : you use `--stride` (see below) with the hills files of multiple walkers the intermediate free energies would
      93             : not follow the simulation. With `--sort time` the hills of all the files are merged in order of their time
      94             : (hills with the same time are taken in the order of the files), so that each intermediate free energy
      95             : contains the hills deposited by all the walkers up to a given time:
      96             : 
      97             : ```plumed
      98             : plumed sum_hills --hills HILLS.0,HILLS.1,HILLS.2 --sort time --stride 300
      99             : ```
     100             : 
     101             : With `--sort clock` the hills are merged in order of the `clock` field (the wall-clock time at which they were
     102             : deposited, written with multiple walkers), which is more appropriate when the walkers run at different speeds.
     103             : Each file should be ordered by the chosen field.
     104             : 
     105             : ## Integrating out variables
     106             : 
     107             : If you want to integrate out some variables from your free energy surface you can use `--idw`:
     108             : 
     109             : ```plumed
     110             : plumed sum_hills --hills PATHTOMYHILLSFILE --idw t1 --kt 0.6
     111             : ```
     112             : 
     113             : With `--idw` you list the variables that you want in the output free energy surface.
     114             : All the other variables in the hills file are integrated out, i.e.
     115             : $F(s_1) = -k_BT \log \sum_{s_2} e^{-F(s_1,s_2)/k_BT}$, where the sum runs over the points of the grid.
     116             : `--kt` is the temperature of the system in energy units: be consistent with the units of your hills file,
     117             : since plumed will not check this for you. If you need more variables you can list them separated by commas:
     118             : 
     119             : ```plumed
     120             : plumed sum_hills --hills PATHTOMYHILLSFILE --idw t1,t2 --kt 0.6
     121             : ```
     122             : 
     123             : ## Following the convergence
     124             : 
     125             : With `--stride` you can write the free energy after each bunch of hills (the stride is a number of hills):
     126             : 
     127             : ```plumed
     128             : plumed sum_hills --stride 300 --hills PATHTOMYHILLSFILE
     129             : ```
     130             : 
     131             : The output files are then called `fes_0.dat`, `fes_1.dat`, etc. (see below), and the last one contains all the hills.
     132             : 
     133             : With `--nohistory` each output contains only the hills of its own block of hills, instead of all the hills up to that point:
     134             : 
     135             : ```plumed
     136             : plumed sum_hills --stride 300 --hills PATHTOMYHILLSFILE --nohistory
     137             : ```
     138             : 
     139             : In this way you can monitor the bias deposited in blocks of time as a metadynamics simulation goes on:
     140             : when the bias deposited in a block is constant over the whole domain, the simulation can be considered to be at convergence.
     141             : 
     142             : To check the convergence you can also follow the free-energy difference between basins as the
     143             : simulation goes on. With `--basins` you can define two or more basins as boxes, each given by the minimum and
     144             : the maximum of each variable of the output, with the basins separated by colons. Along a periodic variable a
     145             : basin can cross the boundary if its minimum is larger than its maximum. For example
     146             : 
     147             : ```plumed
     148             : plumed sum_hills --hills PATHTOMYHILLSFILE --stride 500 --kt 2.5 --basins -pi,0,-pi,pi:0,pi,-pi,pi
     149             : ```
     150             : 
     151             : writes, at each output, the time of the last hill read, the number of hills, and the free energy of each basin
     152             : relative to the first one, computed as $-k_BT \log \sum_{s\in\mathrm{basin}} e^{-F(s)/k_BT}$ over the points of
     153             : the grid, in the file `basins.dat` (the name can be set with `--outbasins`). With `--idw` the basins are defined on
     154             : the projected variables. With `--histo` (see below) the same is done for the free energy from the histogram, in the file `histo_basins.dat`.
     155             : A plateau of these differences is a necessary (not sufficient) indication of convergence.
     156             : 
     157             : ## Time average of the bias
     158             : 
     159             : With standard (not well-tempered) metadynamics the bias does not converge but fluctuates around the free energy.
     160             : A better estimate is the time average of the bias after an initial transient, which you can obtain with `--average`:
     161             : 
     162             : ```plumed
     163             : plumed sum_hills --hills PATHTOMYHILLSFILE --average 1000
     164             : ```
     165             : 
     166             : computes the average of the bias between time 1000 (in the units of the time column of the hills file) and the time of
     167             : the last hill. This is done by scaling the height of each hill deposited at time $t$ after 1000 by $(t_1-t)/(t_1-1000)$, where
     168             : $t_1$ is the final time. You can also give the final time explicitly, e.g. `--average 1000,5000`: hills deposited after
     169             : 5000 are ignored. The same average is useful for well-tempered metadynamics, where it reduces the fluctuations of the
     170             : estimate of the free energy. Combined with `--stride`, each output is the average from the initial time up to the last hill read.
     171             : This is the same average computed by the function `hills_time_average` of the plumed python module.
     172             : 
     173             : ## Bias instead of free energy
     174             : 
     175             : If you have run well-tempered metadynamics you can also ask sum_hills to output the negative bias, $-V(s)=(\gamma-1)/\gamma\, F(s)$,
     176             : instead of the free energy by using `--negbias`:
     177             : 
     178             : ```plumed
     179             : plumed sum_hills --negbias --hills PATHTOMYHILLSFILE
     180             : ```
     181             : 
     182             : Here the default output file name is `negativebias.dat`. If the simulation was not well tempered the bias is minus the free energy,
     183             : and the output is the same as without `--negbias`.
     184             : 
     185             : ## Histograms
     186             : 
     187             : From time to time you might need to use a hills or a colvar file as a set of points from which you want to build
     188             : a free energy as $-k_BT \log P(s)$. You can do this with `--histo`:
     189             : 
     190             : ```plumed
     191             : plumed sum_hills --histo PATHTOMYCOLVARORHILLSFILE --sigma 0.2,0.2 --kt 0.6
     192             : ```
     193             : 
     194             : The histogram is computed with Gaussian kernels whose widths are given with `--sigma`, one for each variable,
     195             : so it is a continuous histogram, and `--kt` is needed to convert it into a free energy. The default output file is `histo.dat`.
     196             : With a hills file the variables are those of the hills; with a colvar file all the columns but time are variables, so you
     197             : will usually select some of them with `--idw` (and give one width for each of them).
     198             : Multiple input files can be given, separated by commas.
     199             : 
     200             : All the points have the same weight: the result is the distribution sampled by the simulation, which is the
     201             : free energy only if the simulation was not biased. **sum_hills does not reweight the points.** To compute a free
     202             : energy from a biased simulation (e.g. from the COLVAR file of a metadynamics simulation) use [driver](driver.md) with
     203             : [READ](READ.md), [REWEIGHT_BIAS](REWEIGHT_BIAS.md) (or [REWEIGHT_METAD](REWEIGHT_METAD.md)), [HISTOGRAM](HISTOGRAM.md)
     204             : and [CONVERT_TO_FES](CONVERT_TO_FES.md), for example
     205             : 
     206             : ```plumed
     207             : #SETTINGS INPUTFILES=regtest/basic/rt-fametad-2-restart/COLVAR
     208             : s: READ FILE=regtest/basic/rt-fametad-2-restart/COLVAR VALUES=sum_abs IGNORE_TIME IGNORE_FORCES
     209             : metad: READ FILE=regtest/basic/rt-fametad-2-restart/COLVAR VALUES=MetaD.bias IGNORE_TIME IGNORE_FORCES
     210             : w: REWEIGHT_BIAS TEMP=300 ARG=metad.bias
     211             : hh: HISTOGRAM ARG=s GRID_MIN=0 GRID_MAX=1 GRID_BIN=100 BANDWIDTH=0.02 LOGWEIGHTS=w NORMALIZATION=true
     212             : ff: CONVERT_TO_FES ARG=hh TEMP=300
     213             : DUMPGRID ARG=ff FILE=fes.dat
     214             : ```
     215             : 
     216             : run with `plumed driver --plumed plumed.dat --noatoms`. With well-tempered metadynamics the bias changes with time:
     217             : use the `rbias` component of [METAD](METAD.md) (with `CALC_RCT`) instead of the bias, or [REWEIGHT_METAD](REWEIGHT_METAD.md).
     218             : Block averages, which give the statistical error of the free energy, are discussed in the documentation of [HISTOGRAM](HISTOGRAM.md)
     219             : and in the tutorial linked there.
     220             : 
     221             : You can compute the free energy from the hills and the histogram at the same time, e.g. from the same file:
     222             : 
     223             : ```plumed
     224             : plumed sum_hills --hills PATHTOMYHILLSFILE --histo PATHTOMYHILLSFILE --sigma 0.2,0.2 --kt 0.6
     225             : ```
     226             : 
     227             : `--nohistory` and `--stride` can also be used with `--histo`, to compute the histogram in blocks of points:
     228             : 
     229             : ```plumed
     230             : plumed sum_hills --histo PATHTOMYCOLVARORHILLSFILE --sigma 0.2,0.2 --kt 0.6 --stride 1000 --nohistory
     231             : ```
     232             : 
     233             : ## Output
     234             : 
     235             : The output format can be controlled by using the `--fmt` option as shown below
     236             : 
     237             : ```plumed
     238             : plumed sum_hills --hills PATHTOMYHILLSFILE --fmt %8.3f
     239             : ```
     240             : 
     241             : where here we chose a float with length of 8 and 3 digits.
     242             : 
     243             : The output file can be named in an arbitrary way by using the `--outfile` option as shown below:
     244             : 
     245             : ```plumed
     246             : plumed sum_hills --hills PATHTOMYHILLSFILE --outfile myfes.dat
     247             : ```
     248             : 
     249             : This command produces a file `myfes.dat` which contains the free energy surface.
     250             : 
     251             : If you use `--stride`, the name specified with `--outfile` is the prefix of the files, so this command:
     252             : 
     253             : ```plumed
     254             : plumed sum_hills --hills PATHTOMYHILLSFILE --outfile myfes_ --stride 100
     255             : ```
     256             : 
     257             : produces output files called `myfes_0.dat`, `myfes_1.dat`, `myfes_2.dat` etc.
     258             : 
     259             : The same is true for the output of the histogram, which is named with `--outhisto`. So this example
     260             : 
     261             : ```plumed
     262             : plumed sum_hills --histo HILLS --kt 2.5 --sigma 0.01 --outhisto myhisto.dat
     263             : ```
     264             : 
     265             : produces a file `myhisto.dat`, while this input
     266             : 
     267             : ```plumed
     268             : plumed sum_hills --histo HILLS --kt 2.5 --sigma 0.01 --outhisto myhisto_ --stride 100
     269             : ```
     270             : 
     271             : produces output files called `myhisto_0.dat`, `myhisto_1.dat`, `myhisto_2.dat` etc.
     272             : 
     273             : */
