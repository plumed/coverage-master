      32             : //+PLUMEDOC GRIDCALC ACCUMULATE
      33             : /*
      34             : Sum the elements of this value over the course of the trajectory
      35             : 
      36             : This action is used to sum the outputs from another action over the course of the trajectory.  This is useful
      37             : if you want to calculate the average value that a CV took over the course of a simulation.  As an example, the following
      38             : input can be used to calculate the average distance between atom 1 and atom 2.
      39             : 
      40             : ```plumed
      41             : c: CONSTANT VALUE=1
      42             : d: DISTANCE ATOMS=1,2
      43             : # This adds together the value of the distance on every step
      44             : s: ACCUMULATE ARG=d STRIDE=1
      45             : # This adds one every time we add a new distance to the value s
      46             : n: ACCUMULATE ARG=c STRIDE=1
      47             : # This is thus the average distance
      48             : a: CUSTOM ARG=s,n FUNC=x/y PERIODIC=NO
      49             : # This prints out the average over the whole trajectory (STRIDE=0 means print at end only)
      50             : PRINT ARG=a FILE=average.dat STRIDE=0
      51             : ```
      52             : 
      53             : You can use this action for block averaging by using the `CLEAR` keyword as shown below:
      54             : 
      55             : ```plumed
      56             : c: CONSTANT VALUE=1
      57             : d: DISTANCE ATOMS=1,2
      58             : # This adds together the value of the distance on every step
      59             : s: ACCUMULATE ARG=d STRIDE=1 CLEAR=1000
      60             : # This adds one every time we add a new distance to the value s
      61             : n: ACCUMULATE ARG=c STRIDE=1 CLEAR=1000
      62             : # This is thus the average distance
      63             : a: CUSTOM ARG=s,n FUNC=x/y PERIODIC=NO
      64             : # This prints out the average over the whole trajectory (STRIDE=0 means print at end only)
      65             : PRINT ARG=a FILE=average.dat STRIDE=1000
      66             : ```
      67             : 
      68             : The instructions `CLEAR=1000` in the above input tells PLUMED to set the values `s` and `n` back to
      69             : zero after 1000 new steps have been performed. The PRINT action will thus print a block average that
      70             : is taken from the first 1000 steps of the trajectory, a second block average from the second 1000 steps
      71             : of the trajectory and so on.  Notice that you can achieve a similar effect using UPDATE_FROM and UPDATE_UNTIL as
      72             : shown below:
      73             : 
      74             : ```plumed
      75             : c: CONSTANT VALUE=1
      76             : d: DISTANCE ATOMS=1,2
      77             : s1: ACCUMULATE ARG=d STRIDE=1 UPDATE_UNTIL=1000
      78             : n1: ACCUMULATE ARG=c STRIDE=1 UPDATE_UNTIL=1000
      79             : a1: CUSTOM ARG=s1,n1 FUNC=x/y PERIODIC=NO
      80             : s2: ACCUMULATE ARG=d STRIDE=1 UPDATE_FROM=1000
      81             : n2: ACCUMULATE ARG=c STRIDE=1 UPDATE_FROM=1000
      82             : a2: CUSTOM ARG=s2,n2 FUNC=x/y PERIODIC=NO
      83             : diff: CUSTOM ARG=a1,a2 FUNC=x-y PERIODIC=NO
      84             : PRINT ARG=a1,a2,diff FILE=colver STRIDE=2000
      85             : ```
      86             : 
      87             : This output calculates the average distance for the first 1000 frames of the trajectory and for the second 1000 frames of the trajectory.
      88             : These two averages are then output to a file called colvar as well as the difference between them.
      89             : 
      90             : ## Estimating histograms
      91             : 
      92             : We can also use this action to construct histograms. The example below shows how you can estimate the
      93             : distribution of distances between atoms 1 and 2 that are sampled over the course of the trajectory.
      94             : 
      95             : ```plumed
      96             : c: CONSTANT VALUE=1
      97             : d: DISTANCE ATOMS=1,2
      98             : # Construct the instantaneous histogram from the instantaneous value of the distance
      99             : kde: KDE ARG=d BANDWIDTH=0.05 GRID_SPACING=0.01
     100             : # Now add together all the instantaneous histograms
     101             : hist: ACCUMULATE ARG=kde STRIDE=1
     102             : # And normalise the histogram
     103             : n: ACCUMULATE ARG=c STRIDE=1
     104             : a: CUSTOM ARG=hist,n FUNC=x/y PERIODIC=NO
     105             : # And print out the final histogram
     106             : DUMPGRID ARG=a FILE=histo.grid
     107             : ```
     108             : 
     109             : At first glance the fact that we use a [KDE](KDE.md) action to construct an instantaneous histogram from a single
     110             : distance may appear odd.  The reason for doing this, however, is to introduce a clear distinction between
     111             : the syntaxes that are used for spatial and temporal averaging.  To see what I mean consider the following input:
     112             : 
     113             : 
     114             : ```plumed
     115             : c: CONSTANT VALUE=5
     116             : d: DISTANCE ATOMS1=1,2 ATOMS2=3,4 ATOMS3=5,6 ATOMS4=7,8 ATOMS5=9,10
     117             : # Construct the instantaneous histogram from the instantaneous value of the distance
     118             : kde: KDE ARG=d BANDWIDTH=0.05 GRID_SPACING=0.01
     119             : # Now add together all the instantaneous histograms
     120             : hist: ACCUMULATE ARG=kde STRIDE=1
     121             : # And normalise the histogram
     122             : n: ACCUMULATE ARG=c STRIDE=1
     123             : a: CUSTOM ARG=hist,n FUNC=x/y PERIODIC=NO
     124             : # And print out the final histogram
     125             : DUMPGRID ARG=a FILE=histo.grid
     126             : ```
     127             : 
     128             : This input computes 5 distances. Kernels corresponding to all five of these distances are added to the instantaneous
     129             : histogram that is constructed using the [KDE](KDE.md) action.  When we call the accumulate action here we are thus
     130             : not simply adding a single kernel to the accumulated grid when we add the elements from `kde`.
     131             : 
     132             : ## Restart
     133             : 
     134             : With [CHECKPOINT](CHECKPOINT.md) the accumulated data (scalar or grid) is stored in the checkpoint, so that sums, averages and histograms continue exactly after a restart.
     135             : 
     136             : */
