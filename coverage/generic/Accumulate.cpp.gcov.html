      30             : //+PLUMEDOC GRIDCALC ACCUMULATE
      31             : /*
      32             : Sum the elements of this value over the course of the trajectory
      33             : 
      34             : This action is used to sum the outputs from another action over the course of the trajectory.  This is useful
      35             : if you want to calculate the average value that a CV took over the course of a simulation.  As an example, the following
      36             : input can be used to calculate the average distance between atom 1 and atom 2.
      37             : 
      38             : ```plumed
      39             : c: CONSTANT VALUE=1
      40             : d: DISTANCE ATOMS=1,2
      41             : # This adds together the value of the distance on every step
      42             : s: ACCUMULATE ARG=d STRIDE=1
      43             : # This adds one every time we add a new distance to the value s
      44             : n: ACCUMULATE ARG=c STRIDE=1
      45             : # This is thus the average distance
      46             : a: CUSTOM ARG=s,n FUNC=x/y PERIODIC=NO
      47             : # This prints out the average over the whole trajectory (STRIDE=0 means print at end only)
      48             : PRINT ARG=a FILE=average.dat STRIDE=0
      49             : ```
      50             : 
      51             : You can use this action for block averaging by using the `CLEAR` keyword as shown below:
      52             : 
      53             : ```plumed
      54             : c: CONSTANT VALUE=1
      55             : d: DISTANCE ATOMS=1,2
      56             : # This adds together the value of the distance on every step
      57             : s: ACCUMULATE ARG=d STRIDE=1 CLEAR=1000
      58             : # This adds one every time we add a new distance to the value s
      59             : n: ACCUMULATE ARG=c STRIDE=1 CLEAR=1000
      60             : # This is thus the average distance
      61             : a: CUSTOM ARG=s,n FUNC=x/y PERIODIC=NO
      62             : # This prints out the average over the whole trajectory (STRIDE=0 means print at end only)
      63             : PRINT ARG=a FILE=average.dat STRIDE=1000
      64             : ```
      65             : 
      66             : The instructions `CLEAR=1000` in the above input tells PLUMED to set the values `s` and `n` back to
      67             : zero after 1000 new steps have been performed. The PRINT action will thus print a block average that
      68             : is taken from the first 1000 steps of the trajectory, a second block average from the second 1000 steps
      69             : of the trajectory and so on.  Notice that you can achieve a similar effect using UPDATE_FROM and UPDATE_UNTIL as
      70             : shown below:
      71             : 
      72             : ```plumed
      73             : c: CONSTANT VALUE=1
      74             : d: DISTANCE ATOMS=1,2
      75             : s1: ACCUMULATE ARG=d STRIDE=1 UPDATE_UNTIL=1000
      76             : n1: ACCUMULATE ARG=c STRIDE=1 UPDATE_UNTIL=1000
      77             : a1: CUSTOM ARG=s1,n1 FUNC=x/y PERIODIC=NO
      78             : s2: ACCUMULATE ARG=d STRIDE=1 UPDATE_FROM=1000
      79             : n2: ACCUMULATE ARG=c STRIDE=1 UPDATE_FROM=1000
      80             : a2: CUSTOM ARG=s2,n2 FUNC=x/y PERIODIC=NO
      81             : diff: CUSTOM ARG=a1,a2 FUNC=x-y PERIODIC=NO
      82             : PRINT ARG=a1,a2,diff FILE=colver STRIDE=2000
      83             : ```
      84             : 
      85             : This output calculates the average distance for the first 1000 frames of the trajectory and for the second 1000 frames of the trajectory.
      86             : These two averages are then output to a file called colvar as well as the difference between them.
      87             : 
      88             : ## Estimating histograms
      89             : 
      90             : We can also use this action to construct histograms. The example below shows how you can estimate the
      91             : distribution of distances between atoms 1 and 2 that are sampled over the course of the trajectory.
      92             : 
      93             : ```plumed
      94             : c: CONSTANT VALUE=1
      95             : d: DISTANCE ATOMS=1,2
      96             : # Construct the instantaneous histogram from the instantaneous value of the distance
      97             : kde: KDE ARG=d BANDWIDTH=0.05 GRID_MIN=0 GRID_MAX=5 GRID_BIN=250
      98             : # Now add together all the instantaneous histograms
      99             : hist: ACCUMULATE ARG=kde STRIDE=1
     100             : # And normalise the histogram
     101             : n: ACCUMULATE ARG=c STRIDE=1
     102             : a: CUSTOM ARG=hist,n FUNC=x/y PERIODIC=NO
     103             : # And print out the final histogram
     104             : DUMPGRID ARG=a FILE=histo.grid
     105             : ```
     106             : 
     107             : At first glance the fact that we use a [KDE](KDE.md) action to construct an instantaneous histogram from a single
     108             : distance may appear odd.  The reason for doing this, however, is to introduce a clear distinction between
     109             : the syntaxes that are used for spatial and temporal averaging.  To see what I mean consider the following input:
     110             : 
     111             : 
     112             : ```plumed
     113             : c: CONSTANT VALUE=5
     114             : d: DISTANCE ATOMS1=1,2 ATOMS2=3,4 ATOMS3=5,6 ATOMS4=7,8 ATOMS5=9,10
     115             : # Construct the instantaneous histogram from the instantaneous value of the distance
     116             : kde: KDE ARG=d BANDWIDTH=0.05 GRID_MIN=0 GRID_MAX=5 GRID_BIN=250
     117             : # Now add together all the instantaneous histograms
     118             : hist: ACCUMULATE ARG=kde STRIDE=1
     119             : # And normalise the histogram
     120             : n: ACCUMULATE ARG=c STRIDE=1
     121             : a: CUSTOM ARG=hist,n FUNC=x/y PERIODIC=NO
     122             : # And print out the final histogram
     123             : DUMPGRID ARG=a FILE=histo.grid
     124             : ```
     125             : 
     126             : This input computes 5 distances. Kernels corresponding to all five of these distances are added to the instantaneous
     127             : histogram that is constructed using the [KDE](KDE.md) action.  When we call the accumulate action here we are thus
     128             : not simply adding a single kernel to the accumulated grid when we add the elements from `kde`.
     129             : 
     130             : ## Restart
     131             : 
     132             : With [CHECKPOINT](CHECKPOINT.md) the accumulated data (scalar or grid) is stored in the checkpoint, so that sums, averages and histograms continue exactly after a restart.
     133             : 
     134             : */
