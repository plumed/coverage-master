      31             : /*
      32             : Collect data from the trajectory for later analysis
      33             : 
      34             : The way this command can be used is illustrated by the following example:
      35             : 
      36             : ```plumed
      37             : d: DISTANCE ATOMS=1,2
      38             : c: COLLECT ARG=d STRIDE=1
      39             : DUMPVECTOR ARG=c FILE=timeseries
      40             : ```
      41             : 
      42             : The COLLECT command in the input above stores the time series of distances over the whole
      43             : trajectory. The STRIDE keyword controls how frequently data is stored and the [DUMPVECTOR](DUMPVECTOR.md)
      44             : command then outputs the full time series of `d` values at the end of the calculation.
      45             : 
      46             : The above example is not particularly useful as you can achieve the same result by using simply
      47             : a DISTANCE command and the [PRINT](PRINT.md) command.  The COLLECT command is useful if you want
      48             : use the whole trajectory to perform a analysis such as  dimensionality reduction (see [dimred](module_dimred.md)).
      49             : The shortcut command [COLLECT_FRAMES](COLLECT_FRAMES.md) uses this action heavily and allows one to easily
      50             : deal with the fact that COLLECT can only collect the time series for one PLUMED Value at a time.
      51             : 
      52             : ## Collecting a part of the trajectory
      53             : 
      54             : You can use the CLEAR keyword to collect a subset of the trajectory as illustrated below:
      55             : 
      56             : ```plumed
      57             : d: DISTANCE ATOMS=1,2
      58             : c: COLLECT ARG=d STRIDE=1 CLEAR=1000
      59             : DUMPVECTOR ARG=c FILE=timeseries STRIDE=1000
      60             : ```
      61             : 
      62             : This outputs files contain from this input contain 1000-frame blocks of the trajectory for the distance between atom 1 and 2.
      63             : This type of input might proove useful if you wish to perform separate analysis on different parts of the trajectory for
      64             : later comparison.
      65             : 
      66             : An alternative way to collect part of the trajectry is to use the UPDATE_FROM and UPDATE_UNTIL arguments as illustrated in the
      67             : example shown below:
      68             : 
      69             : ```plumed
      70             : d: DISTANCE ATOMS=1,2
      71             : c: COLLECT ARG=d STRIDE=1 UPDATE_FROM=100 UPDATE_UNTIL=200
      72             : DUMPVECTOR ARG=c FILE=timeseries
      73             : ```
      74             : 
      75             : In this input the COLLECT action only starts collecting the data on step 100 so the first 100 values of the trajectory are discarded.
      76             : The COLLECT action then stops collecting data on step 200. These 200 stored distances are then output at the end of the simulation
      77             : even if the trajectory contains more than 200 frames.
      78             : 
      79             : ## Analysing the remaining data in the trajectory
      80             : 
      81             : Suppose that you use the first input in the previous section to analyse a 3500-frame trajectory. Three files will be output that contain
      82             : the distances between atom 1 and 2 for the first, second and third 1000-frame blocks of the trajectory. However, the distances between the atoms in the
      83             : final 500 frames are not output anywhere.  If you want to output these last 500 distances as well you can use an input similar to the one shown below:
      84             : 
      85             : ```plumed
      86             : d: DISTANCE ATOMS=1,2
      87             : c: COLLECT ARG=d STRIDE=1 CLEAR=1000 ANALYZED_AT_END
      88             : DUMPVECTOR ARG=c FILE=timeseries STRIDE=1000 DO_AFTER_FINAL_STEP
      89             : ```
      90             : 
      91             : Now four files will be output from that 3500-frame trajectory. However, the last of these files only contains 500 distances.
      92             : 
      93             : ## Collecting vectors
      94             : 
      95             : You can use the collect command even if the input value has a rank that is greater than zero.  For example, the following
      96             : input collects vectors of distances from the trajectory:
      97             : 
      98             : ```plumed
      99             : d: DISTANCE ATOMS1=1,2 ATOMS2=3,4 ATOMS3=5,6 ATOMS4=7,8
     100             : c: COLLECT ARG=d TYPE=vector STRIDE=1 CLEAR=100
     101             : DUMPVECTOR ARG=c FILE=timeseries STRIDE=100
     102             : ```
     103             : 
     104             : Notice that if the input to the collect action is a value with rank>0 you __must__ use the TYPE keyword to specify whether
     105             : the output Value is a vector or matrix.  In the above input we are storing a vector so the DUMPVECTOR command outputs
     106             : a list of 400 distances - 4 distances for each frame.  The assumption in the input above is that the four distances that have
     107             : been computed by the DISTANCES command are indistinguishable.
     108             : 
     109             : By using the following input we can ensure the four distances are treated as distinguishable when we do any analysis:
     110             : 
     111             : ```plumed
     112             : d: DISTANCE ATOMS1=1,2 ATOMS2=3,4 ATOMS3=5,6 ATOMS4=7,8
     113             : c: COLLECT ARG=d TYPE=matrix STRIDE=1 CLEAR=100
     114             : DUMPVECTOR ARG=c FILE=timeseries STRIDE=100
     115             : ```
     116             : 
     117             : The value `c` is now a $100\times 4$ matrix.  Furthermore, when we use DUMPVECTOR to output the output file will contain
     118             : four columns of data.
     119             : 
     120             : ## Collecting matrices
     121             : 
     122             : You can also use this action to collect a matrix as illustrated by the following example:
     123             : 
     124             : ```plumed
     125             : d: DISTANCE_MATRIX GROUPA=1,2 GROUPB=3,4,5
     126             : c: COLLECT ARG=d TYPE=vector STRIDE=1 CLEAR=100
     127             : DUMPVECTOR ARG=c FILE=timeseries STRIDE=100
     128             : ```
     129             : 
     130             : The value `c` here is a vector with 600 elements as the input matrix is converted to a vector. These vectors are then stored in
     131             : one contiguous object.
     132             : 
     133             : If by contrast we use `TYPE=matrix` as shown below:
     134             : 
     135             : ```plumed
     136             : d: DISTANCE_MATRIX GROUPA=1,2 GROUPB=3,4,5
     137             : c: COLLECT ARG=d TYPE=matrix STRIDE=1 CLEAR=100
     138             : DUMPVECTOR ARG=c FILE=timeseries STRIDE=100
     139             : ```
     140             : 
     141             : A $100 \times 6$ matrix is stored.  Each row of this matrix contains a vectorized version of the input matrix.
     142             : There is currently no way to store the collected data in a way that recognises that each of the input PLUMED Value
     143             : was a matrix. You also cannot use this action to store functions evaluated on a grid.
     144             : 
     145             : ## Restart
     146             : 
     147             : With [CHECKPOINT](CHECKPOINT.md) the collected data is stored in the checkpoint, so that the time series continues exactly after a restart.
     148             : 
     149             : */
