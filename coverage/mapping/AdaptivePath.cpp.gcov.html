      30             : /*
      31             : Compute path collective variables that adapt to the lowest free energy path connecting states A and B.
      32             : 
      33             : This shortcut can be used to implement the method discussed in the second paper cited below. This method allows you to
      34             : run a simulation with [PATH](PATH.md) collective variables that forces the system to transition between state A and state B.
      35             : If you run with ADAPTIVE_PATH rather than [PATH](PATH.md) the CV adapts as the simulation progresses and should find the
      36             : lowest free energy path that connects the two states.
      37             : 
      38             : The Path Collective Variables developed by Branduardi that are described in the first paper cited below allow one
      39             : to compute the progress along a high-dimensional path and the distance from the high-dimensional
      40             : path.  Instad of computing progress along the path ($s$) using Branduardi's method we use the expressions that are used in
      41             : [GEOMETRIC_PATH](GEOMETRIC_PATH.md) and that are introduced in the second paper that is cited below.  The progress along the path is is thus computed using:
      42             : 
      43             : $$
      44             : s = i_2 + \textrm{sign}(i_2-i_1) \frac{ \sqrt{( \mathbf{v}_1\cdot\mathbf{v}_2 )^2 - |\mathbf{v}_3|^2(|\mathbf{v}_1|^2 - |\mathbf{v}_2|^2) } }{2|\mathbf{v}_3|^2} - \frac{\mathbf{v}_1\cdot\mathbf{v}_3 - |\mathbf{v}_3|^2}{2|\mathbf{v}_3|^2}
      45             : $$
      46             : 
      47             : In this expression $\mathbf{v}_1$ and $\mathbf{v}_3$ are the vectors connecting the current position to the closest and second closest node of the path,
      48             : respectfully and $i_1$ and $i_2$ are the projections of the closest and second closest frames of the path. $\mathbf{v}_2$, meanwhile, is the
      49             : vector connecting the closest frame to the second closest frame.  The distance from the path, $z$ is calculated using:
      50             : 
      51             : $$
      52             : z = \sqrt{ \left[ |\mathbf{v}_1|^2 - |\mathbf{v}_2| \left( \frac{ \sqrt{( \mathbf{v}_1\cdot\mathbf{v}_2 )^2 - |\mathbf{v}_3|^2(|\mathbf{v}_1|^2 - |\mathbf{v}_2|^2) } }{2|\mathbf{v}_3|^2} - \frac{\mathbf{v}_1\cdot\mathbf{v}_3 - |\mathbf{v}_3|^2}{2|\mathbf{v}_3|^2} \right) \right]^2 }
      53             : $$
      54             : 
      55             : Notice that these are the definitions of $s$ and $z$ from the [GEOMETRIC_PATH](GEOMETRIC_PATH.md).  The reason for this is that
      56             : the adaptive path method implemented in this action was inspired by the work of Diaz and Ensing that was introduced in the second paper cited below.
      57             : To learn more about how the path is adapted we strongly recommend reading this paper.
      58             : 
      59             : The example input below shows how to use the adaptive path.
      60             : 
      61             : ```plumed
      62             : #SETTINGS INPUTFILES=regtest/mapping/rt-adapt/mypath.pdb
      63             : d1: DISTANCE ATOMS=1,2 COMPONENTS
      64             : pp: ADAPTIVE_PATH ...
      65             :    ARG=d1.x,d1.y UPDATE=50 FIXED=5,15
      66             :    WFILE=out-path.pdb WSTRIDE=50
      67             :    REFERENCE=regtest/mapping/rt-adapt/mypath.pdb
      68             :    PROPERTY=path
      69             : ...
      70             : PRINT ARG=d1.x,d1.y,pp.* FILE=colvar
      71             : ```
      72             : 
      73             : The curved path here is defined using a series of points in a two dimensional space.  Furthermore, the coordinates that these points should be projected at
      74             : on the low dimensional path (the $i$ values in the equation for $s$ above) are specified in the `path` property of the input pdb file.
      75             : 
      76             : If you expand the shortcuts in the input above you can see how
      77             : we use a [GEOMETRIC_PATH](GEOMETRIC_PATH.md) shortcut to calculate our position along the path and distance from the path.  In addition, we also collect
      78             : information on the average displacement from the path using an [AVERAGE_PATH_DISPLACEMENT](AVERAGE_PATH_DISPLACEMENT.md) so that we can update the path every step.
      79             : During these update steps the reference points on the path are shifted by the values that are stored in the [AVERAGE_PATH_DISPLACEMENT](AVERAGE_PATH_DISPLACEMENT.md)
      80             : action.  We then use the [REPARAMETERIZE_PATH](REPARAMETERIZE_PATH.md) to ensure that the new set of reference points on the path are all equally spaced.  After the adaption
      81             : steps the new reference points are used when calculating are position on and distance from the reference path.
      82             : 
      83             : The input below illustrates how to the positions of atoms to define the adaptive path:
      84             : 
      85             : ```plumed
      86             : ##SETTINGS INPUTFILES=regtest/trajectories/path_msd/all.pdb
      87             : p1b: ADAPTIVE_PATH REFERENCE=regtest/trajectories/path_msd/all.pdb FIXED=1,42 UPDATE=1000 WFILE=out-path.pdb WSTRIDE=20000
      88             : PRINT ARG=p1b.* FILE=colvar_b STRIDE=1
      89             : ```
      90             : 
      91             : As we have not used the PROPERTY keyword in the input the $i$ values in the equation for $s$ above are set equal to 1, 2, 3...
      92             : Furthermore, when an input like the one above is used the vectors $\mathbf{v}_1$, $\mathbf{v}_2$ and $\mathbf{v}_3$ from the expression above are computed using an [RMSD](RMSD.md)
      93             : action with the DISPLACEMENT flag enabled.  The instaneous structure is thus aligned with the reference structures so as to remove motions due to translation of the center
      94             : of mass and rotation of the reference frame. These vector of atomic displacements that do not include the translation and rotation are also used in the
      95             : [AVERAGE_PATH_DISPLACEMENT](AVERAGE_PATH_DISPLACEMENT.md) action that is used to update the path.
      96             : 
      97             : As we have not used the PROPERTY keyword in the input the $i$ values in the equation for $s$ above are set equal to 1, 2, 3...
      98             :
