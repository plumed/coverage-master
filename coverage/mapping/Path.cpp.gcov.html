      31             : /*
      32             : Path collective variables with a more flexible framework for the distance metric being used.
      33             : 
      34             : The Path Collective Variables developed by Branduardi and that are described in the first paper that is cited below alow one
      35             : to compute the progress along a high-dimensional path and the distance from the high-dimensional
      36             : path.  The progress along the path (s) is computed using:
      37             : 
      38             : $$
      39             : s = \frac{ \sum_{i=1}^N i \exp( -\lambda R[X - X_i] ) }{ \sum_{i=1}^N \exp( -\lambda R[X - X_i] ) }
      40             : $$
      41             : 
      42             : while the distance from the path (z) is measured using:
      43             : 
      44             : $$
      45             : z = -\frac{1}{\lambda} \ln\left[ \sum_{i=1}^N \exp( -\lambda R[X - X_i] ) \right]
      46             : $$
      47             : 
      48             : In these expressions $N$ high-dimensional frames ($X_i$) are used to describe the path in the high-dimensional
      49             : space. The two expressions above are then functions of the distances from each of the high-dimensional frames $R[X - X_i]$.
      50             : Within PLUMED there are multiple ways to define the distance from a high-dimensional configuration.  You could calculate
      51             : the RMSD distance or you could calculate the amount by which a set of collective variables change.  As such this shortcut
      52             : of the path CV allows one to compute the distances from the paths in a variety of different ways. This is as opposed to
      53             : the alternative implementation of path ([PATHMSD](PATHMSD.md)) which is a bit faster but which only allows one to use the [RMSD](RMSD.md) distance.
      54             : 
      55             : ## Examples
      56             : 
      57             : In the example below the path is defined using RMSD distance from frames.
      58             : 
      59             : ```plumed
      60             : #SETTINGS INPUTFILES=regtest/trajectories/path_msd/all.pdb
      61             : p1: PATH REFERENCE=regtest/trajectories/path_msd/all.pdb TYPE=OPTIMAL LAMBDA=69087
      62             : PRINT ARG=p1.spath,p1.zpath STRIDE=1 FILE=colvar
      63             : ```
      64             : 
      65             : In the example below the path is defined using the values of two torsional angles (t1 and t2).  You can specify these arguments in the PLUMED input
      66             : as illustrated below:
      67             : 
      68             : ```plumed
      69             : #SETTINGS INPUTFILES=regtest/mapping/rt-tpath/epath.pdb
      70             : t1: TORSION ATOMS=5,7,9,15
      71             : t2: TORSION ATOMS=7,9,15,17
      72             : pp: PATH ARG=t1,t2 REFERENCE=regtest/mapping/rt-tpath/epath.pdb LAMBDA=1.0
      73             : PRINT ARG=pp.* FILE=colvar
      74             : ```
      75             : 
      76             : However, this is not strictly necessary as PLUMED can also get the names of the arguments from the input pdb file directly as illustrated in the following
      77             : input.
      78             : 
      79             : ```plumed
      80             : #SETTINGS INPUTFILES=regtest/mapping/rt-tpath/epath.pdb
      81             : t1: TORSION ATOMS=5,7,9,15
      82             : t2: TORSION ATOMS=7,9,15,17
      83             : pp: PATH REFERENCE=regtest/mapping/rt-tpath/epath.pdb LAMBDA=1.0
      84             : PRINT ARG=pp.* FILE=colvar
      85             : ```
      86             : 
      87             : If you look at the pdb file for the input above you can see that the remarks tell PLUMED the labels that are being used to define the position in the
      88             : high dimensional space and the values that these arguments have at each point on the path.
      89             : 
      90             : ## Controlling what is calculated
      91             : 
      92             : If you only want to calculate the $s$ coordinate you can use the NOZPATH flag as shown below:
      93             : 
      94             : ```plumed
      95             : #SETTINGS INPUTFILES=regtest/trajectories/path_msd/all.pdb

     105             : PRINT ARG=p1.zpath STRIDE=1 FILE=colvar
     106             : ```
     107             : 
     108             : You can also tell PLUMED to calculate the distance along and distance from the path using the formulas that are given in the documentation for the
     109             : [GPATH](GPATH.md) shortcut as shown below.
     110             :

     112             : #SETTINGS INPUTFILES=regtest/trajectories/path_msd/all.pdb

     115             : ```

     120             : - p1.zpath - the z coordinate evluated using the expression above

     122             : - p1.gzpath - the z coordinate evaluated using the expression in the documentation for [GPATH](GPATH.md)

     125             :

     127             : arguments and the values of these arguments on the path using the [NORMALIZED_EUCLIDEAN_DISTANCE](NORMALIZED_EUCLIDEAN_DISTANCE.md) rather than the
     128             : [EUCLIDEAN_DISTANCE](EUCLIDEAN_DISTANCE.md). In other words, instead of calculating the distance between the vectors coordinates of coordinates $x$ and $y$ using:

     149             :   LAMBDA=1.0

     158             : /*
     159             : Property maps but with a more flexible framework for the distance metric being used.
     160             : 
     161             : This colvar calculates a property map using the formalism developed by Spiwok that is referenced in the second paper cited below.
     162             : In essence if you have the value of some property, $X_i$, that it takes at a set of high-dimensional
     163             : positions then you calculate the value of the property at some arbitrary point in the high-dimensional space
     164             : using:
     165             : 
     166             : $$
     167             : X=\frac{\sum_i X_i*\exp(-\lambda D_i(x))}{\sum_i  \exp(-\lambda D_i(x))}
     168             : $$
     169             : 
     170             : In these expressions the value of the property $X$ is given at the position of $N$ high-dimensional frames ($X_i$). The distances, $D_i$, between
     171             : these frames and our instaneous position are then used to compute the value of the property at the instaneous position in the high dimensional space.
     172             : As illustrated in the examples below, this implementation of the property map allows you to calculate these distances in various different ways.
     173             : This is as opposed to the alternative implementation [PROPERTYMAP](PROPERTYMAP.md) which is a bit faster but which only allows one to use the RMSD distance.
     174             :
