      40             : //+PLUMEDOC BIAS REPLEX_BIASVALUE
      41             : /*
      42             : In a multi-simulation context, takes the values of variables and uses them as
      43             : exchangeable biases between replicas.
      44             : 
      45             : This is analogous to multiple [BIASVALUE](BIASVALUE.md) where biases are
      46             : periodically exchanged using the Metropolis algorithm. The design is consistent
      47             : with replica exchange in GROMACS, except that the replicas exchange biases
      48             : instead of system coordinates. As a result, output trajectories are
      49             : time-continuous and must be sorted ("multiplexed") to recover the correct biased
      50             : ensembles (as opposed to the usual "demultiplexing", or "demuxing", which recovers
      51             : continuous trajectories from discontinuous ones).
      52             : 
      53             : The exchange scheme matches the GROMACS one, where exchanges between neighboring
      54             : biases are attempted alternating odd pairs ($0 \leftrightarrow 1$,
      55             : $2 \leftrightarrow 3$, …) and even pairs ($1 \leftrightarrow 2$, …). Exchanges
      56             : happen at every step that is a multiple of PACE, except at step 0. Multiple
      57             : attempts can be made on the same exchange step (NEX keyword), alternating odd
      58             : and even pairs, to approximate independence sampling in state space. This incurs
      59             : little additional cost since replicas already compute all biases on exchange
      60             : steps. Using NEX=2 ensures all neighboring pairs are attempted once per exchange
      61             : step.
      62             : 
      63             : By default the number of variables $N$ provided with ARG should match the number
      64             : of replicas $M$ in the multi-simulation, and will correspond to a different bias
      65             : each. Alternatively, the bias ladder can be constructed as any linear
      66             : combination of the $N$ input variables. In that case, the COEFFICIENTS keyword
      67             : should specify the appropriate $M \times N$ matrix $(c_{ij})$ (see examples below)
      68             : and biases $i = 1, ..., M$ will be computed as
      69             : 
      70             : $$
      71             : V_i = \sum_j^N c_{ij} x_j.
      72             : $$
      73             : 
      74             : One can also perform multidimensional replica exchange on a grid. In this case
      75             : one must provide a SHAPE keyword specifying the size of each of the $D$
      76             : dimensions. The product of SHAPE should match the number of replicas $M$. As for
      77             : the 1D case, COEFFICIENTS for each bias should be given as an $M \times N$
      78             : matrix, with one row per bias. Biases are numbered with C-style, row-major
      79             : ordering on the grid (last dimension is the fastest-varying index), see examples
      80             : below. For each exchange attempt (odd or even), all dimensions are attempted in
      81             : order starting from the last one.
      82             : 
      83             : !!! warning
      84             :     All replicas are assumed to share the *same* PLUMED biases, forcefield
      85             :     topologies and temperatures. REPLEX_BIASVALUE is unaware of differences
      86             :     outside its own biases and thus cannot include them in the Metropolis
      87             :     acceptance. Keywords ARG, COEFFICIENTS, SHAPE, PACE, NEX, SEED, and TEMP
      88             :     must be identical in all replicas and will be checked. We recommend using a
      89             :     single common PLUMED input file and avoiding the `@replicas:` syntax.
      90             : 
      91             : !!! note
      92             :     Only one REPLEX_BIASVALUE action is allowed in each PLUMED input. Combine
      93             :     all the bias terms in its ARG list and COEFFICIENTS matrix.
      94             : 
      95             : !!! note
      96             :     This action cannot be combined with replica exchange provided by the MD
      97             :     code. For example, when running with GROMACS, use
      98             :     ```bash
      99             :     mdrun -multidir … -plumed …
     100             :     ```
     101             :     *without* `-replex`.
     102             : 
     103             :

     105             :

     109             : #SETTINGS NREPLICAS=4

     132             : 
     133             : ```plumed
     134             : #SETTINGS NREPLICAS=6
     135             : #HIDDEN

     205             : 
     206             : ## Output files
     207             : 
     208             : The first replica (index 0) keeps track of the position of the biases in the
     209             : output FILE (`bias_index.xvg` by default). Column `replica-i` is the index of
     210             : the bias on replica $i$.
     211             : 
     212             : The bias indices can be used to "multiplex" the continuous trajectories (with
     213             : variable biases) into discontinuous trajectories (with fixed biases). Please
     214             : note that exchanges are attempted *after* calculating forces: this means that
     215             : the PLUMED outputs at time $t$ correspond to bias indices *strictly before* $t$
     216             : in the `bias_index.xvg` file. This is consistent with the output of the
     217             : `demux.pl` script provided with GROMACS and can be seamlessly used for
     218             : multiplexing:
     219             : 
     220             : ```bash
     221             : gmx trjcat -f rep?/traj.xtc -demux rep0/bias_index.xvg -o rep?/muxed.xtc
     222             : ```
     223             : 
     224             : !!! warning
     225             :     For long simulations the time reported in `bias_index.xvg` might be inexact
     226             :     due to floating point precision and may be inconsistent with GROMACS
     227             :     trajectories.
     228             : 
     229             : For convenience, it is also possible to output the replica indices in bias space
     230             : by setting REPINDEX_FILE (note that going from replica indices to bias indices
     231             : and vice versa corresponds to finding the inverse permutation, that is the
     232             : permutation that sorts the indices, e.g. `np.argsort`).
     233             : 
     234             : ```bash
     235             : # This should be the inverse operation to the previous one
     236             : gmx trjcat -f rep?/muxed.xtc -demux rep0/replica_index.xvg -o rep?/traj.xtc
     237             : ```
     238             : 
     239             : ## Log output
     240             : 
     241             : Each exchange step logs the new indices. At the end of the run, per-pair
     242             : statistics are given (accepted/attempted, acceptance ratio, average acceptance
     243             : probability), counted over this run only. The VERBOSE flag can be used to output
     244             : statistics after each exchange step (average over NEX attempts).
     245             : 
     246             : 
     247             : ## Restart
     248             : 
     249             : When restarting a simulation (as indicated internally by the MD engine or
     250             : enforced with RESTART=YES) the content of FILE is automatically read to recover
     251             : the state at a time consistent with the checkpoint. The random numbers used to
     252             : accept or reject the exchanges depend only on SEED and on the step, so the
     253             : restarted simulation makes the same decisions as an uninterrupted one would
     254             : (assuming deterministic and bit-identical energies). This also holds when
     255             : restarting from a PLUMED [CHECKPOINT](CHECKPOINT.md), which needs nothing
     256             : specific to this action.
     257             : 
     258             : If needed one can run a "fresh" simulation starting from a state provided by
     259             : BIASINDEX_RFILE, in which case the time consistency check is ignored and the
     260             : very last line is used.
     261             : */
