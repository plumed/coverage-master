      32             : //+PLUMEDOC INTERNAL pdbreader
      33             : /*
      34             : PLUMED can use the PDB format in several places
      35             : 
      36             : - To read molecular structure (\ref MOLINFO).
      37             : - To read reference conformations (\ref RMSD, but also many other methods in \ref dists, \ref FIT_TO_TEMPLATE, etc).
      38             : 
      39             : The implemented PDB reader expects a file formatted correctly according to the
      40             : [PDB standard](http://www.wwpdb.org/documentation/file-format-content/format33/v3.3.html).
      41             : In particular, the following columns are read from ATOM records
      42             : \verbatim
      43             : columns | content
      44             : 1-6     | record name (ATOM or HETATM)
      45             : 7-11    | serial number of the atom (starting from 1)
      46             : 13-16   | atom name
      47             : 17      | alternate location
      48             : 18-20   | residue name (and column 21, if not blank, for residue names of four characters, as written by GROMACS)
      49             : 22      | chain id
      50             : 23-26   | residue number
      51             : 27      | insertion code
      52             : 31-38   | x coordinate
      53             : 39-46   | y coordinate
      54             : 47-54   | z coordinate
      55             : 55-60   | occupancy
      56             : 61-66   | beta factor
      57             : 77-78   | element symbol
      58             : \endverbatim
      59             : 
      60             : REMARK records are read only when they are not numbered: the numbered remarks of the wwPDB (`REMARK 465 ...`) are free text.
      61             : 
      62             : The serial numbers of a PDB file written by the wwPDB count the TER records, so that they skip a number at the end of each chain.
      63             : \ref MOLINFO has the keyword ATOM_ID: with ATOM_ID=order the atoms are numbered 1,2,3... in the order in which they are read,
      64             : and the serial numbers in the file are not used.
      65             : 
      66             : When atoms have alternate locations (column 17), only the first location found in each residue is read,
      67             : together with the atoms of the residue that have no alternate location; the other atoms are skipped
      68             : (\ref MOLINFO writes how many in the log). Residues are identified by chain, residue number and insertion code,
      69             : so that residues 52 and 52A of the same chain are different residues.
      70             : 
      71             : \par mmCIF files
      72             : 
      73             : Files with extension `.cif` or `.mmcif` are read as mmCIF (PDBx/mmCIF) files, with the CIF parser of
      74             : [gemmi](https://gemmi.readthedocs.io). The atoms are read from the `_atom_site` table of the first data block:
      75             : 
      76             : \verbatim
      77             : column                                      | content
      78             : _atom_site.id                               | serial number of the atom (see below)
      79             : _atom_site.auth_atom_id, label_atom_id      | atom name
      80             : _atom_site.auth_comp_id, label_comp_id      | residue name
      81             : _atom_site.auth_asym_id, label_asym_id      | chain id
      82             : _atom_site.auth_seq_id, label_seq_id        | residue number
      83             : _atom_site.pdbx_PDB_ins_code                | insertion code
      84             : _atom_site.label_alt_id                     | alternate location
      85             : _atom_site.type_symbol                      | element symbol
      86             : _atom_site.Cartn_x, Cartn_y, Cartn_z        | coordinates
      87             : _atom_site.occupancy                        | occupancy
      88             : _atom_site.B_iso_or_equiv                   | beta factor
      89             : _atom_site.pdbx_PDB_model_num               | model number: only the first model is read
      90             : \endverbatim
      91             : 
      92             : The author (`auth_`) columns are used, as in PDB files written from the same structure; the `label_` columns
      93             : are used for the atoms where the `auth_` value is missing (or when the column is not there). Chain ids and residue names
      94             : are read in full (chain ids with more than one character, residue names with four or five characters, which a PDB file
      95             : truncates to the three characters of columns 18-20); residue names shorter than three characters are right-justified
      96             : to three, as in the columns 18-20 of a PDB file.
      97             : Only the coordinates are compulsory: a missing occupancy or beta factor is 1, a missing residue number is 0.
      98             : The unit cell is read from `_cell.length_a`, `_cell.length_b`, `_cell.length_c`, `_cell.angle_alpha`,
      99             : `_cell.angle_beta` and `_cell.angle_gamma` (as the CRYST1 record of a PDB file), the space group from
     100             : `_symmetry.space_group_name_H-M` or `_space_group.name_H-M_alt`.
     101             : The PLUMED-specific REMARK lines of PDB files (arguments, TYPE, ...) cannot be given in an mmCIF file.
     102             : 
     103             : By default the serial number of an atom is the value of `_atom_site.id`, which must then be a positive integer.
     104             : With ATOM_ID=order in \ref MOLINFO the atoms are numbered 1,2,3... in the order in which they are read (after skipping
     105             : the other models and the alternate locations), for files where the ids do not match the numbering of the atoms in the simulation.
     106             : The same numbering is then obtained from the PDB and the mmCIF file of a wwPDB entry (whose ids do not count the TER records).
     107             : 
     108             : \par GROMACS TPR files
     109             : 
     110             : When PLUMED is configured with `--enable-libchemfiles`, files with extension `.tpr` are read as GROMACS TPR files,
     111             : with the [chemfiles](https://chemfiles.org) library (0.10.4 or later). The structure is that of the PDB file written by
     112             : `gmx editconf -f topol.tpr -o reference.pdb`:
     113             : - the atoms are numbered 1,2,3... in the order of the file, as in the simulation (ATOM_ID has no effect);
     114             : - the atom names, the residue names, numbers and insertion codes, the elements and the coordinates are those of the TPR file;
     115             : - a TPR file has no chain ids: the sequences of residues in which each residue is bonded to the next one (e.g. the protein and
     116             :   nucleic acid chains) are the chains A, B, C... (then AA, AB...) in the order of the file, and keep their residue numbers;
     117             :   the other residues (water, ions...) have no chain and are numbered after the largest residue number of the chains.
     118             :   This is what `gmx editconf` does with the molecules of more than one residue: the result is the same, unless a molecule
     119             :   of the topology has residues that are not bonded to each other (e.g. two chains in the same molecule, which are here two chains);
     120             : - the occupancy and the beta factor of all the atoms are 1;
     121             : - the box of the simulation is the unit cell (space group P 1).
     122             : PLUMED parser is slightly more permissive than the official PDB format
     123             : in the fact that the format of real numbers is not fixed. In other words,
     124             : any real number that can be parsed is OK and the dot can be placed anywhere. However,
     125             : __columns are interpret strictly__. A sample PDB should look like the following
     126             : \verbatim
     127             : ATOM      2  CH3 ACE     1      12.932 -14.718  -6.016  1.00  1.00
     128             : ATOM      5  C   ACE     1      21.312  -9.928  -5.946  1.00  1.00
     129             : ATOM      9  CA  ALA     2      19.462 -11.088  -8.986  1.00  1.00
     130             : \endverbatim
     131             : 
     132             : Notice that serial numbers need not to be consecutive. In the three-line example above,
     133             : only the coordinates of three atoms are provided. This is perfectly legal and indicates PLUMED
     134             : that information about these atoms only is available. This could be both for structural
     135             : information in \ref MOLINFO, where the other atoms would have no name assigned, and for
     136             : reference structures used in \ref RMSD, where only the provided atoms would be used to compute RMSD.
     137             : 
     138             : \par Occupancy and beta factors
     139             : 
     140             : PLUMED reads also occupancy and beta factors that however are given a very special meaning.
     141             : In cases where the PDB structure is used as a reference for an alignment (that's the case
     142             : for instance in \ref RMSD and in \ref FIT_TO_TEMPLATE), the occupancy column is used
     143             : to provide the weight of each atom in the alignment. In cases where, perhaps after alignment,
     144             : the displacement between running coordinates and the provided PDB is computed, the beta factors
     145             : are used as weight for the displacement.
     146             : Since setting the weights to zero is the same as __not__ including an atom in the alignment or
     147             : displacement calculation, the two following reference files would be equivalent when used in an \ref RMSD
     148             : calculation. First file:
     149             : \verbatim
     150             : ATOM      2  CH3 ACE     1      12.932 -14.718  -6.016  1.00  1.00
     151             : ATOM      5  C   ACE     1      21.312  -9.928  -5.946  1.00  1.00
     152             : ATOM      9  CA  ALA     2      19.462 -11.088  -8.986  0.00  0.00
     153             : \endverbatim
     154             : Second file:
     155             : \verbatim
     156             : ATOM      2  CH3 ACE     1      12.932 -14.718  -6.016  1.00  1.00
     157             : ATOM      5  C   ACE     1      21.312  -9.928  -5.946  1.00  1.00
     158             : \endverbatim
     159             : However notice that many extra atoms with zero weight might slow down the calculation, so
     160             : removing lines is better than setting their weights to zero.
     161             : In addition, weights for alignment need not to be equivalent to weights for displacement.
     162             : Starting with PLUMED 2.7, if all the weights are set to zero they will be normalized to be equal to the
     163             : inverse of the number of involved atoms. This means that it will be possible to use files with
     164             : the weight columns set to zero obtaining a meaningful result. In previous PLUMED versions,
     165             : setting all weights to zero was resulting in an error instead.
     166             : 
     167             : 
     168             : \par Systems with more than 100k atoms
     169             : 
     170             : Notice that it very likely does not make any sense to compute the \ref RMSD or any other structural
     171             : deviation __using__ so many atoms. However, if the protein for which you want to compute \ref RMSD
     172             : has atoms with large serial numbers (e.g. because it is located __after__ solvent in the sorted list of atoms)
     173             : you might end up with troubles with the limitations of the PDB format. Indeed, since there are 5
     174             : columns available for atom serial number, this number cannot be larger than 99999.
     175             : In addition, providing \ref MOLINFO with names associated to atoms with a serial larger than 99999 would be impossible.
     176             : 
     177             : Since PLUMED 2.4 we allow [hybrid 36](http://cci.lbl.gov/hybrid_36/) format to be used to specify atom numbers.
     178             : This format is not particularly widespread, but has the nice feature that it provides a one-to-one mapping
     179             : between numbers up to approximately 80 millions and strings with 5 characters, plus it is backward compatible
     180             : for numbers smaller than 100000. This is not true for notations like the hex notation exported by VMD.
     181             : Using the hybrid 36 format, the ATOM records for atom ranging from 99997 to 100002 would read like these:
     182             : \verbatim
     183             : ATOM  99997  Ar      X   1      45.349  38.631  15.116  1.00  1.00
     184             : ATOM  99998  Ar      X   1      46.189  38.631  15.956  1.00  1.00
     185             : ATOM  99999  Ar      X   1      46.189  39.471  15.116  1.00  1.00
     186             : ATOM  A0000  Ar      X   1      45.349  39.471  15.956  1.00  1.00
     187             : ATOM  A0000  Ar      X   1      45.349  38.631  16.796  1.00  1.00
     188             : ATOM  A0001  Ar      X   1      46.189  38.631  17.636  1.00  1.00
     189             : \endverbatim
     190             : There are tools that can be found to translate from integers to strings and back using hybrid 36 format
     191             : (a simple python script can be found [here](https://sourceforge.net/p/cctbx/code/HEAD/tree/trunk/iotbx/pdb/hybrid_36.py)).
     192             : In addition, as of PLUMED 2.5, we provide a \ref pdbrenumber "command line tool" that can be used to renumber atoms in a PDB file.
     193             :
