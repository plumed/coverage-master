      33             : /*
      34             : Write a PLUMED checkpoint file for an exact restart.
      35             : 
      36             : With this directive PLUMED writes its own checkpoint file, separate from the
      37             : one of the MD engine, whenever the MD engine writes its checkpoint (the MD
      38             : engine tells PLUMED through the `doCheckPoint` command of the interface; the
      39             : GROMACS patch does so) or, with STRIDE, every STRIDE steps for the engines
      40             : that do not send this signal.
      41             : 
      42             : The checkpoint stores the internal state of the actions (hills, accumulators,
      43             : random number generators, ...) at the start of the checkpointing step, together
      44             : with the sizes of all the files that PLUMED has written up to that moment.
      45             : When the simulation is restarted from it, every output file is truncated to the
      46             : size it had at the checkpoint, so that the lines written after it by the
      47             : interrupted run are removed, and the checkpointing step is computed again:
      48             : this requires the MD engine to restart from its own checkpoint of the same
      49             : step, as GROMACS does with `-cpi`. The result is an exact continuation of the
      50             : interrupted run, at variance with a plain [RESTART](RESTART.md) where files
      51             : are only appended.
      52             : 
      53             : CHECKPOINT is a setup directive and must come before any action that writes a
      54             : file, so put it at the top of the input. The file is written atomically and the
      55             : previous checkpoint is kept with the suffix `_prev` (`plumed_prev.cpt` for
      56             : `plumed.cpt`); with multiple replicas every replica writes its own file with the
      57             : usual replica suffix.
      58             : 
      59             : ```plumed
      60             : CHECKPOINT FILE=plumed.cpt
      61             : d: DISTANCE ATOMS=1,2
      62             : PRINT ARG=d FILE=colvar
      63             : ```
      64             : 
      65             : At restart, RESTART_FROM selects the checkpoint to read. The default, AUTO,
      66             : reads FILE when the MD engine tells PLUMED that the run is restarted (or when
      67             : [RESTART](RESTART.md) comes before CHECKPOINT) and starts a new run otherwise.
      68             : A file name reads that checkpoint unconditionally, NO never reads one (the
      69             : checkpoint is only written). Restarting from a checkpoint implies RESTART.
      70             : 
      71             : ```plumed
      72             : CHECKPOINT FILE=plumed.cpt STRIDE=1000 RESTART_FROM=AUTO
      73             : d: DISTANCE ATOMS=1,2
      74             : PRINT ARG=d FILE=colvar
      75             : ```
      76             : 
      77             : The first step presented by the MD engine after the restart must be the one
      78             : stored in the checkpoint, otherwise PLUMED stops with an error: this happens
      79             : when the PLUMED checkpoint and the restart file of the MD engine do not come
      80             : from the same moment of the simulation. With STRIDE, choose a stride that
      81             : matches the checkpointing of the MD engine.
      82             : 
      83             : An action with the per-action keyword `RESTART=NO` starts from scratch at the
      84             : restart step: its state is not restored from the checkpoint and its files,
      85             : trimmed at the checkpoint like all the others, are backed up and rewritten
      86             : instead of being appended. This is the way to add a new action with an
      87             : internal state to a continuation, or to reset one (e.g. a [METAD](METAD.md)
      88             : that starts depositing again from zero while everything else continues
      89             : exactly). The global `RESTART NO` directive after CHECKPOINT is an error,
      90             : since it contradicts the restart from the checkpoint.
      91             : 
      92             : The actions that store their state in the checkpoint include [METAD](METAD.md),
      93             : [PBMETAD](PBMETAD.md), [OPES_METAD](OPES_METAD.md), [OPES_METAD_EXPLORE](OPES_METAD_EXPLORE.md),
      94             : [METAINFERENCE](METAINFERENCE.md) (and the ISDB collective variables with DOSCORE),

      96             : [EXTENDED_LAGRANGIAN](EXTENDED_LAGRANGIAN.md), [ACCUMULATE](ACCUMULATE.md), [COLLECT](COLLECT.md),
      97             : [COMMITTOR](COMMITTOR.md), [MAXENT](MAXENT.md), [READ](READ.md), [RANDOM_EXCHANGES](RANDOM_EXCHANGES.md),
      98             : [LOGMFD](LOGMFD.md), [FISST](FISST.md), [RESCALE](RESCALE.md), [EMMI](EMMI.md), [EMMIVOX](EMMIVOX.md) and
      99             : [EFFECTIVE_ENERGY_DRIFT](EFFECTIVE_ENERGY_DRIFT.md) (exact with a single process, up to rounding with more): they
     100             : restore their state from it, so that their hills, kernels or status files are not read
     101             : (the growing ones are truncated).
     102             : Actions that keep an internal state but do not store it in the checkpoint
     103             : yet are listed in a warning in the log: for them the restart is the usual
     104             : file-based one and an exact continuation is not guaranteed.
     105             : 
     106             : The content of a checkpoint can be inspected with `plumed checkpoint --dump`.
     107             : Compressed (`.gz`) output files cannot be truncated and are not allowed
     108             : together with CHECKPOINT.
