      33             : Activate restart.
      34             : 
      35             : Many MD calculations are run on supercomputer facilities that limit the amount of
      36             : time an individual calculation can run for.  As MD simulations take a long time to
      37             : complete, you often have to restart your calculations and build up your trajectories by
      38             : running a chain of sub-runs. Some MD codes tell PLUMED if the MD has restarted
      39             : the calculation from a checkpoint file while others do not. To avoid problems we recommend
      40             : using the RESTART commands and keywords in your input files whenever you are generating
      41             : trajetories by restarting calculations from a checkpoint file.
      42             : 
      43             : RESTART is a Setup directive and, as such, should appear
      44             : at the beginning of the input file. When you include the RESTART command
      45             : in your plumed.dat file you are telling PLUMED that you want to restart all
      46             : the actions. Restarting these actions ensures that, as discussed [here](Files.md), PLUMED appends
      47             : all the files that are open for writing. Appending to these files makes it
      48             : easier to analyze results from simulations that have been performed as a
      49             : chain of several sub-runs.
      50             : 
      51             : To consider what this means in practise consider the following input:
      52             : 
      53             : ```plumed
      54             : d: DISTANCE ATOMS=1,2
      55             : PRINT ARG=d FILE=out
      56             : ```
      57             : 
      58             : If you run a plumed calculation in a directory which already contains a file called
      59             : `out` that file called `out` will be renamed `bck.0.out` so that the data from the new
      60             : calculation can be output to a new version of the file `out` and so that the data in the
      61             : old version of the file is not lost.
      62             : 
      63             : If by contrast you run the calculation in that same directory with the following input:
      64             : 
      65             : ```plumed
      66             : RESTART
      67             : d: DISTANCE ATOMS=1,2
      68             : PRINT ARG=d FILE=out
      69             : ```
      70             : 
      71             : The data from the new simulation simulation will be appended to the file called `out` that
      72             : was already present in the data.
      73             : 
      74             : Notice that it is also possible to enable or disable restart on a per-action
      75             : basis using the RESTART keyword as illustrated below:
      76             : 
      77             : ```plumed
      78             : d1: DISTANCE ATOMS=1,2
      79             : d2: DISTANCE ATOMS=1,2
      80             : PRINT ARG=d1 FILE=out1
      81             : PRINT ARG=d2 FILE=out2 RESTART=YES
      82             : ```
      83             : 
      84             : If this input is used any files called `out1` are backed up to `bck.0.out1`.  Data from the
      85             : new calculation is then appended to any file called `out2`  that is present in the working directory.
      86             : 
      87             : Notice that the RESTART keyword is assigned one of three values:
      88             : 
      89             : - `RESTART=AUTO` is the default and means that global settings are used
      90             : - `RESTART=YES` means that the action is restarted
      91             : - `RESTART=NO` means that the action is not restarted even if there is a global restart command
      92             : 
      93             : The following input is thus equivalent to the first input that introduced the RESTART keyword.
      94             : 
      95             : ```plumed
      96             : RESTART
      97             : d1: DISTANCE ATOMS=1,2
      98             : d2: DISTANCE ATOMS=1,2
      99             : PRINT ARG=d1 FILE=out1 RESTART=NO
     100             : PRINT ARG=d2 FILE=out2
     101             : ```
     102             : 
     103             : [!CAUTION]
     104             : The RESTART directive can have also other important side effects. For methods such as [METAD](METAD.md)
     105             : or [PBMETAD](PBMETAD.md) when the action is told to restart all the hills from the previous run are read
     106             : in at the start of the calculation so that the bias potential at the start of the restarted simulation is
     107             : identical to the bias potential at the end of the previous run.
     108             : 
     109             : If you are absolutely certain that you do not want to restart any of the actions in your input you
     110             : can use an input like the example below:

     116             : ```

     118             : The `RESTART NO` command in this input tells PLUMED that no actions are to be restarted even if the MD
     119             : code has told PLUMED that the initial configuration came from a checkpoint file and that the trajectory
     120             : is being restarted.
     121             : 
     122             : ## Trimming the files at the restart step
     123             : 
     124             : When an MD code restarts from its checkpoint, the simulation continues from the step S at which the
     125             : checkpoint was written, while the files written by PLUMED may contain lines written after it, by a run
     126             : that was interrupted (or that went on) after writing its checkpoint. If the MD code tells PLUMED the step
     127             : S from which it restarts (the GROMACS patches do this after `-cpi`, and [driver](driver.md) does it with
     128             : `--restart --initial-step S`), PLUMED removes these lines from the files it appends to, before reading or
     129             : writing them, so that they continue exactly where the restarted simulation starts, as GROMACS does with its
     130             : own files. The lines of step S are removed too, since step S is computed again. In this way the COLVAR
     131             : files contain every time once and, for instance, [METAD](METAD.md) reads only the hills deposited before
     132             : step S (the hill of step S is added again) and [OPES_METAD](OPES_METAD.md) only the kernels deposited before it.
     133             : 
     134             : The lines removed are the last lines of the file with a time equal to or later than the time of step S:
     135             : the earlier lines are kept, including those of earlier runs whose time restarted from zero. The trimming
     136             : applies to the files that have a `time` field (PRINT, the hills of METAD, the kernels of OPES_METAD, ...);
     137             : the other files (e.g. those of [DUMPATOMS](DUMPATOMS.md)) and the files where the times after S are not
     138             : increasing are appended as they are, with a line in the log. The lines removed from a file are not lost:
     139             : they are moved to a file `bck.trimmed.N.name` in the same directory (N is the first number not used yet).
     140             : Compressed files (`.gz`, written in append mode as a sequence of gzip streams) are trimmed too: since they
     141             : cannot be truncated, the lines that are kept are compressed again. Files that are rewritten at
     142             : every write (e.g. grids and state files) are not trimmed. When the bias is read from a grid
     143             : ([METAD](METAD.md) with GRID_RFILE) or from a state file ([OPES_METAD](OPES_METAD.md) with STATE_RFILE),
     144             : which are written at the checkpoint of the MD code and already contain the hill or kernel of step S,
     145             : the lines of step S are kept. With the multiple walkers of METAD that share files (WALKERS_N) the hills
     146             : files are not trimmed. The log lists the files that have been trimmed and where their removed lines are. When a trimmed file ends with the same field header that the restarted run prints, the header is not printed again, so that the file is the same as the one of an uninterrupted run.
     147             : 
     148             : The trimming can be switched off for all the files, which are then appended as they are, with
     149             : 
     150             : ```plumed

     156             : or for the files of a single action with the NO_TRIM flag:

     163             : Notice that `RESTART NO_TRIM`, as RESTART, also switches restart on. With [CHECKPOINT](CHECKPOINT.md) the files
