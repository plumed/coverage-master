      32             : Loads a library, possibly defining new actions.
      33             : 
      34             : The LOAD action is only available on systems that allow dynamic loading.
      35             : This action allows you load new funcionality into PLUMED at runtime.
      36             : This new functionality can be in a .so file or a .cpp file. If the
      37             : new functionality is in a cpp file then the code is compiled and the
      38             : the resulting object is loaded.
      39             : 
      40             : Extra header search directories can be supplied when compiling a `.cpp` file:
      41             : 
      42             : ````
      43             : LOAD FILE=x.cpp INCLUDE_PATH={headers:other headers}
      44             : ````
      45             : 
      46             : `INCLUDE_PATH` is a colon-separated, ordered list. Enclose the whole value in
      47             : braces when a directory contains spaces. Relative directories are resolved from
      48             : the working directory, not from the source or input file directory. Empty values
      49             : and empty entries are errors; directory names containing colons are not supported.
      50             : The option is rejected for precompiled libraries. Existing compiler flags and
      51             : include environment variables remain in effect; these additional directories
      52             : apply only to this LOAD invocation.
      53             : 
      54             : With `INCLUDE_PATH`, PLUMED compiles on every LOAD into a separate temporary
      55             : location next to the source and removes the temporary library after loading.
      56             : This avoids reusing a library compiled with different include paths, including
      57             : when multiple PLUMED objects load the same source concurrently, and reflects
      58             : header changes on the next LOAD. The source directory must be writable.
      59             : Without `INCLUDE_PATH`, the existing source-timestamp cache is unchanged (it does
      60             : not track header dependencies).
      61             : 
      62             : Using the LOAD action is useful for making quick tests while developing your own
      63             : actions. Of course, once your implementation is ready you should
      64             : add it to the PLUMED source tree and recompile PLUMED.
      65             : 
      66             : One way to use the LOAD action is to directly load a cpp file as illustrated in the input below.
      67             :

      69             : #SETTINGS INPUTFILES=regtest/basic/rt15/Distance2.cpp

      86             : the cpp file.  To construct the shared object you would use the following command:

      88             : ````
      89             : > plumed mklib Distance2.cpp
      90             : ````
      91             : 
      92             : When you run this command a new file called `Distance2.so` (or `Distance2.dylib` on a mac) is created.
      93             : You can then load this shared object in PLUMED by using the following LOAD command
      94             : 
      95             : ````
      96             : LOAD FILE=Distance2.so
      97             : ````
      98             : 
      99             : The new functionality within the Distance2.cpp file can then be used in the remainder of the input in the same way it was
     100             : used in the previous example.
     101             : (Notice that the only reason for not using the usual PLUMED syntax highlightling in the example above is that we have no
     102             : file called Distance2.so.)
     103             : 
     104             : From PLUMED 2.10 onwards the LOAD action can be placed at any point of the input

     106             : These features are illustrated in the input below:
