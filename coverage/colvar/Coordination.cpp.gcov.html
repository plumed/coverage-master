      30             : /*
      31             : Calculate coordination numbers.
      32             : 
      33             : This keyword can be used to calculate the number of contacts between two groups of atoms
      34             : and is defined as
      35             : 
      36             : $$
      37             : \sum_{i\in A} \sum_{i\in B} s_{ij}
      38             : $$
      39             : 
      40             : where $s_{ij}$ is 1 if the contact between atoms $i$ and $j$ is formed and zero otherwise.
      41             : In actuality, $s_{ij}$ is replaced with a switching function so as to ensure that the calculated CV has continuous derivatives.
      42             : 
      43             : The default switching function is:
      44             : 
      45             : $$
      46             : s_{ij} = \frac{ 1 - \left(\frac{r_{ij}-d_0}{r_0}\right)^n } { 1 - \left(\frac{r_{ij}-d_0}{r_0}\right)^m }
      47             : $$
      48             : 
      49             : but it can be changed using the optional SWITCH option.  You can find more information about the various switching functions that you can
      50             : use with this action in the documentation for [LESS_THAN](LESS_THAN.md).
      51             : 
      52             : To make your __calculation faster you can use a neighbor list__: every NL_STRIDE steps the pairs closer than NL_CUTOFF are listed,
      53             : and only those are computed at the following steps.
      54             : 
      55             : - With NLIST the list is built by checking all the pairs. Use it with small groups (up to about a hundred atoms), or when one of the two groups has only a few atoms (fewer than about ten).
      56             : - With NLISTCELLS the list is built with link cells, at a cost that grows with the number of atoms rather than with the number of pairs. Use it for larger groups:
      57             :   building the list is about 4 times faster with 1000 atoms, and about 30 times with 10000. The pairs are the same, in another order.
      58             :   When one of the two groups has at most 8 atoms, NLISTCELLS builds the list as NLIST: sorting all the atoms into cells would cost more than one distance per pair.
      59             : - NL_CUTOFF must be larger than D_MAX of the switching function (set D_MAX: without it the switching function is not zero at any distance, and the pairs beyond NL_CUTOFF are ignored).
      60             :   The difference NL_CUTOFF-D_MAX is a skin: the list is exact as long as no pair of atoms gets closer by more than the skin between two updates.
      61             :   For atoms in a liquid at room temperature with a time step of 2 fs, a skin of 0.1 nm with NL_STRIDE=10 is a safe choice.
      62             :   A larger skin allows a larger stride but makes every step slower, since more pairs are computed. You can check your choice by comparing a short run with one without neighbor list.
      63             : 
      64             : If GROUPB is empty, the coordination  number will be calculated based on the $\frac{N(N-1)}{2}$ pairs in GROUPA. This avoids computing
      65             : permuted indexes (e.g. pair (i,j) and (j,i)) twice and ensures that the calculation runs at twice the speed.
      66             : 
      67             : Notice that if there are common atoms between GROUPA and GROUPB the switching function should be
      68             : equal to one. These "self contacts" are discarded by plumed (since version 2.1),
      69             : so that they actually count as "zero".
      70             : 
      71             : ## One atom against many atoms
      72             : 
      73             : To compute the coordination number of one atom (or a few) with many atoms, such as the oxygens of all the
      74             : water molecules around an ion, use COORDINATION with a neighbor list: between the updates of the list only
      75             : the atoms in the list are used, and only they are requested from the MD code.
      76             : 
      77             : ```plumed
      78             : ow: GROUP ATOMS=2-30001:3
      79             : c: COORDINATION GROUPA=1 GROUPB=ow SWITCH={RATIONAL R_0=0.35 NN=6 MM=10 D_MAX=1.2} NLIST NL_CUTOFF=1.3 NL_STRIDE=10
      80             : ```
      81             : 
      82             : If you need the coordination number of each atom of the small group as a vector, use [COORDINATIONNUMBER](COORDINATIONNUMBER.md)
      83             : with SPECIESA and SPECIESB.
      84             : 
      85             : ## Examples
      86             : 
      87             : The following example instructs plumed to calculate the total coordination number of the atoms in group 1-10 with the atoms in group 20-100.  For atoms 1-10 coordination numbers are calculated that count the number of atoms from the second group that are within 0.3 nm of the central atom.  A neighbor list is used to make this calculation faster: it contains the pairs within 0.5 nm (a skin of 0.1 nm beyond D_MAX) and it is updated every 10 steps.
      88             : 
      89             : ```plumed
      90             : COORDINATION GROUPA=1-10 GROUPB=20-100 SWITCH={RATIONAL R_0=0.3 D_MAX=0.4} NLIST NL_CUTOFF=0.5 NL_STRIDE=10
      91             : ```
      92             : 
      93             : With larger groups the neighbor list is built faster with link cells:
      94             : 
      95             : ```plumed
      96             : COORDINATION GROUPA=1-1000 GROUPB=1001-5000 SWITCH={RATIONAL R_0=0.3 D_MAX=0.4} NLISTCELLS NL_CUTOFF=0.5 NL_STRIDE=10
      97             : ```
      98             : 
      99             : The following is a dummy example which should compute the value 0 because the self interaction
     100             : of atom 1 is skipped. Notice that in plumed 2.0 "self interactions" were not skipped, and the
     101             : same calculation should return 1.
     102             : 
     103             : ```plumed
     104             : c: COORDINATION GROUPA=1 GROUPB=1 R_0=0.3
     105             : PRINT ARG=c STRIDE=10
     106             : ````
     107             : 
     108             : Here's an example that shows what happens when COORDINATION is provided with
     109             : a single group:
     110             : 
     111             : ```plumed
     112             : # define some huge group:
     113             : group: GROUP ATOMS=1-1000
     114             : # Here's coordination of a group against itself:
     115             : c1: COORDINATION GROUPA=group GROUPB=group R_0=0.3
     116             : # Here's coordination within a single group:
     117             : x: COORDINATION GROUPA=group R_0=0.3
     118             : # This is just multiplying times 2 the variable x:
     119             : c2: COMBINE ARG=x COEFFICIENTS=2 PERIODIC=NO
     120             : 
     121             : # the two variables c1 and c2 should be identical, but the calculation of c2 is twice faster
     122             : # since it runs on half of the pairs.
     123             : PRINT ARG=c1,c2 STRIDE=10
     124             : ```
