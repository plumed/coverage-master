      39             : /*
      40             : Calculate the distances between a number of pairs of atoms and transform each distance by a switching function.
      41             : 
      42             : This CV calculates a series of distances between pairs of atoms and transforms them by a switching function.
      43             : The transformed distance can be compared with a reference value in order to calculate the squared distance
      44             : between two contact maps. Each distance can also be weighted for a given value. CONTACTMAP can be used together
      45             : with [FUNCPATHMSD](FUNCPATHMSD.md) to define a path in contactmap space as was done in the 2008 paper by Bonomi that
      46             : is cited below.
      47             : 
      48             : If $s_i$ is the switching function of the $i$-th contact, $r_i$ its distance, $w_i$ its weight and $s_i^0$ its reference
      49             : value, CONTACTMAP computes:
      50             : 
      51             : - without SUM and CMDIST, one component for each contact, $w_i (s_i(r_i) - s_i^0)$;
      52             : - with SUM, $\sum_i w_i (s_i(r_i) - s_i^0)$;
      53             : - with CMDIST, $\sum_i w_i^2 (s_i(r_i) - s_i^0)^2$.
      54             : 
      55             : The weights are 1 and the reference values 0 unless they are given with WEIGHT and REFERENCE.
      56             : With NORMALIZE_WEIGHTS the weights (the default ones or those given with WEIGHT) are divided by their sum, so that
      57             : they sum to one: with SUM the CV is then the weighted average of the contacts, and with CMDIST it is
      58             : $\sum_i w_i^2 (s_i(r_i) - s_i^0)^2 / (\sum_j w_j)^2$.
      59             : The individual contacts can be accessed as components
      60             : named `cm.contact-1`, `cm.contact-2`, etc, assuming that the label of the CONTACTMAP is `cm`.
      61             : 
      62             : ## Examples
      63             : 
      64             : The following example calculates switching functions based on the distances between atoms
      65             : 1 and 2, 3 and 4, 4 and 5 and 5 and 6. The values of these four switching functions are then output
      66             : to a file named colvar.
      67             : 
      68             : ```plumed
      69             : f1: CONTACTMAP ATOMS1=1,2 ATOMS2=3,4 ATOMS3=4,5 ATOMS4=5,6 SWITCH={RATIONAL R_0=1.5}
      70             : PRINT ARG=f1.* FILE=colvar
      71             : ```
      72             : 
      73             : The following example calculates the difference of the current contact map with respect
      74             : to a reference provided. In this case REFERENCE is the fraction of contact that is formed
      75             : (i.e. the distance between two atoms transformed with the SWITCH), while R_0 is the contact
      76             : distance. WEIGHT gives the relative weight of each contact to the final distance measure.
      77             : 
      78             : ```plumed
      79             : cmap: CONTACTMAP ...
      80             :   ATOMS1=1,2 REFERENCE1=0.1 WEIGHT1=0.5
      81             :   ATOMS2=3,4 REFERENCE2=0.5 WEIGHT2=1.0
      82             :   ATOMS3=4,5 REFERENCE3=0.25 WEIGHT3=1.0
      83             :   ATOMS4=5,6 REFERENCE4=0.0 WEIGHT4=0.5
      84             :   SWITCH={RATIONAL R_0=1.5}
      85             :   CMDIST
      86             : ...
      87             : 
      88             : PRINT ARG=cmap FILE=colvar
      89             : ```
      90             : 
      91             : The reference contact map can also be taken from a reference structure, by giving a PDB file
      92             : (or any other structure file that [MOLINFO](MOLINFO.md) can read, e.g. mmCIF) to REFERENCE.
      93             : The reference value of each contact is then its switching function evaluated at the distance between the two atoms
      94             : in the reference structure. The atoms are identified by their serial numbers in the file,
      95             : the distances are computed without periodic boundary conditions (so the molecule should be whole in the file)
      96             : and the coordinates are read in Angstrom (or in the natural units if those are used).
      97             : 
      98             : ```plumed
      99             : #SETTINGS INPUTFILES=regtest/basic/rt-contactmap-pdb/native.pdb
     100             : cmap: CONTACTMAP ...
     101             :   ATOMS1=1,67 ATOMS2=1,68 ATOMS3=5,61 ATOMS4=15,57
     102             :   SWITCH={RATIONAL R_0=0.6}
     103             :   REFERENCE=regtest/basic/rt-contactmap-pdb/native.pdb
     104             :   CMDIST
     105             : ...
     106             : 
     107             : PRINT ARG=cmap FILE=colvar
     108             : ```
     109             : 
     110             : The next example calculates the fraction of native contacts (Q)
     111             : for Trp-cage mini-protein. R_0 is the distance at which the switch function is guaranteed to
     112             : be 1.0 – it doesn't really matter for Q and  should be something very small, like 1 A.
     113             : REF is the reference distance for the contact, e.g. the distance from a crystal structure.
     114             : LAMBDA is the tolerance for the distance – if set to 1.0, the contact would have to have exactly
     115             : the reference value to be formed; instead for lambda values of 1.5–1.8 are usually used to allow some slack.
     116             : BETA is the softness of the switch function, default is 50 nm$^{-1}$.
     117             : WEIGHT is the 1/(number of contacts) giving equal weight to each contact.
     118             : 
     119             : When using native contact Q switch function, please cite the 2013 paper from Best from the bibliography below
     120             : 
     121             : ```plumed

     137             : 
     138             : With a reference structure given to REFERENCE, the Q switching functions that do not have REF
     139             : take it from the distance in the reference structure, so the native contacts need no per-contact numbers.
     140             : Without CMDIST the reference structure only provides these distances: no reference value is subtracted,
     141             : so that the CV below, where NORMALIZE_WEIGHTS gives each contact the weight 1/8, is the fraction of native contacts, between 0 and 1.
     142             : 
     143             : ```plumed
     144             : #SETTINGS INPUTFILES=regtest/basic/rt-contactmap-pdb/native.pdb
     145             : q: CONTACTMAP ...

     150             :    NORMALIZE_WEIGHTS
     151             :    SUM

     155             : ```
     156             : 
     157             : The contacts themselves can be taken from the reference structure: with CUTOFF instead of the ATOMS keywords,
     158             : the contacts are all the pairs of atoms of the reference structure that are closer than CUTOFF.
     159             : To use only some of the atoms (e.g. the heavy atoms, the $C_\alpha$ atoms or a single domain), give a reference structure
     160             : that contains only those atoms; the atoms are identified by their serial numbers, that must be those of the simulation.
     161             : CHAINS chooses the pairs of atoms in the same chain (INTRA), in different chains (INTER) or both (ALL, the default),
