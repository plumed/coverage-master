      30             : /*
      31             : Probe the alpha helical content of a protein structure.
      32             : 
      33             : Any chain of six contiguous residues in a protein chain can form an alpha helix. This
      34             : colvar thus generates the set of all possible six residue sections and calculates
      35             : the [DRMSD](DRMSD.md) or [RMSD](RMSD.md) distance between the configuration in which the residues find themselves
      36             : and an idealized alpha helical structure. These distances can be calculated by either
      37             : aligning the instantaneous structure with the reference structure and measuring each
      38             : atomic displacement or by calculating differences between the set of inter-atomic
      39             : distances in the reference and instantaneous structures. The backbone atoms N, CA, CB, C and O
      40             : of each residue are used (for glycine the HA2 atom is used in place of CB), so each section contains 30 atoms.
      41             : 
      42             : In the original paper on this method (see below) the authors used the set of distances from the alpha helix configurations to measure
      43             : the number of segments that have an alpha helical configuration. This is done by calculating
      44             : the following sum of functions of the rmsd distances:
      45             : 
      46             : $$
      47             : s = \sum_i \frac{ 1 - \left(\frac{r_i-d_0}{r_0}\right)^n } { 1 - \left(\frac{r_i-d_0}{r_0}\right)^m }
      48             : $$
      49             : 
      50             : where the sum runs over all possible segments of alpha helix.  By default the
      51             : NN, MM, D_0 and R_0 parameters are set equal to those used in the paper cited below, which are
      52             : $n=8$, $m=12$, $d_0=0$ and $r_0=0.08$ nm. The value of R_0 is given in the length units of [UNITS](UNITS.md);
      53             : the default is converted, so it is always 0.08 nm. As in the other actions that take R_0, NN, MM and D_0, the function above, $f(r)$,
      54             : is stretched so that it goes to zero at $d_{max}=d_0+r_0\,10^{5/(m-n)}$, where $f(d_{max})=10^{-5}$ (1.42 nm with the default
      55             : parameters): each segment contributes $\left(f(r_i)-f(d_{max})\right)/\left(1-f(d_{max})\right)$ if $r_i<d_{max}$ and zero otherwise.
      56             : The value of $d_{max}$ is the D_MAX of the switching function in the expanded input. To use the function without stretching,
      57             : use LESS_THAN={RATIONAL R_0=0.08 NN=8 MM=12}.
      58             : 
      59             : If you would like to use a different switching function you can use the LESS_THAN keyword, as in the second example below,
      60             : where D_MAX is given as for the default function.
      61             : In this case the label of the action is the vector of the distances between each segment and the ideal alpha helix, and
      62             : the number of segments that are similar to an alpha helix is the `lessthan` component. The vector can be given in input to other
      63             : actions: for example [LOWEST](LOWEST.md) gives the distance of the segment that is closest to an alpha helix.
      64             : 
      65             : The following input calculates the number of six residue segments of
      66             : protein that are in an alpha helical configuration.
      67             : 
      68             : ```plumed
      69             : #SETTINGS MOLFILE=regtest/basic/rt32/helix.pdb
      70             : MOLINFO STRUCTURE=regtest/basic/rt32/helix.pdb
      71             : alpha: ALPHARMSD RESIDUES=all R_0=0.1
      72             : PRINT ARG=alpha FILE=colvar
      73             : ```
      74             : 
      75             : Here the same is done using [RMSD](RMSD.md) instead of [DRMSD](DRMSD.md), and with the LESS_THAN keyword. The cost of the two methods is similar.
      76             : The distance of the segment that is closest to an alpha helix is also computed.
      77             : 
      78             : ```plumed
      79             : #SETTINGS MOLFILE=regtest/basic/rt32/helix.pdb
      80             : MOLINFO STRUCTURE=regtest/basic/rt32/helix.pdb
      81             : alpha: ALPHARMSD RESIDUES=all TYPE=OPTIMAL LESS_THAN={RATIONAL R_0=0.1 NN=8 MM=12 D_MAX=1.78}
      82             : closest: LOWEST ARG=alpha
      83             : PRINT ARG=alpha.lessthan,closest FILE=colvar
      84             : ```
      85             : 
      86             : ## Periodic boundary conditions
      87             : 
      88             : Unless the NOPBC flag is used, each six residue section is made whole before computing its distance from the reference: the
      89             : atoms N, CA, CB, C and O of the six residues are taken in this order, and each atom is moved to the periodic image that is closest
      90             : to the previous one, as is done by [WHOLEMOLECULES](WHOLEMOLECULES.md). This is done in the same way for [DRMSD](DRMSD.md) and
      91             : [RMSD](RMSD.md), so there is no need to use [WHOLEMOLECULES](WHOLEMOLECULES.md) before this action.
      92             : You can turn off this treatment by using the NOPBC flag as shown below:
      93             : 
      94             : ```plumed
      95             : #SETTINGS MOLFILE=regtest/basic/rt32/helix.pdb
      96             : MOLINFO STRUCTURE=regtest/basic/rt32/helix.pdb
      97             : alpha: ALPHARMSD RESIDUES=all R_0=0.1 NOPBC
      98             : PRINT ARG=alpha FILE=colvar
      99             : ```
     100             : 
     101             : ## How the number of segments is computed
     102             : 
     103             : The number of segments that are similar to an alpha helix (the value of the action, or its `lessthan` component when
     104             : LESS_THAN is used) is computed by a single action, ALPHARMSD_SCALAR, which loops over the segments and adds the derivatives
     105             : of each segment directly to the atoms, so that the segments are computed once per step. The vectors that appear in the expanded
     106             : input (the distances from the reference structure and their switching functions) are only computed when they are used
     107             : elsewhere in the input, e.g. when the vector that is the value of the action with LESS_THAN is printed. The result is the same.
     108             : With `USEGPU` and TYPE=DRMSD the same calculation is done on the GPU by ALPHARMSD_SCALAR_ACC, from the openaccPTM plugin.
     109             : With `USEGPU` and the other types the number of segments is the sum of the vector of the switching functions.
     110             : 
     111             : */
