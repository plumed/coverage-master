      29             : //+PLUMEDOC COLVAR ANTIBETARMSD
      30             : /*
      31             : Probe the antiparallel beta sheet content of your protein structure.
      32             : 
      33             : Two protein segments containing three contiguous residues can form an antiparallel beta sheet.
      34             : Although if the two segments are part of the same protein chain they must be separated by
      35             : a minimum of two residues to make room for the turn. This colvar thus generates the set of
      36             : all possible six residue sections (residues $i$, $i+1$, $i+2$ and $j-2$, $j-1$, $j$) that could conceivably form an antiparallel beta sheet
      37             : and calculates the [DRMSD](DRMSD.md) or [RMSD](RMSD.md) distance between the configuration in which the residues find themselves
      38             : and an idealized antiparallel beta sheet structure. These distances can be calculated by either
      39             : aligning the instantaneous structure with the reference structure and measuring each
      40             : atomic displacement or by calculating differences between the set of inter-atomic
      41             : distances in the reference and instantaneous structures. The backbone atoms N, CA, CB, C and O
      42             : of each residue are used (for glycine the HA2 atom is used in place of CB), so each section contains 30 atoms.
      43             : 
      44             : This colvar is based on the paper cited below.  The authors of
      45             : this paper use the set of distances from the antiparallel beta sheet configurations to measure
      46             : the number of segments whose configuration resembles an antiparallel beta sheet. This is done by calculating
      47             : the following sum of functions of the rmsd distances:
      48             : 
      49             : $$
      50             : s = \sum_i \frac{ 1 - \left(\frac{r_i-d_0}{r_0}\right)^n } { 1 - \left(\frac{r_i-d_0}{r_0}\right)^m }
      51             : $$
      52             : 
      53             : where the sum runs over all possible segments of antiparallel beta sheet.  By default the
      54             : NN, MM, D_0 and R_0 parameters are set equal to those used in the paper cited below, which are
      55             : $n=8$, $m=12$, $d_0=0$ and $r_0=0.08$ nm. The value of R_0 is given in the length units of [UNITS](UNITS.md);
      56             : the default is converted, so it is always 0.08 nm. As in the other actions that take R_0, NN, MM and D_0, the function above, $f(r)$,
      57             : is stretched so that it goes to zero at $d_{max}=d_0+r_0\,10^{5/(m-n)}$, where $f(d_{max})=10^{-5}$ (1.42 nm with the default
      58             : parameters): each segment contributes $\left(f(r_i)-f(d_{max})\right)/\left(1-f(d_{max})\right)$ if $r_i<d_{max}$ and zero otherwise.
      59             : The value of $d_{max}$ is the D_MAX of the switching function in the expanded input. The segments with a distance from the
      60             : reference larger than $d_{max}$, whose strands are far apart, are then not computed (see below).
      61             : To use the function without stretching, use LESS_THAN={RATIONAL R_0=0.08 NN=8 MM=12}.
      62             : 
      63             : If you would like to use a different switching function you can use the LESS_THAN keyword, as in the second example below,
      64             : where D_MAX is given as for the default function, so that the pairs of strands that are too far apart can be skipped also with this function.
      65             : In this case the label of the action is the vector of the distances between each segment and the ideal antiparallel beta sheet, and
      66             : the number of segments that are similar to an antiparallel beta sheet is the `lessthan` component.
      67             : 
      68             : The following input calculates the number of six residue segments of
      69             : protein that are in an antiparallel beta sheet configuration.
      70             : 
      71             : ```plumed
      72             : #SETTINGS MOLFILE=regtest/basic/rt32/helix.pdb
      73             : MOLINFO STRUCTURE=regtest/basic/rt32/helix.pdb
      74             : ab: ANTIBETARMSD RESIDUES=all R_0=0.1
      75             : PRINT ARG=ab FILE=colvar
      76             : ```
      77             : 
      78             : Here the same is done using [RMSD](RMSD.md) instead of [DRMSD](DRMSD.md), and with the LESS_THAN keyword. The cost of the two methods is similar.
      79             : 
      80             : ```plumed
      81             : #SETTINGS MOLFILE=regtest/basic/rt32/helix.pdb
      82             : MOLINFO STRUCTURE=regtest/basic/rt32/helix.pdb
      83             : hh: ANTIBETARMSD RESIDUES=all TYPE=OPTIMAL LESS_THAN={RATIONAL R_0=0.1 NN=8 MM=12 D_MAX=1.78}
      84             : PRINT ARG=hh.lessthan FILE=colvar
      85             : ```
      86             : 
      87             : ## Strands cutoff
      88             : 
      89             : The segments that have the two strands of the beta sheet further apart than `STRANDS_CUTOFF` are not computed, and they contribute
      90             : zero to the number of segments that are similar to a beta sheet. The distance between the two strands is the distance between the
      91             : CA atoms of their central residues. The default cutoff is 1 nm (the cutoff is in the length units of [UNITS](UNITS.md), the default
      92             : is converted). This makes the calculation much faster, as the number of pairs of strands grows with the square of the number of residues.
      93             : Use `STRANDS_CUTOFF=0` to compute all the pairs: the number of segments then also includes the small contributions of the many segments
      94             : whose strands are far apart (with 18 peptides of 8 residues about 1 more segment). If you use LESS_THAN together with STRANDS_CUTOFF,
      95             : notice that the distances of the skipped segments are zero in the vector that is the value of the action, so this vector
      96             : should not be used to find the segment that is closest to a beta sheet.
      97             : 
      98             : ## How the number of segments is computed
      99             : 
     100             : Without `USEGPU`, the number of segments that are similar to a sheet (the value of the action, or its `lessthan` component when
     101             : LESS_THAN is used) is computed by a single action, ANTIBETARMSD_SCALAR, which loops over the pairs of strands, skips those that are further
     102             : apart than `STRANDS_CUTOFF` and adds the derivatives of each segment directly to the atoms. When the switching function goes to zero at
     103             : a finite distance (as the default one, or with D_MAX in LESS_THAN), it also skips the pairs of strands that are so far apart that the
     104             : distance of the segment from the reference is certainly larger than that distance (this does not change the result, and makes
     105             : STRANDS_CUTOFF=0 cheaper). The vectors that appear in the expanded input
     106             : (the distances of the strands, the distances from the reference structure and their switching functions) are only computed when they are
     107             : used elsewhere in the input, e.g. when the vector that is the value of the action with LESS_THAN is printed. The result is the same.
     108             : With `USEGPU` and TYPE=DRMSD the same calculation is done on the GPU by ANTIBETARMSD_SCALAR_ACC, from the openaccPTM plugin: one GPU thread per pair of strands within `STRANDS_CUTOFF`. With `USEGPU` and the other types the number of segments is the sum of the vector of the switching functions.
     109             : 
     110             : ## Chains and residues
     111             : 
     112             : The STYLE keyword selects whether the two strands of a segment are taken from the same chain (STYLE=intra), from different
     113             : chains (STYLE=inter) or both (STYLE=all, the default). With STYLE=intra and STYLE=all each chain must contain at least 8 residues,
     114             : otherwise PLUMED stops with an error; for systems made of short peptides (for example in studies of aggregation) use STYLE=inter.
     115             : 
     116             : ## Periodic boundary conditions
     117             : 
     118             : Unless the NOPBC flag is used, each six residue section is made whole before computing its distance from the reference.
     119             : The two strands of three residues are made whole separately: the atoms N, CA, CB, C and O of each strand are taken in this order,
     120             : and each atom is moved to the periodic image that is closest to the previous one, as is done by [WHOLEMOLECULES](WHOLEMOLECULES.md).
     121             : The second strand is then moved to the periodic image where the CA atom of its central residue is closest to the CA atom of the
     122             : central residue of the first strand (this is the ALIGN_STRANDS flag of [SECONDARY_STRUCTURE_RMSD](SECONDARY_STRUCTURE_RMSD.md)).
     123             : This is done in the same way for [DRMSD](DRMSD.md) and [RMSD](RMSD.md), so there is no need to use [WHOLEMOLECULES](WHOLEMOLECULES.md)
     124             : before this action. The distance used with STRANDS_CUTOFF is also computed with the periodic boundary conditions.
     125             : You can turn off this treatment by using the NOPBC flag as shown below:
     126             : 
     127             : ```plumed
     128             : #SETTINGS MOLFILE=regtest/basic/rt32/helix.pdb
     129             : MOLINFO STRUCTURE=regtest/basic/rt32/helix.pdb
     130             : ab: ANTIBETARMSD RESIDUES=all R_0=0.1 NOPBC
     131             : PRINT ARG=ab FILE=colvar
     132             : ```
     133             : 
     134             : */
